# 手动验收清单（真机）

> 这份清单只收**浏览器 / 自动脚本验证不了**的行为：它们要么依赖 Tauri 的文件系统与窗口生命周期，
> 要么只有在「磁盘异常」时才成立。每条都写清：怎么造、看什么、坏的时候长什么样。
>
> 发版前照着点一遍，大约 20 分钟。**自动检查**（`npm run audit:*`、`cargo test --lib`）覆盖的是另一部分，
> 见 `docs/README.md` §4。

---

## 1. 换库不丢最后几秒的字

**为什么**：保存是防抖的（编辑器 700ms–2s + 落盘队列 350ms）。换库会整库替换 Dexie 并清空队列。

1. 打开笔记库 A，随便找一篇角色，在正文末尾打几个字（不要按保存）；
2. **两秒内**点「文件 › 打开本地文件夹…」，切到另一个库；
3. 再切回 A，打开同一篇。

**预期**：刚打的字还在。
**坏的样子**：字没了（`de5040b` 之前就是这样）。

---

## 2. 关窗口不丢最后几秒的字

1. 在正文里打几个字，**立刻**点窗口关闭（Alt+F4 / 红叉）；
2. 重新打开应用，进同一篇。

**预期**：字还在。
**坏的样子**：最后那几秒的输入消失（`de5040b` 之前就是这样）。

---

## 3. 磁盘上的文件被外部改过：两条路都要能走

1. 在 Obsidian（或记事本）里改一篇**当前没有打开**的笔记，保存；
2. 回到应用，打开同一篇，改一个字段；
3. 等状态栏从「待保存」变回「已同步」。

**预期**：弹出「1 个文件在磁盘上被外部修改过」，正文没被覆盖。点右边「覆盖磁盘」→ 提示「已按编辑器里的版本覆盖磁盘」，盘上变成你刚才改的版本；点「文件 › 刷新」→ 采纳 Obsidian 那一版。
**坏的样子**：状态栏一直转圈、每 350ms 重试一次、没有任何提示（`6ae2e46` 之前就是这样）。

---

## 4. 开着笔记库导入备份，真的落到文件夹

1. 先导出一次数据备份（`文件 › 导出 › 备份`），得到 `.ocbak`；
2. 删掉其中一篇角色（进回收站即可），再清空回收站；
3. `文件 › 导入…` 选那个 `.ocbak`，策略选「跳过」；
4. **重启应用**，看那篇角色在不在。

**预期**：导入完成提示里既有「新增 N 条」也有「写进文件夹 N 篇」；重启后角色还在。
**坏的样子**：导入提示成功、列表里也出现，但重启就没了（`c320b23` 之前就是这样 —— 只写了 Dexie）。

第 2.5 步：导入对话框里选「替换」→ 应当**当场拒绝**并说明「笔记库开着时不能用替换导入」。

---

## 5. 回收站恢复撞名：自动改名而不是失败

1. 建一个角色叫「验收甲」，记下它的文件名；
2. 删掉它（进回收站）；
3. 再建一个角色，**名字改成同一个**「验收甲」（会占掉同名文件）；
4. 打开回收站，恢复第 2 步那条。

**预期**：恢复成功，落成 `验收甲 (2).md`；两个角色都在。
**坏的样子**：提示「目标已存在」，那条永远恢复不出来（`ff3867a` 之前就是这样）。

---

## 6. 「小说 / 地图」不能再建同名分类

1. 侧栏「新建分类」，名字填 `小说` → **预期**：当场报错「…是内置目录的名字」；
2. 设置 › 世界 › 自定义分类，把某个分类改名成 `地图` → **预期**：同样被拒，原分类不变；
3. 老库里的同名分类（之前被助手写坏的）：重启应用后应自动消失（载入时丢掉并写回清理结果），
   笔记本身不动（小说页里那些章节还在）。

---

## 7. 字段表读失败时不许写回

1. 关掉应用，把 `.ocstudio/fields.json` 的内容改成 `{ 坏掉的 json`；
2. 打开应用 → 字段表回落默认（界面能开，这是有意的）；
3. 进 设置 › 世界 › 字段，改任一字段名。

**预期**：提示「字段表上次没有读成功，先刷新笔记库再改」，盘上的坏文件**没有被覆盖**。
**恢复**：把 `fields.json` 改回合法 JSON（或删掉它）→ 文件 › 刷新。

---

## 8. tags.json 写不进去时，改动不丢

1. 把 `.ocstudio/tags.json` 设为**只读**（`attrib +R tags.json`）；
2. 在设置 › 世界 › 标签里改一个标签颜色；
3. 看状态栏：应为「保存异常」，悬停能看到原因；
4. 去掉只读（`attrib -R`），文件 › 刷新。

**预期**：解除只读后刷新，颜色是新的（改动没有在失败时被丢掉，`35cf5b3` 之前会丢）。

---

## 9. 图片写盘失败要有提示

> 造失败最省事的办法：把笔记库所在的盘写满，或把 `.ocstudio` 与 `附件/` 设为只读。

1. 在角色「立绘」或「相册」里选一张图上传。

**预期**：弹出「图片保存失败」并带原因；不会出现「图没出现、也没有任何提示」。
（`d5eb241` 之前六个上传入口都是静默失败的。）

## 10. 编辑手感（这三条一直在被改，回归时容易漏）

| 操作 | 预期 |
|---|---|
| 正文里按 Tab | 段首出现两个全角空格；Shift+Tab 退回；**表格里 Tab 仍然是跳下一格** |
| 正文里按 Esc | 焦点离开正文（再按 Tab 能走到工具栏）；菜单开着时 Esc **只关菜单** |
| 把窗口拖窄 / 三分栏 | 工具栏图标收进一个「…」，不压在「保存」上 |
| 改完角色正文不保存，切到「世界观」 | 状态栏回到「已保存」，不弹「有未保存的更改」 |
| **中文输入法组字期间**（拼音还没上屏） | 不触发保存、不把拼音写进文件；组字中按 Esc 只取消候选，不关弹层、不退出 | 
| 在「新建文件夹 / 重命名」输入框里打拼音、按回车选词 | 选中的是候选词，不会把拼音建成名字（isImeComposing 守卫） | 
| 手机上长按选词 → 工具栏「插入链接」 | 应该有一个能填地址的地方；现在只是插入一个空链接（	oggleLink({href:''})），点了打不开 —— 待定交互 |
| 正文里打 @ 与 / | 弹出提及 / 命令菜单；**这条只能用真键盘验** —— 无头浏览器合成的文字输入不会走 ProseMirror 的 handleTextInput，自动化里看不到弹层（2026-11-12 记） |

## 11. 助手（需要已配置模型）

| 场景 | 预期 |
|---|---|
| Agent 模式：「在《某本书》下写一章」 | 先要求确认写入（审批框），确认后小说页能看到新章节；不需要切创作模式 |
| 创作模式但**没开**「可写回」 | 助手不会硬写，会告诉你「切到创作模式 → 选作品 → 打开可写回」 |
| 审批框一直不点 | 5 分钟后自动取消，并给一条横幅说明 |
| 会话资料里选过的小说被重排 / 删掉 | 再发消息时 tag 自动清空或改名，不会把章节挂到别人下面 |

## 12. 恢复到「干净」状态

验收过程中造过的故障都要清掉：

- `fields.json` / `tags.json` 的只读属性、坏内容；
- 回收站里为测试建的角色；
- 分类里为测试建的条目。

确认 设置 › 数据 › 导出数据备份 能正常导出后，再收工。

---

## 13. 同一个动作、不同入口（回归时最容易只测一条路）

**为什么**：删除 / 新建 / 打开这三种动作各有四五个入口。只测一个入口，另一条路上「返回去了别处」
「删完别处还显示」都发现不了。下面每条都在 2026-11-11 逐条走过一遍，作为以后的回归项。

| 动作 | 入口 | 预期 |
|---|---|---|
| 打开实体后按「返回」 | 关系图点节点 → 角色编辑器 → 返回 | 回到**关系图**，不是角色列表 |
| 同上 | 表格点行 / 时间线点事件 | 各自回到表格 / 时间线 |
| 新建角色 | 列表工具栏「新建角色」 | 立刻进入编辑器，默认名「新角色」 |
| 同上 | `Ctrl+K` → 快速新建 → 新建角色 | 同上（角色数 +1，编辑器打开） |
| 删除事件 / 词条 | 从列表删除 | 时间线、关系图、相册里**立刻**消失，不需要刷新 |
| 删除失败 | 任意入口（可临时让服务层抛错） | 只弹「操作没有完成 + 原因」，**不会**同时弹「已移至回收站」 |

## 14. 空库首次体验（新用户唯一一次「第一印象」）

**怎么造空库**：浏览器预览会把示例数据播种进空库（`SeedData`，桌面版因有笔记库会跳过）。
要测真空库，先 `localStorage.setItem('oc-studio-vault-enabled', 'true')`，再清空 IndexedDB 的
`OCStudioDatabase` 所有表并刷新；桌面版直接新建一个空文件夹即可。

| 位置 | 预期（2026-11-12 逐条走过） |
|---|---|
| 首页 | 「还没有内容 · 从这里开始」+ 新建角色 / 新建事件 / 新建国家 |
| 角色 / 事件 / 国家 | 「还没有 X」+「创建第一个」 |
| 世界观 | 目录侧「目录还是空的 / 点右上角的 ＋ 新建」，右栏「还没有词条」+「新建词条」（只留一个创建按钮） |
| 表格 | 「0 角色 · 0 行 … 还没有角色」+「新增」 |
| 相册 | 「暂无图片」 |
| 小说 / 地图 | 「还没有小说」+「新建小说」/「还没有地图」+「新建地图」 |
| 新建角色 | 直接进编辑器、默认名「新角色」；改名保存后立刻出现在表格与关系图 |
| 新建词条 | 点「新建词条」后**树里立刻出现「新词条」**（不用刷新），改名后树里同步改 |
| 词条正文 | 空正文有占位提示：「编写词条内容… 输入 @ 引用角色/事件/国家，输入 / 插入块」 |

**坑**：测的时候别往「目录搜索」里打字 —— 那会把树过滤成空，看起来像「新建的词条没出现」。
（这一轮我就被自己坑了一次。）

## 15. 表格（四个页签 / 窄窗 / 层级）

**为什么单列**：表格是最容易「只在大库、宽屏下测过」的地方。2026-11-12 补测了另外三种极端情况，
结论都正常，留作回归项。

| 场景 | 预期 |
|---|---|
| 空库 · 四个页签 | 各自「还没有 X」+「新增」；「展开全部 / 折叠全部」在空表里不出现 |
| 空表时按「新增」 | 建的是**当前页签**那一类（角色页签建角色、词条页签建词条），建完留在表里不跳走 |
| 窗口 1024 / 900 宽 | 表格**自己横向滚动**（表头与内容一起动），整页不出现横向滚动条 |
| 带父子关系的词条 | 子行标题比父行**右缩进 18px**（实测 205 → 223），折叠父行后子行随之隐藏 |

## 16. 回收站按天自动清理

**为什么**：删除的笔记落在 `.ocstudio/trash/<YYYYMMDD-HHMMSS>/`；页头下拉可选 **保留 30 天 / 保留 7 天 / 从不清理**（默认 30 天），打开笔记库或改设置时清掉过期批次。

1. 删一个测试角色（进回收站）；确认 `.ocstudio/trash/` 下出现一个 `2026….` 批次目录；
2. **造一个「旧」批次**：复制那个目录，把名字改成一年前，例如 `20251110-120000`；
3. 打开回收站 → 页头下拉选「保留 7 天」。

**预期**：提示「已清理 N 个过期条目」；旧批次目录消失，刚删的那个批次还在（列表里仍能看到今天的条目，恢复也正常）。
**反向检查**：
- 选「从不清理」后，任何旧批次都不会被删；
- 手工改名为 `abc` 的目录**不会**被删（只认 `YYYYMMDD-HHMMSS`）；
- 时钟调到未来 / 目录 mtime 新于期限时也不删（两个条件都要过期）。

**内部实现**：`vault_trash_batches` 只列文件名合法的批次，`vault_trash_purge` 拒绝非法名与符号链接；清理后对应 Dexie 行一起删，避免「恢复时源文件不存在」的幽灵条目。
