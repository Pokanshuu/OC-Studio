# 地图

> 未实现。定位：地图是**一个视图**（跟时间线、关系图平级），不是一类新实体。

---

## 0. 一句话

**地图不是数据，是看数据的一个角度**——跟时间线把事件摆到时间轴上一样，地图把地点摆到平面上。

---

## 1. 两种地图，别混

| | 手绘地图 | 生成地图 |
|---|---|---|
| 长什么样 | 一张背景图（作者画好的大陆/城市） | 算法生成的轮廓（插件：地图生成器） |
| 数据 | 背景图 + **锚点** | 从国家/词条推导 + 可调参数 |
| 作者投入 | 高（得先有图） | 低（一键出草图） |
| 定位 | **主战场**：最终展示用 | **起步工具**：没图时先有个大概 |

生成器是**插件**（见 `docs/插件.md` §0.1），手绘地图是**内置视图**。

---

## 2. 数据：锚点存在实体上

| 键 | 在哪 | 说明 |
|---|---|---|
| `map_position: { x, y }` | 实体的 frontmatter | 归一化坐标（0–1），与图片尺寸无关——换一张更清晰的地图不用重摆 |
| `map_id` | 实体（可选） | 一个库可以有多张地图（世界 / 某国 / 某城），为空 = 主地图 |

背景图存 `.ocstudio/maps/<名>.png`，随库走。

**为什么归一化**：`graphPosition` 是绝对坐标，因为关系图没有底图；地图有底图，底图会换（草图 → 精修），绝对坐标会全废。

---

## 3. 与实体的联动

| 方向 | 行为 |
|---|---|
| 实体 → 地图 | 「地点」组件里出现「在地图中查看」；有锚点就定位过去 |
| 地图 → 实体 | 点锚点 = 跳转那个国家 / 事件 / 词条 |
| 地点字段 | 现在是一行文本（`place`），**锚点存在实体上而不是地点字段里**——地点是给读者看的名字，锚点是给地图用的坐标 |

事件也可以有锚点（"这里发生过什么"），所以地图上能叠一层事件图层。这是它比"插入一张图片"多出来的全部价值。

---

## 4. 交互（第一版只做这些）

- 缩放 / 平移（与关系图同一套手势与 `MIN_ZOOM`）
- 点锚点 → 打开实体
- 拖动锚点 → 改位置（**写回实体 frontmatter**；移动端只读）
- 图层开关：国家 / 事件 / 词条（对应实体类型）
- **不做**：路径规划、距离测量、经纬度投影、多层地形——那是 GIS，不是设定集

---

## 5. 与模板的关系

地图可以作为一个 **block 组件**塞进模板（比如国家页显示"本国位置"的缩略）。缩略态只读、不可拖。

---

## 6. 不做

- 真 GIS（投影 / 经纬度 / 等高线）
- 在应用里画地图（画图是外部工具的事，我们只认一张背景图 + 锚点）
- 地图之间互相嵌套的层级导航（先只有"一个库多张图"）

---

## 7. 风险

| 风险 | 说明 |
|---|---|
| 底图换了，锚点全歪 | 归一化坐标能扛"换分辨率"，扛不住"构图改了"——换了构图就该重摆，UI 要提示这一点 |
| 大底图性能 | 与主题背景图同一个问题：上屏用压缩版，原图只在导出时用 |
| 锚点重叠 | 两个国家挨得近时锚点会叠，需要错开或聚合（与关系图同一套问题） |
| 生成器的产出算谁的 | 插件生成的地图只是"底图"，锚点仍然必须落在实体上，否则数据和插件绑死 |
