## 0. 一句话

**笔记 = 模板 + 一串组件。** 模板在**设置里**编排，写作时只填空；同一套组件既给编辑器渲染，也给列表、时间线、关系图、导出图片用。

### 0.1 现在的问题

| 问题 | 具体 |
|---|---|
| **存反向** | `country.characters` / `country.events` 是存在国家自己行里的镜像，靠 `lib/membership.ts` 保存时双边写。Obsidian 改国籍、导入 `.ocbak`、软删除角色都会漂（见 §1.4） |
| **关系只能连角色** | `relatedCharacters` 是唯一的关系存储，国家之间（盟友 / 敌对）、角色与国家（使节）都没有字段，只能写进正文 |
| **一个事实三种写法** | 角色国籍是 `countryId`（单值），事件国家是 `countries[]`（多值），国家侧又各有一份数组 |
| **四类实体各写一遍编辑器** | 加一类实体 = 再写一遍；改一处布局 = 改四处 |
| **标签没有位置** | 角色里是字段行，事件 / 国家里挂在「关联」下，数据层又是独立一张表 |
| **一个东西两个名字** | 角色叫「关系」用表格，事件 / 国家叫「关联」用 chips，导航叫「关系图」 |

## 1. 三条已定判断

### 1.1 分层，不是折半

| 极端 A | 极端 B | 定在哪 |
|---|---|---|
| Notion：一切皆块，无文件约束 | 纯 markdown：固定列、硬编码编辑器 | **界面统一成组件序列；文件保持 frontmatter + 正文两段** |
| 全结构化（什么都是字段） | 全自由（只有一篇散文） | **结构化只到"属性"层；正文保留散文形态** |
| 用户从零搭页 | 我们定死 | **预设模板 + 可调顺序和参数** |
| 快照卡片 | 纯引用 | **实体用引用；一次性内容用快照** |
| 官方闭集 | 用户写组件 | **官方组件 + 用户组合参数** |

**判据只有一条：写作面不许被动。** 所有取舍都以"写的时候什么都不用想"为准。

### 1.2 模板在设置里，不在编辑器里

| | 块编辑器 | 本设计 |
|---|---|---|
| 结构由谁先决定 | 作者边写边搭 | **打开笔记前就已存在** |
| 编辑模板的时机 | 创作过程中 | **设置里，与创作完全分离** |
| 写作面上看得到组件吗 | 看得到（卡片、边框、悬停工具栏） | **看不到，只看到小节标题** |
| 想要别的排法 | 当场拖 | **换一个模板** |

一句话：**那套是作者在排版，这套是版已经排好了。**

### 1.3 组件是闭集

用户能动的：**用哪些组件 / 什么顺序 / 组件内部参数**。
用户不能动的：**组件渲染逻辑**。自定义组件 = 插件系统 + 沙箱，不在范围内。

### 1.4 数据 vs 展示

**写进文件的只有"事实"；列表、反向、统计一律算出来，不存。**

| 数据（写） | 展示（算） |
|---|---|
| 角色的国籍 | 国家的国民 |
| 事件的涉及国家 | 国家的相关事件 |
| 角色 A 给 B 起的关系名 | B 那边的那一行 |
| 词条的 `parentId` | 父词条的"包含" |
| 模板的组件顺序 | 笔记的布局 |

加字段前先问三句：**是实体自己的属性吗？能从别处算吗？会不会有第二处写同一个事实？**
（是 / 是 / 会 → 不存）

**没有"同步"这回事。** 不需要在保存时互相同步，因为第二个地方根本没有东西要同步。

> 历史遗留：`country.characters`、`country.events` 这类旧的"反向数组"**不读、不写、不删**——读侧改成查询、写侧只写实体那一侧，盘上的旧数据原样留着，将来一次性整理。所以这是零迁移。

## 2. 概念

| 概念 | 定义 | 在哪 |
|---|---|---|
| **组件 component** | "能显示什么 + 能存什么"的声明，官方闭集 | 代码 registry |
| **模板 template** | 有序组件列表 + 每组件参数 | `.ocstudio/templates/*.md` |
| **笔记 note** | 应用了某模板的一份 markdown | 库里的一篇文件 |

### 2.1 组件分三级

用户列的 11 项**不是同一层级**：

| 级别 | 定义 | 例子 |
|---|---|---|
| **atom** | 一个字段：一行标签 + 一个值 | 别名、种族、国籍、生日、重要 |
| **group** | 若干 atom 按序排 | **基本信息** |
| **block** | 独立成块、模板里可排序 | 封面、基本信息、关系、标签、图片、画廊、时间、地点、简介、正文 |

atom **只活在 group 内**；block 在模板里排序，group 内部再排 atom。

### 2.2 三个特殊 block

| 组件 | 特殊点 |
|---|---|
| **封面** | 永远贴顶，**无标题行**、无上分隔线；可关 |
| **正文** | **无标题行**；位置可排（默认最后）；它是"剩下的部分" |
| **基本信息** | 唯一带 atom 编排的 group block |

### 2.3 内置分类：宠物 / 武器

它们不是角色的一个单选（`kind` 已删除），而是**分类 = 模板 + 一组笔记**的两个出厂预设：

| 项 | 宠物 | 武器 |
|---|---|---|
| 分类 id | `cat-pet` | `cat-weapon` |
| 模板 id / 名 | `pet` / 宠物 | `weapon` / 武器 |
| 图标 | `pawPrint` | `swords` |
| 默认在侧栏 | **否**（设置 › 世界 › 自定义分类里打开） | **否** |
| 模板组件 | 基本信息 · 标签 · 简介 · 正文 | 同左 |

三条规则：

1. **模板随包走，分类默认不启用** —— 不预建侧栏入口，不替用户决定「我的世界有没有宠物」；
2. **内置分类不可删、不可改名**，只能开关；要改形状就复制成自建分类。
3. 分类条目**就地编辑**：`CategoryEntryEditor` 用分类绑定的模板渲染，不再把 `activeItem` 切到「世界观」。
   老库里已存在的同名「宠物 / 武器」分类在读盘时原地升级成预设（条目保留）。
4. **分类可以绑任何「含正文」的模板**（`lib/templates/note.ts` 的 `isNoteTemplate`）：
   2026-11-06 起十一个组件在笔记宿主上全部实装，所以判据只剩「含 `body`」。
   实体模板复制到分类里也能逐块渲染（基本信息退回笔记字段、关系显示层级 / 引用）。
   绑定面不再人为收窄 —— 收窄的理由（「有封面、实际渲染不出来」）已经不存在。
5. **列表页与角色 / 事件同一套壳**：`ListShell` + `CategoryListToolbar`（标题 / 搜索 / 排序 / 视图 / 新建）+
   移动端 `MobileFilterBar`；排序支持手动拖拽（`SortableList` + `order`）、最近编辑、最近创建、标题；
   视图有目录 / 卡片 / 画廊三态（复用共享 `ViewToggle`），卡片与画廊都接 3:2 封面；画廊用
   `CoverFlow` 顶排 + `VerticalSplit` 底排目录，高度偏好 `oc-categories-gallery-split`。
   手机「更多」列出已启用的分类，`MobileSection` 里对应 `category`。
6. **字段**：词条（含分类条目）开放自建字段，值落 `WorldEntry.custom` 与 frontmatter 同名键，
   世界编辑器与分类编辑器共用 `WorldCustomFields`。**基本信息是独立组件，不是模板的一部分**：
   模板只记「选了哪一个」—— `info.params.group = <InfoGroup id>`。组件（`InfoGroup`：
   `id / name / fields`，存 `.ocstudio/info-groups.json`）自己有名有字段，可被多个模板复用，
   **名字与模板名无关**，关系只由「选择」这个动作决定。内置两个组件（宠物 15 个字段 / 武器 12 个
   字段，对齐改版 `entity-info.ts`），可改字段、可改名、不可删；自建组件可增删字段、可删
   （删掉后引用它的模板退回「全部字段」）。没选组件的模板（如 `entry`）回落到字段表里的全部
   自定义字段；老数据的 `info.params.fields` 内联字段仍按原样读，选择器里可一键「存为组件」。
   **两个入口**：模板侧「基本信息」行的设置键打开**组件选择器**（列出全部组件、单选、每行设置键
   跳到组件编辑器、底部「新建基本信息组件」）；设置 › 世界 › 自定义组件 › 基本信息管理组件库
   （其中「字段表」仍分角色 / 事件 / 词条三条实体行，走 `lib/fields`）。模板字段键在扫描前登记
   （`vault-load` 的 `readTemplateFieldKeys`，会连 `info-groups.json` 一起读），盘上的值也能读回。
7. **封面槽位**：`WorldEntry.cover` 是分类条目的 3:2 封面（frontmatter `cover` / `封面图`），
   `WorldCoverField` 由世界编辑器与分类编辑器共用；卡片和目录行显示缩略图，`.ocbak` / 文件夹落地
   通过 `collectWorldEntryImageRefs` 一起带走。宠物 / 武器模板的 `cover` 组件默认开启。
8. **旧 `类别` 角色**：设置 › 世界 › 自定义分类会检测角色上遗留的 `kind` / `类别: 武器|宠物`，
   一键复制成对应分类条目（封面 / 简介 / 正文 / 标签 / 自定义字段）。**只复制、不删原角色**，
   同名同分类跳过；导入后清掉角色上的旧键，避免重复提示。
9. **编排预览**：右栏取真实数据 —— 笔记模板取最近一篇匹配笔记，实体模板取最近角色 / 事件 / 国家；
   渲染封面、标题、模板字段、标签、简介、正文、关系、画廊、时间 / 地点（画廊取真实缩略图，
   最多 4 张）。取不到数据时回落到结构示例。编排层顶栏「导出图片」打开**导出中心 · 海报页签**
   （预选当前对象），用 `PosterCanvas`（1080 宽隐藏排版）+ `html-to-image` 导出 PNG；那里可选版式 /
   内容组件 / 封面位置与倍率 / 对齐 / 列数 / 背景 / 署名，封面 / 画廊可点开全屏查看；关系可点击，
   关闭编排层与设置后跳到真实实体；标签可点击，跳到设置 › 标签管理。

## 3. 文件格式

### 3.1 笔记只记模板名

```md
---
模板: 角色
名称: 蜜蜂
别名: [蜂, 小蜜]
头像: images/qavatar-1234.png
立绘: [images/p-1.png]
种族: 精灵
国籍: "[[瓦兰]]"
生日: "1234-05-06"
标签: [主角, 蜂群]
重要: true
关系:
  - 类型: 所属
    目标: "[[瓦兰]]"
---

## 简介

养蜂人，左臂有蜂巢状纹身。

## 正文

她出生在雨季的第三天……
```

**没有 per-note 布局键。** 想要不同排法 → 换模板。

### 3.2 模板也是 markdown

```md
---
名称: 角色
id: character
组件: [封面, 基本信息, 关系, 标签, 时间, 简介, 正文]
基本信息:
  字段: [名称, 头像, 立绘, 别名, 种族, 国籍, 生日]
关系:
  呈现: 表格
画廊:
  模式: 网格
---

（正文留空；这一栏只是给人看的说明）
```

- `id` 不可改，`名称` 可改
- **改名不批量回写笔记**：笔记里的 `模板:` 是旧名时按模板的 `别名` 匹配

### 3.3 为什么文件里仍是两段

1. frontmatter 结构化、正文不是；合并只能把结构化数据塞进正文 → Obsidian 里全是机器语法
2. markdown 往返不再保真
3. 现在是外科式写入（未编辑零改动），塞进正文后每次保存都要重写整段

统一只做在两段**之上**：模型层是组件序列，文件层是两段。

### 3.4 引用 vs 快照

| 想要 | 用什么 | 文件里 |
|---|---|---|
| 事件笔记里看到角色卡，角色改了要跟着变 | **引用** | 一行 `![[弗利欧]]` |
| 一段台词、一张一次性排版卡 | **快照** | ` ```oc-card ` 围栏块 |

- 引用不需要新语法：`![[名字]]` 是纯文本，Obsidian 原生认，往返零风险
- 快照沿用 `markdown/doc.ts` 的 `FALLBACK_FENCE_INFO` 机制，换个 info 串（`oc-card` / `oc-line`）

**实体类一律用引用。** 快照会让"哪一份才是真的"重新成为问题。

### 3.5 命名与重命名通则

**文件里存的永远是人可读的名字，不是 id；改名靠别名，不批量回写。**

| 对象 | 存什么 | 改名怎么办 |
|---|---|---|
| 模板 | `模板: 角色` | 旧名写进模板的 `别名`，读取时按名 + 别名匹配；零文件改动 |
| 标签 | `标签: [主角, 蜂群]` | 旧名写进 `.ocstudio/tags.json` 的 `aliases`，读取时归一 |

只有用户显式点「整理 / 应用」时才真正改写文件（那是他自己的动作，也知道会动哪些篇）。这条通则在两个地方复用，不要为标签另发明一套。

## 4. 组件清单

| # | 组件 | 级别 | 数据键（frontmatter） | 消费者 |
|---|---|---|---|---|
| 1 | 封面 | block（无标题） | `cover` | 编辑器 · 列表卡 · 导出 · 站点 |
| 2 | 基本信息 | group | `名称` + 各 atom | 全部 |
| 2a | 名称 | atom | `名称` | 全部 |
| 2b | 头像 | atom | `avatar` | 编辑器 · 列表 · 导出 |
| 2c | 立绘 | atom | `portrait[]` | 编辑器 · 相册 · 导出 |
| 2d | 普通字段 | atom | 字段名（`别名`/`种族`/`国籍`/`生日`…） | 编辑器 · 搜索 · 列表 |
| 3 | 关系 | block | `关系[] = {类型, 目标}` | 编辑器 · 关系图 · 反查 |
| 4 | 标签 | block | `tags` | 全部 |
| 5 | 图片 | block | `image` | 编辑器 · 相册 · 导出 |
| 6 | 画廊 | block | `gallery[]` | 编辑器 · 相册 · 导出 |
| 7 | 时间 | block | `time` / `endTime` | 编辑器 · 时间线 · 排序 |
| 8 | 地点 | block | `place`（预留 `placeId`） | 编辑器 · 未来地图 |
| 9 | 重要 | atom | `important` | 列表筛选 · 首页 |
| 10 | 简介 | block | `summary` | 编辑器 · 列表摘要 · 导出卡 |
| 11 | 正文 | block（无标题） | markdown 正文 | 编辑器 · 站点 · 全文搜索 |

> 键名以 `lib/vault/fields.ts` 词汇表为准（它是唯一源）。
>
> **词条 / 分类条目也拥有全部槽位**（2026-11-06）：`WorldEntry` 新增
> `avatar` / `image` / `gallery` / `time` / `endTime` / `location`，落盘键与实体侧同名；
> 关系分三类：手写的命名边存 `WorldEntry.relations`（与角色 / 事件同形，目标只能是另一篇笔记），
> 父 / 子来自 `parentId`，引用 / 被引用来自正文 `[[ ]]` / `@` 的查询。三者各管一种事实，
> 不互相镜像；关系块把同一目标的多行合成一行显示（命名边优先）。
> 自定义字段与词汇表撞名时以第一类列为准（`readCustomFields` 跳过已被占用的键）。
>
> **接线进度只认 `src/lib/templates/support.ts`**（2026-11-06：十一个组件全部接线）：
> 组件在模板里开了却没人画，等于骗用户 —— 没接线的组件在设置里会显示「开发中」且不可点
> （2026-11-08 起四行全部可点：基本信息 / 正文 / 关系 / 画廊）。
> 实体模板的「正文」在全宽布局按模板顺序渲染；分栏布局正文固定在右栏（那是布局模式，不是模板）。
>
> **添加列表按宿主收窄**（2026-11-06）：实体模板的「添加组件」只列它真有数据列的组件 ——
> 角色没有时间 / 地点 / 单图，事件没有头像 / 单图，国家没有时间 / 地点 / 单图；
> 笔记模板仍是十一个。宿主表就是 `support.ts` 的 `WIRED_BY_TEMPLATE`，
> `availableComponents(templateId)` 是「添加列表」的唯一来源（设置与编排层共用）。
> 历史模板里已经加过的不可用组件仍按行显示、可手动移除，不会被静默删掉。

**「重要」是 atom 不是 block**：它是个标记，不该占一个区块。默认在基本信息组内，列表卡右上角以星标呈现。模板硬要拉成 block 也允许，渲染为一行 checkbox，标题默认关。

**标签是维度，不是分类树**（2026-10-30 定）：一个标签 = 名字 + 颜色 + 别名，可以改名、合并、统计使用篇数；**不做层级**，没有父子标签。理由：关系图已经承担了结构表达，再叠一套分类树就是过度分类——创作最忌讳这个。

### 4.1 图片槽位（一套实现，五个槽位）

封面 / 头像 / 立绘 / 图片 / 画廊看起来像，但**不能互换**。真正的区别不在长相，而在这四件绑死的事：

1. **裁剪比例在写入时就定死**，直接决定存下来的字节
2. **谁在别处取它**：头像被列表卡、`@` 下拉、关系图节点吃掉；封面被站点首页吃掉；图片不会
3. **相册怎么分组**：每个槽位是相册里的一个抽屉
4. **导出卡默认勾不勾**

| 槽位 | 键 | 数量 | 比例 | 裁剪 | 圆形 | 级别 | 相册分组 | 导出卡默认 |
|---|---|---|---|---|---|---|---|---|
| 封面 | `cover` | 1 | 3:2 | 有 | — | block（无标题） | 封面 | 勾 |
| 头像 | `avatar` | 1 | 1:1 | 有 | 是 | atom | 头像 | 勾 |
| 立绘 | `portrait[]` | n | 9:16 | 有 | — | atom | 立绘 | 勾（首张） |
| 图片 | `image` | 1 | 任意 | 无 | — | block | 正文图 | 不勾 |
| 画廊 | `gallery[]` | n | 任意 | — | — | block | 画廊 | 不勾 |

**为什么不能合成一个「图片」**：合成会同时丢掉上面四样，是退化不是精简。

**代码契约**（合并实现，参数化槽位）：

```ts
/** 图片槽位：图片能力的唯一入口，五个槽位只是参数不同 */
export interface ImageSlot {
  /** frontmatter 键名（人可读，见 §3.5） */
  key: string
  /** 单选一张 / 多选一组 */
  multiple: boolean
  /** 裁剪框比例；null = 不裁剪，保持原图 */
  aspect: number | null
  /** 圆形显示（头像） */
  round?: boolean
  /** 挂在哪个组件里：block 独立成块，atom 只在 group 内 */
  level: 'block' | 'atom'
  /** 相册里的抽屉名 */
  albumBucket: string
  /** 导出角色卡时默认勾选 */
  exportDefault: boolean
}
```

- 编辑器渲染只有一个 `ImageSlotField`（选图 → 裁剪 → 落盘 → 改写引用），**不是五份图片组件**；呈现差异由 `aspect` / `round` / 列数决定
- 模板里这五个是**固定槽位**，不能互换（不能把「封面」改成「头像」），只能开关；「图片 / 画廊」额外允许改宽度、列数、网格或滑动——那是呈现，不是语义
- **立绘 vs 画廊**是同一个"图片数组"能力的两个槽位：立绘在基本信息组内、固定 9:16；画廊是独立 block、可切网格或滑动。区别在位置与默认呈现，不在数据。这也解释了为什么清单里立绘是 atom、画廊是 block

一句话：**数据一个，槽位五个，实现一套，皮肤五层。**

## 5. 视觉契约：小节壳（ComponentSection）

**组件化的第一个抽取物。** 现在 `CharacterFrontmatter.tsx` 把同一套壳手写了三遍（立绘 / 关系 / 相册）。

### 5.1 结构

```tsx
<ComponentSection title="关系" action={<AddAction … />} divider>
  {items.length > 0 ? <RelationsTable … /> : null}
</ComponentSection>
```

```
┌─────────────────────────────────────────────┐  ← divider：1px border-line，第一个区块不画
│                                             │  ← 24px（pt-6，线与标题不贴在一起）
│  关系                              ＋ 添加  │  ← SECTION_TITLE_BARE + ADD_ACTION
│                                             │  ← 12px（mb-3）
│  （内容区：空则不渲染，壳到这里结束）        │
└─────────────────────────────────────────────┘
```

### 5.2 三种状态

| 状态 | 渲染 |
|---|---|
| **空** | 只渲染标题行，内容高度 0 —— 整壳 ≈ 24px |
| **满** | 标题行 + 内容；内容区**不带横向内边距**（外层统一给） |
| **只读** | 标题行保留，`action` 省略 |

> token 里已写明：`ADD_ACTION` 的注释就是「空区块只留标题行，内容出现后再撑开」。

### 5.3 节奏（壳统一给，组件不许带 margin）

| 位置 | 宽（完整编辑器） | 窄（三栏中栏 / 移动） |
|---|---|---|
| 区块之间 | `gap-8`（32px） | `gap-6`（24px） |
| 分隔线 → 区块内容 | 24px（`pt-6`，画线的那一块自带） | 同 |
| 标题行 → 内容 | 12px（`mb-3`） | 同 |
| 外层内边距 | 无（全宽阅读） | `p-4` |
| 分隔线 | 1px `border-line`，画在区块**顶部** | 同 |

字段行不许自带上下 margin；尾线靠 `LIST_END` / `FIELD_GRID` 去掉。

### 5.4 标题参数

block 支持 `标题: false`（默认开）。用于事件模板把「时间」放第一位且不要标题、或「重要」拉成 block 时。

### 5.5 实现分层（2026-11-06）

| 层 | 文件 | 职责 |
|---|---|---|
| 组件块 | `src/components/shared/template-blocks/` | 有数据的区块：时间 / 地点 / 简介 / 画廊 / 图片 / 头像。**不碰数据库**，值从 props 来、改动走回调 |
| 渲染循环 | `src/components/shared/TemplateRenderer.tsx` | 顺序 / 开关 / 分隔线；`render` 返回 `null` 就不占位 |
| 实体宿主 | `features/{characters,events,countries}/...Frontmatter.tsx` | 把各自强类型列映射成块；正文在全宽布局按模板顺序渲染 |
| 笔记宿主 | `features/world/components/note/NoteTemplateContent.tsx` | **一处分发**：世界观编辑器与分类条目编辑器共用；`NoteBlocks.tsx` 负责读写 `worldEntries` |

同一条规则：**新增一个组件只改这三处**（块 / 分发 / 接线表），不要在每个编辑器里各写一遍 switch。

### 5.6 反例（编辑器里不许出现）

- ❌ 卡片容器（`bg-paper-card` 的圆角矩形）
- ❌ 描边 / 虚线框 / 空态占位框
- ❌ 悬停才出现的 **🗑 删除 / 拖拽手柄**（危险动作不许跟着悬停浮出来）
- ❌ 组件名旁的"这是组件"标签、类型徽章

> **唯一的例外（2026-11-08）：悬停才现的 ⚙**，而且只做一件事 —— 跳到这个组件的设置。
> 有标题行的块（基本信息）放在标题行最右边；没有标题行的块（正文）浮在块右上角。
> 组件解析在 `lib/templates/edit-target.ts`，按钮是 `components/shared/ComponentEdit.tsx`。
- ❌ 空组件显示"还没有内容"之类的提示句（Rule 13）

### 6.1 封面

### 6.2 基本信息

- 顺序：头像 → 名称 → 立绘 → atom 列表
  - 头像 `rounded-full`，空态用衬线首字

### 6.3 关系

> **2026-11-05 已实装**（`src/components/shared/relations/`）。角色 / 事件 / 国家共用同一个
> `RelationsSection`，三个编辑器的 form hook 只负责把各自的存储列映射成 `RelationRow[]`；
> 原来的 `CharacterRelationSection` / `EventRelationSection` / `CountryRelationSection` 已删除，
> 「关联」这个叫法与那种「相关角色 / 相关国家 / 相关事件 / 标签」各写一行的形态一并退役。

- 标题 `关系` + `＋ 添加`；添加浮层按实体类型分组、可搜索，**候选由各编辑器给**
  （角色给角色 / 笔记；事件给角色 / 国家 / 事件；国家给角色 / 事件；笔记只给笔记）
- **三档呈现，同一份数据**：紧凑（chips + 关系名）/ 列表（表格：对象 · 类型 · 关系 · ×）/ 图（只读缩略）
  - 笔记的「类型」列显示具体分类（宠物 / 武器 / 自定义分类名），不是笼统的「词条」；没有分类才回落「词条」
  - 切换：标题行右侧图标，hover 才显形；**写回模板**（`relations.presentation`），不是单篇
  - 窄栏（< 480px）强制紧凑，切换图标一并收起；图只读，建边只在「关系图」页
  - 图呈现只画当前实体与直接关系（中心 + 一圈目标，反查虚线），不跑布局、不画整库
- **只写一侧**：角色 ↔ 角色一对一条边、一个名字；另一侧是查出来的，不是存的（§1.4）。
  「来自」那一组是反查行：只读、没有 ×；事件 / 国家的参与者与成员是**事实边**，
  关系名固定（参与 / 属于 / 发生于），不提供改名
- **箭头**：命名边（角色↔角色、事件↔事件）的关系格里有一个箭头小钮，四档
  无 / 正向 / 反向 / 双向，写回同一条边的 `arrow`；角色↔角色默认双向、事件↔事件默认无箭头，
  事实边不显示。反查行只显示字形（改的是另一侧的边）；`none` 也写盘，
  否则「没设」会被角色边默认双向吃掉（见 `docs/关系图.md` §2.1）
- 空态：只有标题行
- **数据仍写现有强类型列**（阶段一）：`Character.relatedCharacters`、`Event.relations` /
  `characters` / `countries`；国家的成员仍是 `Character.countryId` / `Event.countries` 的查询。
  阶段二·二再统一成落盘的显式边，见下面的数据形状。
- 参数：`relations.presentation`（表格 / 紧凑 / 图）+ `relations.title`，三件套模板都消费
  （`lib/templates/params.ts`）；设置里的接线进度见 `lib/templates/support.ts`
- **笔记宿主 = 层级 + 命名边 + 正文提及**（2026-11-06）：
  - 父词条 / 子条目：`parentId` 的两头，查询、只读
  - 命名边：`WorldEntry.relations`，与角色 / 事件同一套边模型；「添加」直接在关系块里选一篇笔记
    并落一条边，表内可改名、改箭头、×。目标只能是另一篇笔记（角色 / 事件 / 国家用 `@` 提及）
  - 引用 / 被引用：正文 `[[ ]]` / `@` 的扫描（`useNoteLinks`），查询、只读
  - 同一目标已有命名边时不再重复显示「引用」；反查侧同理，命名边优先
  - 双边关系仍是**两条边**：A 给 B 起一个名字，B 那边是只读的「来自 A」；B 要自己的叫法就再建一条
  - **不把命名边塞回正文**：正文提及是文字，命名边是数据，二者可以同时存在，UI 只显示一行
- **角色 → 笔记是反向的同类边**（2026-11-06）：`Character.relatedNotes`（落盘 `related_notes` / `相关笔记`），
  角色关系块里直接选笔记；笔记侧读到的是只读「来自该角色」。与笔记自己的 `relations` 同形，
  目标固定是笔记，不会和 `relatedCharacters` 混在一起

**数据形状（阶段二，已按现状校正）**：落盘是 `relations: [{ name, relation, color?, arrow? }]` —— `name` 是目标的**文件名/标题**（`[[ ]]` 的解析键），`relation` 是关系名；`color` 取色板名（`lib/relation-colors.ts`），`arrow` 取 `none / forward / reverse / both`（角色之间默认 `both`，笔记 / 事件 / 归属与参与默认 `none`，见 `docs/关系图.md` §2.1）；两条都**可选**，不写就是不设。同两点可以有多条不同名字的边（兄弟 + 同事），图里并行错开。笔记的 `targetId` 只在内存里，落盘后靠 `name` 重新解析；目标改名时写回会按 `targetId` 重写 `name`。角色的 `related_notes` 用同一形状，只是落盘键不同。

- 配置面：**设置 › 世界 › 自定义组件 › 正文** → 组件列表（字数 / 空）→ 用**编辑器内核**
  （`EditorCore`）写；新建 / 点击改名 / 删除都在这一页，改完 600ms 自动存，没有保存按钮
- 模板里只剩**选择**：编排行 / 模板页点「正文」的设置键 → 正文组件选择器

- 铺正文的入口只有一个：各 `create*`（角色 / 事件 / 国家 / 词条）里读选中的组件，
  **走了 AI 的 `library_create` 也自然拿到**。组件是「空正文」= 不铺（不写空文档）
- 旧数据：`body.params.preset`（把 Markdown 直接写在模板里）**只读兼容**，不再写
- 旁注：没有预设的旧实体仍由 `DocumentEditor` 的默认骨架兜底（`lib/body-skeleton.ts`），
  那是**渲染时的占位**，不落盘；正文组件是**真的写进正文**，两者不冲突

## 7. 配套界面总览

组件化的"配置面"。**配置面可以像工具，但必须用同一套墨水。**

| 界面 | 形态 | 尺寸 | 预览 | 何时看到 |
|---|---|---|---|---|
| 模板编排 | 全宽覆盖层 | 左 200 / 中 flex / 右 400 | 实时 | 从设置进入 |
| 标签管理 | 弹窗 | 640 × 70vh | 无 | 设置 › 世界 › 标签 |
| 组件编辑（参数） | 右侧抽屉 | 360 | 无（改完看编排预览） | 编排行 chevron |
| 正文组件 | 设置内的编辑器页 | 同设置弹窗 | 无（写的就是最终正文） | 设置 › 世界 › 自定义组件 › 正文 |
| 基本信息组件选择 | 行内展开的组件列表 | 同编排行 | 无 | 「基本信息」行的设置键 |
| 图片导出 | 导出中心 · 海报页签 | 全宽覆盖层：左预览 / 右 320 | 实时画布（1080 宽真 DOM 缩放） | 文件 / 模板编排 |
| 网页导出 | 导出中心 · 网站页签 | 同上 | 实时 iframe（桌面 / 手机） | 文件 / 设置 › 数据 |

### 7.1 配置面的设计纪律

| 允许（写作面不允许） | 仍然禁止 |
|---|---|
| 拖拽手柄、复选框、chevron、开关 | 阴影（唯一一档 `FLOAT_SHADOW` 只给浮层） |
| 分组标题（`text-[11px] tracking-[0.08em] text-ink-faint`） | 卡片描边 / 虚线框 |
| 行 hover 高亮 `bg-[var(--oc-hover)]` | 任何黑白半透明底（用 `--oc-hover`） |
| 选中浅底块 | 超过三档的圆角 |
| 紧凑行高（32–36px） | 彩色强调（危险色除外） |

一句话：**写作面像纸，配置面像工具，用的是同一套墨水。**
所有新界面必须能通过 `npm run audit:design`。

## 8. 模板编辑界面

### 8.1 层级

```
设置 › 世界 › 模板         ← 模板卡片列表（每张：名称、组件数、用它的笔记数）
        └─ 点卡片 → 全宽编排层（Esc / ← 返回）
```

**为什么是全宽覆盖层而不是塞在设置弹窗里**：三栏（列表 / 编排 / 预览）在 720px 的弹窗里做不出来，硬塞会变成滑动地狱。入口仍在设置里——它属于设置，不属于创作。

### 8.2 布局

```
┌───────────────────────────────────────────────────────────────────┐
│ ←   角色                                    ⋯      ─   □   ×     │  ← 顶栏 48，与编辑器页头同高
├──────────┬──────────────────────────────────┬─────────────────────┤
│ 模板      │  ⠿ 封面                    [开] │  预览   窄 · 宽     │
│  角色  ●  │  ⠿ 基本信息          [开] ▸     │  ┌───────────────┐  │
│  事件     │  ⠿ 关系    呈现[表格 ▾]          │  │  弗利欧        │  │
│  国家     │  ⠿ 标签                    [开] │  │  流浪的绘星师  │  │
│  词条     │  ⠿ 画廊  模式[网格▾] 列[3]       │  │  …            │  │
│           │  ⠿ 正文                    [开] │  └───────────────┘  │
│ ＋ 新建   │  ＋ 添加组件                      │  预览不写入文件     │
└──────────┴──────────────────────────────────┴─────────────────────┘
```

- 左栏 200：模板项 `h-8`，选中 `bg-[var(--oc-hover)]`；底部「＋ 新建模板」
- 中栏：编排列表，宽 ≥480
- 右栏 400：预览

### 8.3 编排行

| 部位 | 规格 |
|---|---|
| 行高 | `h-9`，`px-2`，`ROUND_ITEM`，hover `bg-[var(--oc-hover)]` |
| 手柄 | 最左 12px，**仅 hover 显形**（观感同 `DRAG_SLOT_ROW`） |
| 名称 | `text-sm text-ink`，占满剩余 |
| 开关 | 关掉 = 组件不在模板里，整行文字转 `text-ink-faint` |
| 参数 | 有参数时一个 `SlidersHorizontal` 图标，点开**行内参数条**（轻参数用分段按钮；`info` 用组件选择器）。契约在 `src/lib/templates/params.ts`，只对真正消费参数的模板开放 |
| 行间 | **无线**（这是列表不是表格） |
| 拖拽中 | 被拖行 `opacity-40`，落点是 2px 墨色线，不是占位块 |
| 底部 | 「＋ 添加组件」→ `MENU` 列出未启用的组件，点一下加到底 |

### 8.4 组件参数编辑（当前实装：行内；右侧抽屉待做）

- 当前：点行内 `SlidersHorizontal` → 在该行下方展开参数条（无底色），选中浅底块；改动即时写模板
- 轻参数：`relations.presentation` / `title`，`gallery.mode` / `columns` / `title`，
  `time.interval` / `title`，`place.title`，`summary.title`，`image.width` / `title`（分段按钮）
- 基本信息：`info.group`（选中的组件 id）—— 不是「本模板的字段」，而是**从组件库里选一个**，见 §8.5
- 正文：`body.group`（选中的正文组件 id）—— 与 `info.group` 同一套：**从组件库里选一个**，
  见 §6.10 / §8.6
- 契约唯一源：`src/lib/templates/params.ts`；`npm run audit:templates` 校验「值合法 / 有消费方 / 能往返」
- 待做：参数多到行内放不下时再抽右侧抽屉（宽 360，从右滑入，左缘 1px `border-line`，`FLOAT_SHADOW`）
- **无保存按钮的语义**：改动即时写模板文件；读写失败才报错

### 8.5 基本信息组件（选择，不是编排）

**模板不拥有字段**。基本信息是一份独立的、可复用的组件（`InfoGroup`），模板只**选择**其中一个：

```
基本信息                          宠物  ⚙  ×
  ├ 基本信息组件
  │   ● 宠物                15 个字段  ⚙
  │   ○ 武器                12 个字段  ⚙
  │   ＋ 新建基本信息组件
  ├ 标签
  └ 正文
```

- **名字无关**：组件叫什么由用户定，跟模板名没有任何绑定；改名不影响任何模板（引用的是 id）
- **关系 = 选择**：模板里存的只有 `info.params.group = <id>`；同一份组件可被多个模板同时选中
- 行上右侧显示选中的组件名（`宠物` / `内联字段` / `未选择`），不展开也能看出选了谁
- 每行 `⚙` 跳到组件编辑器（设置 › 世界 › 自定义组件 › 基本信息 › 该组件）
- 底部「＋ 新建基本信息组件」：建一个空组件 → 立刻选中 → 跳进去加字段
- 组件库在设置里维护（`BasicInfoPanel`）：新建 / 改名 / 增删字段 / 删除；编辑器顶部一行
  「`角色、武器 在用`」是反向引用（哪些模板选了这个组件）
- 内置组件（宠物 / 武器）可改字段、可改名、不可删；自建组件可删，删掉后引用它的模板退回
  「全部字段」（不静默清空数据）
- **字段类型**（2026-11-06）：笔记型组件的每个字段可选 **单行 / 数字 / 日期 / 开关**
  （`InfoGroup.types`，缺省 = 单行；列型宿主的控件归 `lib/fields`，组件里写了也不作数）。
  出厂时宠物 / 武器的日期、体重已经配好；改过的内置组件底部给「恢复出厂字段」。
  值仍一律存字符串（`WorldEntry.custom`）：开关 `'true' | 'false'`、日期 `YYYY-MM-DD`
- **没有「多行」这一档**（2026-11-06 删）：长文本归**正文**组件，基本信息只放结构化短字段。
  在基本信息里开多行框，等于在正文旁边再造一份长篇正文 —— 两边各写各的，写的人不知道该写哪边；
  版式也会被切成「两列 → 整宽 → 两列」三截。内置宠物 / 武器原有的长文字段（外观特征 / 性格 /
  习性 / 能力技能 / 使用条件 / 能力效果）已从字段表移除，那几段写进正文。
  盘上留着的 `'longtext'` 读回时**一律回落单行**（`isInfoFieldType` 不认它），字段与已存的值都不删
- **显示名与落盘键分离**（2026-11-06）：`InfoGroup.labels` 存「键 → 显示名」，缺省 = 键名。
  行上主输入框改**显示名**（不动数据），右侧一个 `#` 小字改**落盘键**（frontmatter 的键名；
  改键不搬已存的值，但类型与显示名跟着键一起搬）。键与显示名相同时不存冗余条目
- 老数据的内联 `info.params.fields` 仍能读；选择器底部提供「存为组件」，把它收成一份正式组件
- **实体字段表是另一条线**：角色 / 事件 / 词条的字段表走 `lib/fields`，实体模板直接消费，
  不进这个组件库（否则同一份字段会有两个真源）

### 8.6 正文组件（选择，不是编排）

和 §8.5 同一套关系，只是内容从「字段」换成「骨架」：

```
正文                              角色  ⚙
  ├ 正文组件
  │   ● 角色（## 人物简介 / ## 人物生平）  ⚙
  │   ○ 国家（政治制度 / 地理环境 / 人文风貌）  ⚙
  │   ○ 空正文
  │   ＋ 新建正文组件
```

- 模板里存的只有 `body.params.group = <id>`；组件自己有名、有 Markdown 骨架
- 内置组件可改不可删；删掉自建组件后，引用它的模板退回默认（角色 / 国家各自一份）
- 「空正文」是一种正当选择：不铺任何东西
- 选择器与基本信息组件的选择器**长一样**（单选 / 每行设置键 / 底部新建），
  设置键跳到 设置 › 世界 › 自定义组件 › 正文（深链 `body:<id>`）

### 8.6 模板操作

| 操作 | 行为 |
|---|---|
| 新建 | 空白模板 = 封面 + 基本信息 + 正文 |
| 复制 | 名 `角色 副本` |
| 导出 | 存成 `.ocstudio/templates/<名>.md`，可分享 |
| 恢复默认 | 内置模板专用，回到出厂定义 |
| 删除 | 内置不可删；自建删前确认（`BTN_DANGER`） |

### 8.7 主题

模板可填 `主题: <主题 id>`，只允许引用已注册主题，不许写任意 CSS。
「不同国家的角色用不同背景」= 两个模板各挂一个主题 id。

### 8.8 标签管理（维度维护）

入口：`设置 › 世界 › 标签`。弹窗 640 × 70vh，**这里才允许出现"分类管理"的味道**，但仍不许彩色强调。

```
┌──────────────────────────────────────────────┐
│ 标签                                      ×  │
├──────────────────────────────────────────────┤
│ ● 主角        12 篇       改名 · 合并 · 删除 │
│ ● 蜂群         3 篇       改名 · 合并 · 删除 │
│ ● 反派         8 篇       改名 · 合并 · 删除 │
│ ＋ 新建标签                                   │
└──────────────────────────────────────────────┘
```

| 动作 | 行为 |
|---|---|
| 新建 | 名字 + 色板（`lib/tag-colors.ts` 预设，不开放任意取色） |
| 改名 | 改 `db.tags.name`；落盘队列的 `enqueueTagReferences` 会把所有引用它的实体排进队列，下次 flush 用新名字重写 frontmatter。**没有 aliases 读取层**——这条实现选择了“改名即重写引用”，因此不需要整理动作 |
| 合并 | 选一个目标标签：所有实体里的源 tag id 换成目标 id，再删源标签；篇数自然相加 |
| 删除 | 从注册表移除，并把该 tag id 从所有实体里摘掉；**笔记本身保留**。会触发引用重写（与“只删注册表”的旧设想不同，理由同上：当前读取层按 id 找名字，留下孤儿 id 无法显示） |
| 计数 | 该标签被多少篇笔记引用（扫四张实体表，不读正文） |

删除的语义要写死：**删标签 ≠ 删笔记。** 笔记、正文、其它字段都不动，只去掉这个标签引用。

> **2026-11-05 已实装**：`设置 › 世界 › 标签`（`features/tags/components/TagsPanel.tsx`）。入口是设置二级面板而不是独立弹窗，因为设置里已经有同级的“自定义分类 / 模板 / 自定义组件”。

## 11. 分阶段实施

| 阶段 | 干什么 | 可见效果 | 迁移 |
|---|---|---|---|
| **一** | `ComponentSection` 壳 + 组件 registry + 模板文件 + 渲染循环；**数据仍写原有强类型列** | 编辑器由组件拼装；空/满态统一；设置里能编排；分类条目在分类内按模板渲染 | 无 |
| **一·收尾** | 十一个组件全部接线（2026-11-06）：笔记宿主补六列 / 实体补简介与画廊 / 呈现块共用；正文在全宽布局按模板顺序 | 设置里不再有「开发中」；任何含正文的模板都能绑分类 | 无（新键是可选列） |
| **二** | 字段 / 关系 / 时间 / 地点统一成 frontmatter 键；**显式关系边替掉国家镜像** | 自定义模板真能改结构 | 有 |
| **三** | 通用记录模型（模板可定义全新实体） | 自定义实体 | 大 |
| **四** | 图片导出 + 网页导出 + 预设 | 导出角色卡 / 站点 | 无 |

**阶段一是关键：不迁移也能看见组件化。**

成本公式：**每加一个组件 = 1 个契约 × 最多 6 个消费方**（编辑器 / 列表 / 搜索 / 时间线·图 / 导出 JSON·MD / 导出图片·站点）。

## 12. 明确不做

- 用户自定义组件（写渲染逻辑）：插件系统 + 沙箱
- 模板带任意样式 / 脚本：只允许引用注册过的主题 id
- 正文里再嵌任意块（Notion 那种）：毁掉 markdown 往返
- 改模板自动 retro-fit 已有笔记的结构：只影响新建与默认呈现
- 单篇笔记覆盖组件顺序：想要别的排法 → 换模板

## 14. 风险

1. **组件粒度爆炸**：block → group → atom 已三层，再加层级就会变成模板语言。止步线在 §12。
2. **模板与实现漂移**：模板能配的东西必须每项都有渲染器支持，否则用户配出"没反应的组件"。需要模板校验（`audit` 式）。
3. **模板数量膨胀**：「每篇想不一样就新建模板」会让设置里长成排版软件。闸门：模板是一**类**的形状，不是一**页**的形状。
4. **迁移不可逆点**：阶段二的显式关系边落盘后旧版读不懂——接受（`.ocbak` 兜底）或写双读。
5. **样式漂移**：十一个组件各自写间距一定漂。间距只由壳给，这条要进 code review 清单。
6. **别名只增不减**：模板名和标签名的旧名一直堆在 `别名` / `aliases` 里，越积越长。必须有一个显式的「整理」动作（§8.8）把它们真正改写进文件再清空；不做这个动作，索引层会越来越慢、越来越难调试。
