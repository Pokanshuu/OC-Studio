# 小说

> **已实现**（2026-11-04 随 PR #5 吸收，2026-11-08 补齐预览与导出）：书架 / 章节树 / 作品信息 / 分页预览 / 导出 Markdown · TXT · Word · 逐页 PNG。
> 仍未做的只有三条（整棵树当大纲、与设定反向联动、小说目录不进关系图与相册），见 `docs/todo.md` §7。
> 定位：小说是**库里的一类笔记**，不是另一个应用。

- **`小说/` 目录必须在扫描的关键词表里**（`lib/vault/mapping.ts` 的 KEYWORD_RULES）：漏了它，整个目录会被判成「未映射」，文件不落库 —— 表现就是「刷新之后书架空了」（2026-11-06 修）。地图同理。
## 0. 一句话

**章节 = 一篇笔记**，大纲 = 一棵树；导出时把整棵树拼成一册。

---

## 1. 放在库里，不另开新库

```
笔记库/
├── 角色/ 事件/ 国家/ 词条/        ← 设定集
├── 小说/
│   ├── 第01章-雨季.md
│   ├── 第02章-蜂巢.md
│   └── 大纲.md
└── .ocstudio/
```

- 章节和设定在同一棵树里，`@` 引用、`[[内链]]`、搜索、回收站、时间线全部免费复用
- 章节用**文件名前缀**排序（`第01章`），不另建章节表——排序规则简单、Obsidian 里也认得

## 2. 大纲用现有的 `parentId`

`lib/world-tree.ts` 的 `buildEntryTree` 已经是"树唯一实现"，大纲直接复用：

| 层 | 例子 |
|---|---|
| 卷 | 第一部：蜂群 |
| 章 | 第01章 雨季 |
| 节（可选） | 01-3 她在等雨停 |

编辑器侧栏的 `OutlinePanel` 是雏形，合并 fork 后统一到树；**不新增第二套层级表达**。

## 3. 与设定的联动（这是相对普通写作工具的全部优势）

| 能力 | 怎么来 |
|---|---|
| 正文里 `@角色` | 已有的 mention 引用；导出时可选择"显示名字"或"显示带链接的名字" |
| 一致性检查 | agent 的 skill：把章节里提到的设定和实体当前值比对（"她说是银发，档案写黑发"） |
| 章节涉及哪些角色/国家 | 从 `@` 引用反查（**算出来的，不存**，见 `docs/模板.md` §1.4） |
| 时间线 | 章节可以挂时间点，于是能在大纲里看出叙事顺序 vs 世界时间顺序的错位 |

最后一条是这个功能真正的卖点，也是普通写作软件做不到的。

## 4. 导出器

| 格式 | 说明 |
|---|---|
| **Markdown** | 按树拼接，章节之间插标题；图片按相对路径 |
| **TXT** | 最朴素，平台投稿常用 |
| **Word** | 作品信息（作者 / 简介 / 封面）+ 章节结构，自带最小 ZIP writer |
| **PNG** | 逐页出图（9:16 / 16:9 / A4），四套版式 + 字号 / 行距 / 页边距 / 页码 / 扉页，打包成 zip |
| 静态站 | 复用 `lib/export/site`，可发布连载 |
| EPUB | 后置（要额外依赖，且排版是另一个坑） |

导出走现成的 `lib/export/` 管线（图片内联、单文件、`files.rs` 落盘），不另建一套。

**整本翻页预览在导出中心的小说是左半边**（`features/novel/NovelReader`）：一次一页、
`‹ ›` / ← → 翻页、`±` 缩放、双击切「整页 / 宽度」。它和 PNG 导出**共用同一份分页**
（`pagination.ts`：章节 → 页 → 行）与**同一份版式**（`layout.ts`：四套预设 + 参数），
所以预览里看到的就是导出的那张纸。版式参数与三套 / 四套预设的细节见 `docs/导出器.md` §5。

**Word / Markdown / TXT 的预览是共用的**：直接画一页 A4，用的是导出中心同一个
`components/shared/document/PagePreview`（模型见 `lib/export/page`）。小说这边只做一次映射 ——
`features/novel/preview-doc.ts` 的 `novelPageDoc()`：整本书一个分区（不画分区标题），
卷 / 章 / 节靠 `depth` 分两级，章节纯文本转 `<p>`。这三种格式不读分页，也就不吃版式参数。

## 5. 不做

- 分栏、页眉页脚、脚注、首字下沉 —— 版式只在导出器里给四套预设 + 几个参数，不做成编辑器排版器
- 字数统计看板、写作目标、番茄钟（这是另一个产品）
- 自动编号（不猜 `第NN章`）；手动顺序 = 目录里拖拽，落库为 `order`，文件名不动

## 6. 风险

| 风险 | 说明 |
|---|---|
| **fork 冲突** | 那个 fork 已经改过编辑器与大纲；合并前先出冲突地图（`git merge-tree`），别边合边改 |
| 长文性能 | 一章几千字没问题；但"全书搜索"要等索引（见 todo §9 Rust 化） |
| 与"库 = 一套设定集"的语义 | 一个库里同时有设定和小说，导图/关系图会把章节也当实体拉进来 → 需要"小说目录默认不进关系图、不进相册"的规则 |
| 备份体积 | 全书纯文本不大，但封面/插图会进 `.ocbak`，注意内联策略 |

## 7. 兼容 fork 版数据（PR #5）

那个 fork 的小说**自成一库**（IndexedDB `OCStudioNovels`，表 `novels`），和我们「章节 = 笔记」不是一套模型。用户可能已经在那边写了一堆章节，所以**第一版就要能读进来**。

### 7.1 它的数据长什么样

```ts
Novel {
  id?: number; title: string; author: string; synopsis: string
  coverUrl?: string; notes?: string; noteItems?: { id, text }[]
  targetWords?: number
  chapters: { id: string; title: string; content: string /* HTML */; summary?: string; status?: 'draft'|'revising'|'done' }[]
  createdAt: number; updatedAt: number
}
```

### 7.2 映射（单向，只读不写回）

| 它的 | 我们的 | 说明 |
|---|---|---|
| `Novel` 一条 | 顶层词条（`category: '小说'`） | 标题 = `title`；简介 → 正文第一段；作者 / 目标字数 → frontmatter 键 |
| `Novel.chapters[]` | 该词条的子节点（`parentId`） | 标题 = `chapter.title`；`order` = 数组下标（保留原顺序） |
| `chapter.content`（HTML） | 正文 doc | HTML → Tiptap 段落 + 粗体 / 斜体；其余标签降级成文本，**不丢内容** |
| `chapter.summary` / `status` | frontmatter `梗概` / `章节状态` | 原样保留，不做翻译 |
| `coverUrl` | 封面图字段 | 若指向 `blob:` 则跳过（跨库拿不到），记一条导入报告 |
| `notes` / `noteItems` | 根节点正文末尾的「备注」小节 | 不静默丢 |

### 7.3 三条硬规矩

1. **幂等**：导入完成在 `meta` 表打一个 `legacyNovelsImportedAt` 标记；再次打开只提示「已导入过」，不重复建节点
2. **不删源**：`OCStudioNovels` 一个字节都不动（用户可能还在用旧版），导入只是**读**
3. **可核对**：导入结束给一份报告（几本小说 / 几章 / 跳过的封面 / HTML 降级处数），写进 `.ocstudio/journal.jsonl` 让用户能回查

### 7.4 顺带预留的其它 fork 数据

同一套思路接到 W3 / W4：`db.maps` → 底图 + `map_position`，`db.relations` → 显式边。**兼容层是只读适配器，不是第二个真源**。
## 8. 编辑器选型（2026-11-03 定）

fork 的小说页**用的也是我们的内核**（`import { EditorCore } from '@/components/editor/EditorCore'`），只是 fork 了一份旧版内核并在外面套了小说壳。所以问题不是"选哪个编辑器"，而是"内核要哪一代"。

| 维度 | 我们的（0.19.2） | fork 那份（0.18.1） |
|---|---|---|
| 结构 | `EditorCore` 321 行 + 9 个专职模块（配置 / 右键 / 气泡 / 移动键盘 / 找替换 / 大纲） | `EditorCore` **单文件 1069 行** |
| 内链弹层 | `createWikiLinkExtension()` 每编辑器一份（0.19.2 修过卡左上角） | 模块级共享 popup，那个 bug 会复现 |
| 未保存判定 | `dirty.ts` 快照签名 + `doc.eq` + 忽略尾部空段落 | 无 |
| 图片引用 | `image-refs.ts` 唯一收集器 | 无 |
| 国籍镜像 | `membership.ts` | 无 |
| vault 往返 | Markdown 桥 + 外科式写回 | 章节存 HTML，离开 Tiptap 没有结构 |
| 移动端 | 键盘态 + 工具栏 + 选词工具条，分层 | 塞在 EditorCore 里自绘 |
| 找替换 / 大纲 | 有 | 无 |

**定论：内核用我们的，只取它的「小说壳」。**

- 取：章节列表与切章不丢稿（防抖 + 卸载 flush）、分页预览（`render.ts` + `background.ts`）、字数、Docx 导出
- 不取：它那份 `EditorCore`、`novelDb`、HTML 作为正文落库
## 9. 书架与封面（2026-11-03）

小说入口在侧边栏**「创作」组**（和「世界观」并列），点进去先是**书架**，再进某一章的编辑。

| 项 | 定法 |
|---|---|
| **封面比例** | **2:3**（书籍经典 6:9）。和角色卡 3:2、头像 1:1 一样是**槽位**，不是随意样式；将来接图片时裁剪比例写死 |
| 封面空态 | 衬线首字占位（不画虚线框、不写「暂无封面」） |
| 卡片 | `bg-paper-card` + `ROUND_ITEM`，hover 用 `--oc-hover`，**零阴影** |
| 卡片文案 | 书名 + 事实（`N 章 · X 字`）。**不写**副标题、不写「分章节写作 / 支持导出…」这类说明 |
| 网格 | `LIST_GRID`（2 / 3 / 4 / 5 列随宽度） |
| 新建 | 页头右侧 `BTN_PRIMARY`「新建小说」，不在空态里重复第二个入口 |
| 删除 | 卡片右上角 / 目录行右侧的删除（桌面 hover 显形，手机长按出动作表）；**连同全部章节**一起进回收站 |
| 进书 | 点卡片直接进第一章；书内左侧目录、右侧正文，返回用 `ArrowLeft` |
| 进出动画 | 书架 ↔ 目录复用角色 / 事件 / 国家那套 150ms 滑动（`SectionSwap` + `.section-fade` / `.section-stack`）：书架左滑出、目录右滑入，返回反向。分类条目编辑器同一套 |
| 作品信息 | 目录面板底部这一栏**默认展开**（作者 / 简介 / 封面是新书第一件要填的事，收起等于藏起来） |

**和 fork 版书架的差别**：fork 的卡片带「· OC Studio」署名、顶部有一句三行说明、封面是 1:1 灰块 —— 三条都不符合 `oc-studio-design` 的文案节制与槽位规范，已按上表重做。
## 10. 与 fork 的功能对齐（2026-11-03 盘点；2026-11-10 已全部补齐）

fork 的小说页比我们多一圈**作品级元信息**和**章节级备注**。逐项对账：

| fork 有的 | 我们 | 状态 |
|---|---|---|
| 作品名 | ✅ 根节点标题 | 保持 |
| 作者 / 简介 / 目标字数 | ✅ 根节点 `novelAuthor` / `novelDescription` / `novelTargetWords` | 已落（作品信息默认展开） |
| 封面 | ✅ `cover` 槽位（2:3） | 已落 |
| 作品笔记（noteItems 一条条） | ✅ 导入时并进正文 | 保持 |
| 章节标题 | ✅ | 保持 |
| **章节大纲 / 备注**（summary） | ✅ 章节 `chapterOutline` 文本域 | 已落 |
| 字数（章节 / 全书 / 目标进度） | ✅ 全书 + 章节字数 + 「/ 目标」进度 | 已落 |
| 预览 / 导出（9:16 · 16:9 · A4 分页） | ✅ 分页预览（`pagination.ts` + `layout.ts` + `background.ts`）+ Markdown / TXT / Word / 逐页 PNG | 已落 |
| 自动保存提示 | ✅（`dirty` + 落盘队列） | 保持 |

**仍然缺的**：把整棵树当大纲的面板（现在只有章节级大纲文本 + 编辑器里读 heading 的 `OutlinePanel`）、章节 `@角色` 反查、叙事时间与实际时间的错位 —— 见 `docs/todo.md` §7。

**已知交互坑（已修）**：`DocumentEditor` 的常驻工具条是 `sticky top-12`，放在小说页这种没有 48px 页头的容器里会浮在正文上、挡住输入行。
小说页因此**不挂常驻工具条**（`showToolbar={false}`），格式走气泡菜单与 `/` 命令。
