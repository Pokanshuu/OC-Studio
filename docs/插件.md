# 插件

> 远期方向。**v1 明确不做"用户自定义组件"**（见 `docs/模板.md` §12），插件是它的唯一通路——所以插件必须带沙箱，不能退化成"在模板里写 JS"。

---

## 0. 一句话

插件 = **被沙箱关起来的扩展**，通过白名单 API 读数据、出视图、加导出器；它碰不到 DOM、Dexie、Tauri。

---

## 0.1 两个官方插件（先做这两个，当作示例）

| 插件 | 做什么 | 为什么拿它当示例 |
|---|---|---|
| **地图生成器** | 读国家 / 词条 → 渲染 SVG/Canvas → 导出 PNG；地图本身也是一个**视图**，与实体联动（见 `docs/地图.md`） | 同时用到"读实体、渲染容器、导出图片"三种能力 |
| **Agent**（名字待定） | 内置 MCP + 一组 skill，和用户讨论设定、写小说、补全条目 | 用到"读写能力层 + 权限分级 + 长任务"，是插件的压力上限 |

两个官方插件**走和第三方完全相同的接口**——它们自己就是开发文档的活样本。给别人的开发文档**后期再补**，先有能跑的两个样本，文档从样本里长出来（避免写完就过时）。

---

## 0.2 Skill（Agent 的技能包）

Agent 不是"一个万能模型"，而是 **MCP 工具 + 一组 skill**：

- 内置几个官方 skill：`角色讨论`、`设定补全`、`小说续写`、`一致性检查`
- 用户可以**安装 skill**（跟插件同一种分发包，只是只含提示词与工具调用声明，不含可执行代码——所以它比插件更容易开放）
- skill 只能调用能力层暴露的工具，不能直接动数据；写入同样受权限四级约束

---

## 1. 能扩展什么

| 类型 | 例子 |
|---|---|
| 命令 | 「一键生成地图」「批量补全国籍」 |
| 面板 | 地图画布、族谱树、统计图 |
| 导出器 | 导出为某种格式（SVG / PNG / 自定义文本） |
| 数据变换 | 解析一段文本成一批词条（导入适配器） |
| **skill** | 一段可复用的提示词 + 工具组合（Agent 专用） |

---

## 2. 架构

```
插件包（zip）
├─ manifest.json   { id, name, version, apiVersion, permissions, entry }
├─ entry.js
└─ 资源
```

- **运行时**：`iframe`（桌面 / 移动都可用）或 Worker（纯计算）
- **通信**：宿主 RPC，插件只能调白名单方法
- **禁止**：直接访问 DOM / Dexie / Tauri / 网络（默认关）
- **显示**：宿主给一块容器，插件往里画；不能改宿主界面

---

## 3. 权限

| 权限 | 默认 |
|---|---|
| 读实体 / 集合 | 关（逐项授权） |
| 订阅数据变更 | 关 |
| 渲染容器 | 关 |
| 导出图片 / 文件 | 关 |
| 网络 | 关 |
| 读写自己的存储 | 开（插件级 `localStorage` 空间） |

用户逐项授权，授权记录可撤销；插件崩溃不能带崩宿主。

---

## 4. 分发

- 先只做**本地文件导入**（zip），社区市场后置
- 版本 / 禁用 / 卸载 / 日志四件事在 v1 就要有，否则装错一个就废

---

## 5. 前置与风险

**前置**：稳定的内部数据 API、导出管线、主题令牌。三者任意一个没定，插件 API 都要跟着改版本——所以插件必须排在模板 / 关系图 / 主题之后。

| 风险 | 说明 |
|---|---|
| **安全（最高）** | 没有安全评估前不开放写权限与网络 |
| API 稳定性 | 插件 API 一旦发布就有兼容负担，先定 `apiVersion` |
| 沙箱差异 | Tauri（WebView2）与 Capacitor（Android WebView）的 iframe 能力不同，移动端能力要单独评估 |
| 维护成本 | 社区插件的 issue 会算到项目头上，先想好"只支持内置 API"的态度 |
