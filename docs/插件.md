# 插件

> 远期方向。**v1 明确不做"用户自定义组件"**（见 `docs/模板.md` §12），插件是它的唯一通路——所以插件必须带沙箱，不能退化成"在模板里写 JS"。

---

## 0. 一句话

插件 = **被沙箱关起来的扩展**，通过白名单 API 读数据、出视图、加导出器；它碰不到 DOM、Dexie、Tauri。

---

## 0.0 三类插件（2026-11-05 定稿）

按「它能碰什么」分类，**共用一份 manifest**（`src/lib/plugins/types.ts`）：

| 类型 | 有什么 | 能做什么 | 默认权限 |
|---|---|---|---|
| **功能** `tool` | 自己的界面（宿主给一块容器） | 白名单 API、可能要数据权限、长任务 | 只看得到、只画得出 |
| **主题** `theme` | **只有数据**（令牌 / 背景 / 排版） | 换颜色，不换逻辑 | **无**（没有代码可执行） |
| **技能** `skill` | 提示词 + 工具声明 | 调助手能调的那几个工具 | 跟着助手走 |

判定口径：**能不能执行代码**。能 → 必须沙箱 + 逐项授权；不能（主题 / 技能）→ 只是数据，可以先开放。所以「第三方主题也是一种插件」成立，而且它是最容易开放的那一类。

界面落点（2026-11-05 已实装地基）：

- 侧栏新增「工具」分组，只列**可用且已启用**的功能插件；导航键 `工具:<插件 id>`，`ToolSection` 是插件视图的接线表
- 设置 › 插件：开关、权限逐项授权、版本 / 类型 / 可用状态；「添加插件」「市场」标开发中（不假装能用）
- 主题即插件：`lib/plugins/themes.ts` 把四套官方配色各登记成一个 `kind: 'theme'` 插件，个性化里的主题选项按插件开关过滤（**当前正在用的那套永远保留**，否则会出现「颜色没变但没选中项」）
- 地图生成器已是工具页：先选目标地图 → 参数 → 生成 → 用作底图（算法仍全在 `src/plugins/map-generator/`，宿主只接线）
- 助手（`official.agent`）：**整目录搬自 `D:\Codes\Simple-Agent`**，`src/plugins/agent/` + `src-tauri/src/agent/` 是**原样移植**，上游更新整目录覆盖。它是这个插件系统的一个现成样本 —— 证明「插件 = 自带存储与状态的独立单元」这条契约撑得住一整个 App：
  - **存储归插件**：系统 app data 下一只 SQLite（`rusqlite`），密钥走系统钥匙串。宿主不碰，也不该碰 —— 这就是 `own-storage` 那条默认权限的实际含义。**后果要记住**：`.ocbak` 备份带不上它，备份范围得另说
  - **网络归插件**：`reqwest` 在 Rust 侧流式，WebView 里没有 CORS 问题；换宿主的 `fetch` 反而会在 Capacitor 下退步
  - **样式归插件**：自带 2184 行 CSS，生成时用 `scripts/scope-plugin-css.mjs` 收进 `.oc-agent-root`（`globals.css` 里 `@import` 已收编的那两份）。**同一套 `--oc-*` 令牌、同一组色值**，所以观感本来就是通的，不需要换皮
  - **宿主只留一道缝**：`src/plugins/agent/AgentPlugin.tsx`（挂载点 + 亮暗同步 + 引导）。除了它，插件目录里一个字都不改
  - **内置助手暂不走 MCP**，进程内直接调 `lib/capabilities/`；MCP / REST 是把同一份工具定义再导出一次，不是另写一套

## 0.1 两个官方插件（先做这两个，当作示例）
| 插件 | 做什么 | 为什么拿它当示例 |
|---|---|---|
| **地图生成器** | 读参数与种子 → 生成图层 → 导出 PNG；地图本身是一个**视图**，与实体锚点联动（见 `docs/地图.md`） | 同时用到"渲染容器、导出图片、读参数"三种能力 |
| **Agent**（名字待定） | 内置 MCP + 一组 skill，和用户讨论设定、写小说、补全条目 | 用到"读写能力层 + 权限分级 + 长任务"，是插件的压力上限 |

### 0.1.1 地图生成器已按这个形状落地（2026-11-03）

**内置只保留地图视图，生成能力整体在插件里**——去掉插件，手绘底图 + 锚点 + 图层开关照样能用。

```
src/plugins/map-generator/      ← 插件（官方，entry: 'builtin'）
├─ manifest.ts                  id / name / version / apiVersion / permissions / entry
├─ index.ts                     ← **唯一对外边界**，内置侧只能从这里进
│   ├─ MAP_GENERATOR_MANIFEST
│   ├─ createMapGeneratorWorker()
│   ├─ generateWorld / renderView / buildMapVectors
│   └─ sampleProfile / generatePolitical / normalizeMapParams
├─ kernel/                      纯算法（noise / tectonics / terrain / climate / hydrology / biomes / vectors / render / mapwright）
├─ worker.ts                    Worker 壳（进度 / 生成 / 渲染）
├─ types.ts                    参数、视图枚举、Worker 线格式
└─ params.ts / political.ts / profile.ts / thumbnail.ts

src/features/map/              ← 内置视图（S3 落地）
├─ types.ts                     锚点（归一化 0–1）、图层、底图
└─ index.ts
```

**这个边界就是将来的沙箱线**：插件不碰 Dexie / localStorage / DOM / 用户文件，只接收参数、回图层与 PNG。所以真正搬进 iframe / Worker 沙箱时，`index.ts` 的签名不变，换的是宿主怎么加载它（`entry: 'builtin'` → `entry.js` + manifest 校验）。

权限按 §3 逐项声明，当前只给了三项：`read-params`、`render-canvas`、`export-image`——**没有数据读写权限**，也不需要：地图的锚点存在实体上，由宿主读写。

两个官方插件**走和第三方完全相同的接口**——它们自己就是开发文档的活样本。给别人的开发文档**后期再补**，先有能跑的两个样本，文档从样本里长出来（避免写完就过时）。

## 0.2 Skill（Agent 的技能包）

Agent 不是"一个万能模型"，而是 **MCP 工具 + 一组 skill**：

- 内置几个官方 skill：`角色讨论`、`设定补全`、`小说续写`、`一致性检查`
- 用户可以**安装 skill**（跟插件同一种分发包，只是只含提示词与工具调用声明，不含可执行代码——所以它比插件更容易开放）
- skill 只能调用能力层暴露的工具，不能直接动数据；写入同样受权限四级约束

---

## 1. 能扩展什么

| 类型 | 例子 |
|---|---|
| 命令 | 「一键生成地图」「批量补全国籍」 |
| 面板 | 地图画布、族谱树、统计图 |
| 导出器 | 导出为某种格式（SVG / PNG / 自定义文本） |
| 数据变换 | 解析一段文本成一批词条（导入适配器） |
| **skill** | 一段可复用的提示词 + 工具组合（Agent 专用） |

---

## 2. 架构

```
插件包（zip）
├─ manifest.json   { id, name, version, apiVersion, permissions, entry }
├─ entry.js
└─ 资源
```

- **运行时**：`iframe`（桌面 / 移动都可用）或 Worker（纯计算）
- **通信**：宿主 RPC，插件只能调白名单方法
- **禁止**：直接访问 DOM / Dexie / Tauri / 网络（默认关）
- **显示**：宿主给一块容器，插件往里画；不能改宿主界面

---

## 3. 权限

| 权限 | 默认 |
|---|---|
| 读实体 / 集合 | 关（逐项授权） |
| 订阅数据变更 | 关 |
| 渲染容器 | 关 |
| 导出图片 / 文件 | 关 |
| 网络 | 关 |
| 读写自己的存储 | 开（插件级 `localStorage` 空间） |

用户逐项授权，授权记录可撤销；插件崩溃不能带崩宿主。

---

## 4. 分发

- 先只做**本地文件导入**（zip），社区市场后置
- 版本 / 禁用 / 卸载 / 日志四件事在 v1 就要有，否则装错一个就废

---

## 5. 前置与风险

**前置**：稳定的内部数据 API、导出管线、主题令牌。三者任意一个没定，插件 API 都要跟着改版本——所以插件必须排在模板 / 关系图 / 主题之后。

| 风险 | 说明 |
|---|---|
| **安全（最高）** | 没有安全评估前不开放写权限与网络 |
| API 稳定性 | 插件 API 一旦发布就有兼容负担，先定 `apiVersion` |
| 沙箱差异 | Tauri（WebView2）与 Capacitor（Android WebView）的 iframe 能力不同，移动端能力要单独评估 |
| 维护成本 | 社区插件的 issue 会算到项目头上，先想好"只支持内置 API"的态度 |
