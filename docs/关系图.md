> 2026-10-30 定：**实时物理方向放弃**。打开就是上次的样子，位置由作者自己排。
> 关联文档：`docs/模板.md`（关系组件的表格 / 图切换、显式关系边）、`docs/时间线.md`。

---

## 0. 一句话

**图是作者排的版面，不是物理模拟的副产品。**

---

## 1. 为什么放弃实时物理

| | 实时物理 | 静态手摆 |
|---|---|---|
| 可复现 | 每次重算都不同 | 位置存在实体里，永远一致 |
| 导出 / 静态站 | 要另做一套"收敛态" | 直接就是收敛态 |
| 耗电 / 低端机 | 持续模拟 | 只在拖动时算 |
| 跨端 | 不可复现 | 跟着库走 |
| 移动端 | 拖不动 | 只读也成立 |

**一个例外**：初次布局仍然用 `computeForceLayout`（`features/relations/layout.ts`）算**一次**——但那是可被「整理」按钮重跑的一次性动作，不是持续模拟。

---

## 2. 已定

| 项 | 定法 |
|---|---|
| **边** | **正交**（`routeEdges` 四向落点）。不做曲线，不做样式开关 |
| 位置 | `graphPosition`（仓库写 frontmatter 的 `graph_position`），React Flow 画布绝对坐标，打开时 `fitView` 自适应 |
| 打开时 | **零动画**，静止呈现上次的位置 |
| 「整理」按钮 | 跑一次力导向 + 过渡动画，之后完全靠手摆 |
| 移动端 | **只读**：可缩放、可平移，不可拖动节点 |
| 结构变更 | 只能在图上**建边**（现有 `RelationCreateDialog`）；**不能在图上新建实体** |

## 4. 节点形态

| 类型 | 形态 | 尺寸 |
|---|---|---|
| 角色 | 圆形头像 + 名字 | 56px 圆 + `text-[12px]` |
| 国家 | 矩形卡（旗帜 / 封面）+ 名字 | 96 × 64 |
| 事件 | 矩形卡（封面 / 无图占位）+ 名字 | 96 × 64 |
| 词条 | 图标或小卡 | 96 × 64 |

- 选中：1px `var(--oc-ink)`；悬停：1px `var(--oc-line-hover)`
- 连线手柄：四向小圆点，**悬停才显形**（`NODE_HANDLE` 已有）
- 无图的卡：衬线首字占位（复用 `MEDIA_FALLBACK`）
- **节点尺寸写死，不随文字长度变**（见 §9 风险 2）

---

## 5. 画布

- 底：`bg-paper` + 点阵（`radial-gradient(var(--oc-line) 1px, transparent 1px)`，间距见 §3）
- **不画网格线**，点阵就够
- 缩放：`MIN_ZOOM`（0.6）为下限；`fitView` padding 0.2
- 平移：空白处拖动 / 空格拖动
- 小地图：后做，先不做

---

## 6. 手摆的工具（分期）

| 期 | 内容 |
|---|---|
| **一期**（demo 就带） | 「整理」按钮 + 撤销 |
| 二期 | 网格吸附（若验证有用）+ 对齐参考线 |
| 三期 | 框选多选 + 整体拖动 |
| 四期 | 编组框 + 锁定 |

**「整理」是这套方案的地基**：新建五个节点后总要先生成一版能看的布局，再手调。没有它，手摆就是体力活。

---

## 7. 导出

- 导出的就是收敛态：当前 `graphPosition` + 正交边
- 图片导出面板勾「关系图」即可（见组件化文档 §9.1）
- 静态站：同一份渲染输出，不另做一套

---

## 8. 不做

- 实时物理（持续模拟 / 每帧重算路由）
- 曲线边
- 每次打开重新布局
- 在图上新建实体
- 跨会话撤销（位置已落盘，撤销只在本次会话有意义）

---

## 9. 风险

1. **手摆的体力成本**：兜底是「整理」。如果用户抱怨"重排完还得再摆一遍"，说明力模型参数不对（向心引力 / 斥力 / 边长），**该调算法而不是加工具**。
2. **节点尺寸与窗口无关、但与字体有关**：节点尺寸写死，不要按文字自适应，否则不同字号下 `fitView` 出来的构图会变。
3. **并行边**：同一对节点的多条关系（兄弟 + 同事）必须错开，`routeEdges` 要支持并行偏移，否则两条正交线重合，看起来只有一条。
4. **位置坐标是 RF 空间**：窗口大小变化不影响，但**新增节点没有位置**时要有个默认落点规则（否则全叠在原点）。
