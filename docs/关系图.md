## 0. 一句话

**图是作者排的版面，不是物理模拟的副产品。**

### 0.1 现在的问题

| 问题 | 具体 |
|---|---|
| **不可复现** | 力导向每次重算位置，导出图片、静态站、换台机器都不是同一张图 |
| **节点同形** | 角色 / 国家 / 事件全是一种形态（图标 + 名字的小团），看不出类型 |
| **移动端不能拖** | 只能看，不能摆；而"手摆"正是这套方案的核心 |

## 1. 为什么放弃实时物理

| | 实时物理 | 静态手摆 |
|---|---|---|
| 可复现 | 每次重算都不同 | 位置存在实体里，永远一致 |
| 导出 / 静态站 | 要另做一套"收敛态" | 直接就是收敛态 |
| 耗电 / 低端机 | 持续模拟 | 只在拖动时算 |
| 跨端 | 不可复现 | 跟着库走 |
| 移动端 | 拖不动 | 只读也成立 |

**一个例外**：初次布局仍然用 `computeForceLayout`（`features/relations/layout.ts`）算**一次**——但那是可被「整理」按钮重跑的一次性动作，不是持续模拟。

## 2. 已定

| 项 | 定法 |
|---|---|
| **边** | 两种线型**可切换**：**正交**（默认，`routeEdges` 四向落点）/ **曲线**（自动浮动贝塞尔，从节点边缘发散）。线型是**展示偏好**，存应用设置 `edgeStyle`，不落实体 |
| **边名** | 默认**不画**（一屏几十条时全是标签）；悬停节点显示与它相邻的边名，悬停单条线或打开这条线的样式面板显示那一条。导出图仍保留全部名字（不设 `showLabel` 的消费方按显示处理） |
| **边色** | **12 档预设**（`--oc-accent-1..12`，见 `src/lib/relation-colors.ts`），**关系名与线条同色**；没选色 = 中性线色 `var(--oc-line-hover)`。色板只有预设，不给取色器；线型不换色，换色不改线型 |
| **箭头** | 边的**数据**，四档 **无 / 正向 / 反向 / 双向**，与颜色一起落 `关系:` 数组 |
| 位置 | `graphPosition`（仓库写 frontmatter 的 `graph_position`），React Flow 画布绝对坐标，打开时 `fitView` 自适应 |
| 打开时 | **零动画**，静止呈现上次的位置 |
| 「整理」按钮 | 跑一次力导向 + 过渡动画，之后完全靠手摆 |
| 移动端 | **只读**：可缩放、可平移，不可拖动节点 |
| 结构变更 | 图上能**建边**（拖拽连线 / `RelationCreateDialog`）与**新建节点**（角色 / 国家 / 事件，见 §10.5）；分类条目不在图上新建（它得先有分类与模板） |
| **边的方向** | 角色 ↔ 角色默认**双向**（见 §2.1）；箭头方向按边可选 **无 / 正向 / 反向 / 双向**，与边名一起落 frontmatter；角色 ↔ 国家是归属、事件 ↔ 角色是参与，这两类**默认无箭头** |

### 2.1 角色之间是双向关系

- **一对角色一条边：一个名字、一个颜色、一个箭头方向**
- 默认 **双向**（`both`）+ 中性线色：关系本来就是对等的，"谁是发起方"只是存储细节。需要单向时（师父 / 徒弟、谁单方面效忠谁）在边上显式选 `正向` / `反向`，**不是靠加第二条边**
- 颜色是**阅读辅助**，不是语义：同一条边的文字永远跟着线色走，不需要另设图例。色板 12 档在亮暗两套下都 ≥ 4.5:1（`globals.css` 的 `--oc-accent-*`）
- **落盘形状**：`relations: [{ name, relation, color?, arrow? }]`（与 `docs/模板.md` §6.3 一致）。`color` / `arrow` 都可选；**不写 `arrow` = 角色边默认双向**，要显式去掉箭头必须写 `arrow: none`（否则与「没设」分不开）。编辑器关系格里的箭头小钮与图上的样式面板写的是同一个值
- **只存发起方那一侧**，另一边是查出来的（见 `docs/模板.md` §1.4）。所以在 A 上加了 B，B 的关系表里立刻有 A；删掉、改名同样同步——因为那本来是同一条数据
- **笔记之间也有同形状的命名边**：`WorldEntry.relations`，图上是实线 `relation`（不是虚线 `reference`）。引用仍是正文推出来的，只读；命名边是用户手写的，可以改名 / 配色 / 删
- 不对称称呼（师父 / 徒弟两个名字）**不做**：一条边只有一个名字、一个方向；真需要两个名字就建两条边（§9 并行边错开）

|---|---|---|
| 角色 | 圆形头像 + 名字 | 56px 圆 + `text-[12px]` |

## 5. 画布

- 底：`bg-paper` + 点阵（`radial-gradient(var(--oc-line) 1px, transparent 1px)`，间距见 §3）
- **不画网格线**，点阵就够
- 缩放：`MIN_ZOOM` **0.2**（全景要能整图入画）；低于 `LABEL_ZOOM`（**0.7**）时节点名整批淡出 —— 0.6 倍下一屏几十个名字只会糊成一片，那时留图形比留字有用。两个阈值都在 `relation-graph-utils.ts`
- `fitView` padding 0.2；「全景」按钮与初始 `fitView` 共用同一个 `minZoom`
- 节点名有**两层纸色光晕**（`globals.css` 的 `.graph-node-label`）：压在别人的卡片和线上也能读
- 平移：空白处拖动 / 空格拖动
- 小地图：**默认开**，`160×110`、可拖可点、视口框可见；开关在左下「显示」面板里，窄屏不显示（右下要留给缩放条）

## 6. 手摆的工具（分期）

| 期 | 内容 |
|---|---|
| **一期**（已完成） | 「重排全部」（在右上 ⋯ 里，带撤销）+ 8px 吸附 + 对齐参考线 + 框选多选 |
| 二期 | 框选后整体拖动 / 对齐 / 均匀分布 |
| 三期 | 编组框 + 锁定 |

**「重排全部」是这套方案的地基**：新建五个节点后总要先生成一版能看的布局，再手调。没有它，手摆就是体力活。

**它不在工具栏一级位置**（2026-11-06）：一次就覆盖全部手摆位置，撤销提示只有几秒，位置却已经写盘 —— 放进 `⋯` 后要多一次点击，够挡住手滑。日常的「自动动作」只剩「新节点落在视口中心」这一条（§10.5），它不覆盖任何已有位置。

### 6.1 与 fork 那套「自动整理 + 布局保存 + 框选」怎么合

那一套（PR #5）和我们不是两条路线，是**同一套排版工具的不同零件**——他们强在"一键能看"，我们强在"排完可复现"。合起来的分工：

| 能力 | 谁的做法 | 合成后 |
|---|---|---|
| 一键成版面 | 他们的「自动整理」：跑一次力导向 + 避让，修好排成一圈 / 头像重叠 | **取他们的**：`computeForceLayout` + 碰撞检测跑一次，落到 `graphPosition` |
| 保存 | 他们：拖动自动保存 + 手动保存按钮 | **取自动保存**（位置本来就随库走，`graphPosition` 落 frontmatter）；「手动保存」降级为状态提示，不做第二个真源 |
| 多选 | 他们：框选 + 鼠标模式（右键平移 / 左键平移+Shift 框选） | **取他们的**，提前到一期 |
| 多选后怎么摆 | 我们：手摆 + 吸附 | 框选后可**整体拖动 / 对齐 / 均匀分布**，再靠吸附微调 |
| 撤销 | 我们：整理可撤销 | 位置改动（拖动 / 整理 / 对齐 / 分布）进**会话内撤销栈**；跨会话不做（位置已落盘） |
| 吸附与参考线 | 我们：待 demo 验证参数 | 自动整理之后用它们做精修 |

一句话：**自动整理负责「从无到有」，手摆 + 吸附负责「从有到好」，框选负责「批量」**。三者共用同一份 `graphPosition`，不加第二套坐标。

顺带定死两条：**任何自动动作都不得覆盖已有位置**（只在动过的节点或整图整理时生效），**布局不进 `.ocbak` 之外的地方**（不写 localStorage、不写应用设置）。

## 7. 导出

- 导出的就是收敛态：当前 `graphPosition` + 当前边型（正交 / 曲线）
- 图片导出面板勾「关系图」即可（见组件化文档 §9.1）
- 静态站：同一份渲染输出，不另做一套

## 8. 不做

- 实时物理（持续模拟 / 每帧重算路由）
- 线型自由配置（只给「正交 / 曲线」两档）
- 任意取色：只给 **12 档预设**（`--oc-accent-1..12`），不开放取色器
- 手拖曲线控制点（曲线模式先自动分离；控制点列为 P3，见 `docs/todo.md` §3）
- 每次打开重新布局
- 在图上新建**分类条目**（它需要分类 + 模板，得在分类页里建；角色 / 国家 / 事件可以在图上新建，见 §10.5）
- 跨会话撤销（位置已落盘，撤销只在本次会话有意义）

## 9. 风险

1. **手摆的体力成本**：兜底是「整理」。如果用户抱怨"重排完还得再摆一遍"，说明力模型参数不对（向心引力 / 斥力 / 边长），**该调算法而不是加工具**。
2. **节点尺寸与窗口无关、但与字体有关**：节点尺寸写死，不要按文字自适应，否则不同字号下 `fitView` 出来的构图会变。
3. **并行边**：同一对节点的多条关系（兄弟 + 同事）必须错开——正交模式靠并行偏移，曲线模式靠曲率分离；否则两条线重合，看起来只有一条。
4. **位置坐标是 RF 空间**：窗口大小变化不影响，但**新增节点没有位置**时要有个默认落点规则（否则全叠在原点）。

## 10. 界面（2026-11-06 改版）

原本是「一条栏里挤六件事 + 两个角被静态盒子占着」（六件 = 筛选 / 缩放 / 线型 / 整理 / 保存 / 导出），
和地图改版前是同一个病。现在按**四个角各管一件事**排，底部不再有第二条栏。

### 10.1 四个角

| 角 | 放什么 | 文件 |
|---|---|---|
| **左上** | 身份（`关系图谱 · 42 节点 · 67 关系`）+ **定位**（🔍 或 ⌘F/Ctrl+F，点开就地变输入框） | `RelationTopBar` |
| **右上** | `＋ 新建` + `⋯`（重排全部 / 刷新 / 导出 PNG） | `RelationToolsBar` |
| **左下** | **一条控制条**：`显示 ▾` + 四类 chip（角色 / 事件 / 国家 / 分类） | `RelationControlBar` |
| **右下** | 视口：`− 85% +` + 全景 | `RelationZoomBar` |

- **图例只在「显示」面板里**（和地图同规矩）：图例行同时就是开关，带篇数。面板里还有孤立节点 / 显示关系名 / 线型 / 小地图。
- 浮条皮肤一律 `FLOAT_BAR` / `FLOAT_BAR_ICON` / `FLOAT_BAR_TEXT`（`lib/ui-tokens`），不再就地拼。
- 窄屏：左上的身份条整条隐藏，左下只留 `显示 ▾`（四个 chip 收进面板），右下缩放条保留。
- **「保存布局」删掉了**：拖动结束就逐点写盘，那个按钮只是把同样的坐标再写一遍（§6.1 早就定了「手动保存降级为状态提示」）。

### 10.2 单击选中，双击打开

| 操作 | 桌面 | 移动端 |
|---|---|---|
| 单击节点 | **选中**（不跳走） | **打开**条目 |
| 双击节点 | 打开条目 | —— |
| 选中后右上角圆钮 | 打开条目（给不想双击的人） | —— |
| 点空白 | 取消选中 | 取消选中 |

- 选中与悬停共用一套高亮：**节点 + 它连的线一起亮，其余压暗到 0.25** —— 只看点不连线，看不出谁连谁。
- 选中态是 React Flow 自己的 `selected`（框选天然复用），没有第二份 `selectedNodeId`。
- 双击打开，所以 `zoomOnDoubleClick` 关掉，免得双击顺手把画布放大一次。

### 10.3 定位与聚焦

- **定位**（左上 / ⌘F）：只查**图里已有的节点**，不查全库（那是顶栏 ⌘K 的活）。结果 6 条，↑↓ 选、回车跳。
  跳之前会自动做三件事：打开被筛掉的那一类、退出聚焦、放行孤立节点 —— 否则「定位到一个不在画布上的节点」。
- **聚焦**（右键节点 →「只看它的关系」）：只留这个节点 + 一跳邻居，左上变成 `← 全部 | 先总理`。
  和「选中」的区别是**持久**：选中是看一眼邻居，聚焦是把画布收窄到这一撮。

### 10.4 线的分级

不新增视觉语汇，只改**权重**（判据是 `GraphEdgeKind`，只影响画法，不改数据）：

| 类别 | 例子 | 画法 |
|---|---|---|
| `relation` | 角色↔角色的「师徒」、事件↔事件的「前因」、笔记↔笔记的命名边 | 实线 1.4 / 不透明度 0.85，可改名、可配色、可加箭头 |
| `member` | 属于 / 参与 / 发生于 | 细实线 1.0 / 0.6，名字由字段决定（**不能改名**），只能删 |
| `reference` | 分类条目 @ 出来的「引用」 | **虚线** 2 3 / 0.45 —— 它是机器推的，不是人手画的；不配不删 |

### 10.5 节点动作

- **右键菜单**：打开 / 只看它的关系 / 更换图片 / 删除。
- **删除节点**：走各 feature 的 `delete*`（软删除 + 清引用 + 操作日志），二次确认后进回收站。
- **删除关系**：点线 → 面板底部「删除这条关系」→ 确认。只动真源那一侧的字段（`relatedCharacters` / `relations` / `countryId` / `events.characters|countries` / `worldEntries.relations`）；`world` 参与的「引用」不给删（删线不等于删正文里的引用），但笔记之间的命名边可以删。
- **改关系名**：同一个面板的顶部输入框，回车 / 失焦落库（`updateEdgeStyle` 的 `relation` 补丁）。
- **新建节点**：右上 `＋ 新建` → 角色 / 国家 / 事件；建完**落在当前视口中心**（`screenToFlowPosition`），
  不再交给力导向 —— 没坐标的节点会被排到已钉住节点的质心周围（半径 `max(220, n×16)`），几十个节点时那圈在屏幕外。
- **拖动中**：名字跟着指针走（浮尘），缩很小的时候也看得清在拖谁。

### 10.6 与 fork（`oc_editor`）功能对齐的取舍

| fork 有 | 这里 |
|---|---|
| 删除节点 / 删除关系 / 改关系名 / 只看内部关系 / 更换图片 | **对齐**（走我们的软删除与"关系只存真源一侧"） |
| 自动整理（网格避让） | **用我们的力导向**（`computeForceLayout`），但降级进 ⋯ |
| 保存布局按钮 | **不做**（拖动即保存） |
| 手动「添加关系」的双下拉 | **不做**：拖拽连线 + 定位已经覆盖这条路，几十个条目下两个原生 select 不可用 |
| SVG / PDF 导出 + 导出对话框 | **未做**：关系图整图导出还没接导出中心（`docs/主题.md` §5） |
| 自定义分类 hub 节点 / scoped edges / localStorage 布局 / zustand 可见性 | **不做**：我们的分类条目就是 `worldEntries`，坐标在实体上，没有第二套边表与第二份坐标 |

> 显示开关（四类 / 孤立节点 / 关系名 / 小地图）**不落盘**：与地图的图层开关同一口径，重开回到默认。
