# 迁移计划：单真源（文件夹）

> 状态：**P0 已落地**（引导页、删内置模式入口、术语、Mock 标）。
> 备份格式**只有 `.ocbak`**，不改名、不加第二套格式；新旧差异由文件里的 `version` 字段在后端判断。
> 已取消的方案：`.ocpack` 单文件包（见 §9）。

---

## 1. 术语定稿

| 场景 | 用词 | 例子 |
|---|---|---|
| 用户心智里「我的这个世界观 / 这套设定」 | **笔记库** | 「请选择你的笔记库位置」「笔记库加载失败」 |
| 需要用户去操作系统对话框的地方 | **本地文件夹** | 「打开本地文件夹…」「新建本地文件夹…」 |
| 代码 / 文档内部 | **vault** | `lib/vault/*`、`vaultFs` |

原则：跟用户对话叫「笔记库」，让用户点系统对话框叫「文件夹」。**不新增别名**（别再造“仓库”“资料库”这种第三个词）。

---

## 2. 目标架构

```
文件夹（唯一真源：Markdown + frontmatter + 附件）
   │  打开时整库读入
   ▼
Dexie（本次会话的工作缓存：索引、事务、关系图、时间线）
   │  防抖写回（只写改动过的那几篇）
   ▼
文件夹
```

- **没有第二套真源**：Dexie 退出即散，丢了重扫一遍就回来。
- 由此消失的：`关闭仓库` 之后的「幽灵编辑」、两套数据的选择题、同步冲突的解释成本。
- 仍然保留（无法消除）的成本：写回要「增量 + 不覆盖外部改动」（`serialize.ts` + mtime 乐观锁），这是文件夹真源固有的。

## 3. 备份与版本

**只有一个格式**：`.ocbak`（JSON，图片内联为 data URI），菜单/设置里统一叫「完整备份（.ocbak）」。原来的「JSON（不含图片）」已于 2026-10 删除，`exportAllData` 退回为完整备份的内部第一步。

- 备份内容带 `version` 字段（当前 `1`），`validateImportData` 是**唯一的版本判断点**：读不出来就明确报「不支持的版本：X」。
- 将来的格式变更**只动这个字段**：后端识别 `version` 决定怎么读，**不新增扩展名、不改菜单名**。
- 导出前先 `drainVaultWrites()`：包里的内容必须是「磁盘上真实的文件」对应的数据，不是队列里还没落盘的中间态。
- 桌面版导出走「系统保存对话框 → Rust `save_text`」（`src-tauri/src/files.rs`）。WebView2 里 `<a download>` 不可靠，旧的导出在桌面版是**静默失败**的。

## 4. 老数据迁移（应用内还有旧数据、没绑定文件夹）

启动闸门底部只有一个入口：**导入旧版本数据**（下拉两项）。

| 下拉项 | 行为 |
|---|---|
| （主按钮）导入旧版本数据 | 选一个文件夹 → 全量物化进去 → 自动打开 |
| 导入旧版本备份… | 选 `.ocbak` → 选合并策略 → 导入 Dexie → **紧接着走同一套落地流程** |

**目标文件夹可以已有笔记。** 合并策略不是只在 Dexie 里生效，它原样落到文件夹里的同名笔记上：

| 策略 | 文件夹里的同名笔记 |
|---|---|
| 跳过重复 | 原样不动，只补新条目 |
| 覆盖重复 | 就地更新（外科式改写：只动我们拥有的键与正文，用户自造的键与注释保留） |
| 保留两者 | 另起一篇 `名字 (2).md` |
| 清空并导入 | 先把已有笔记整批**挪进** `.ocstudio/trash/`，再整套写入 |

**永远不删文件**：最狠的「清空并导入」也只是移动。落地**不给策略默认值** —— 主按钮选到已有笔记的文件夹会先弹同一套选项再写；空文件夹没得合并，直接写。

只在 Dexie 里「导入成功」是不算数的：下一次打开文件夹时 `loadVault` 会整库替换 Dexie，没落地的数据当场散掉 —— 所以导入完一定接着落地。

**迁移前不强制导 `.ocbak`**：点按钮却弹出保存对话框，是在做另一件事；而且不需要那层保险 —— 清空 Dexie 发生在**写盘成功之后**，写盘失败就直接抛错停在那里，旧数据一个字节都没动。

落地（`src/lib/vault/export-dir.ts` 的 `exportLegacyToFolder`）做什么：

1. 读全量 Dexie（角色 / 国家 / 事件 / 词条 / 时期 / 标签 / 项目元信息）
2. 扫一遍目标文件夹，知道哪些笔记已经存在（同名判定按文件名，不看目录）
3. 按策略处理旧笔记（跳过 / 就地更新 / 另起一篇 / 整批挪进回收站）
4. 图片：`data:` URI 解码成字节、`images/…` 从应用数据目录复制、绝对路径直接复制 → 一律落进 `附件/`，实体引用改写成 vault 相对路径
5. 每篇笔记用**同一套** `serializeEntity` + `serializeBody` 写全量，路径一律走 `allocateRelPath`；就地更新的那几篇以原文件为底稿做外科式替换
6. 回收站条目写进 `.ocstudio/trash/`（扫描层跳过这个目录，不会在应用里复活，但字节留着）
7. 写 `oc-studio.json`（世界名 / 一句话 / 封面）、`.ocstudio/tags.json`（标签颜色）、`.ocstudio/fields.json`（字段表）
8. 写完直接按「打开文件夹」载入 —— id 由扫描重新分配，mtime 基线天然是新的
9. 报告：新建 / 更新 / 跳过同名 / 挪进回收站 / 图片 / 找不到原件的图片

为了「无损」，vault 侧这几处也补齐了（否则迁过去就是丢数据）：

- **时期**：`时期/xxx.md` 现在能被扫描层读回来（`dataset.periods` 以前是硬编码空数组）
- **简介 / 概要 / 事件关联 / 旧版人生故事**：`bio`、`summary`、事件的 `relations`、`lifeStory` 现在都在词汇表里有键链，读写成对
- **自增主键**：落盘中间件原来只从 request 取主键，不带 id 的 `add` / `bulkAdd` 的主键只有 response 里才有 → 新建实体、「保留两者」导入的行**只在 Dexie 里活着**。现在两处都看
- **多行值**：`emitScalar` 遇到含换行的字符串会写成裸标量，YAML 读回来会被折行。现在强制走双引号转义

自检：`npx tsx scripts/vault-migrate-check.ts`（内存闭环 31 项断言：造一份旧库 → 物化 → 扫描读回 → 逐字段比对）。

## 9. 已取消：`.ocpack` 单文件包

一度实现的方案：`.ocpack` = 改了后缀的 zip，备份出单文件、导入解包落地成文件夹（含 zip 炸弹/软链接/保留名的安全边界与 8 个单测）。

**取消原因（用户拍板）**：备份格式沿用旧的 `.ocbak`，不新增第二套格式；**新旧版本交给后端按文件里的 `version` 判断**，不在界面层用扩展名分流。

已回退的部分：`src-tauri/src/ocpack.rs`、`src/lib/vault/ocpack.ts`、菜单项、导入分支、`zip` 依赖。
保留的部分：`src-tauri/src/files.rs` 的 `save_text`（修的是「桌面版导出静默失败」这个真 bug，与本方案无关）。
