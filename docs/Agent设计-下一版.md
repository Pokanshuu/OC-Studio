# 助手（内置 Agent）设计 —— 下一版

> 2026-11-10 记。起因：同一天里助手连出两次事故 —— 新建条目全落到 `.ocstudio/`、以及凭空给国家和事件编出父子层级。
> 前者是写入路径的 bug（已修），后者是**设计问题**：工具面、文档面、验证面三张皮各说各话，模型只能在矛盾里做推断。
> 能力层本身（`Caller` / 权限 / 落盘链路）见 `docs/Agent接入.md`，本文只谈「怎么让这个 agent 少走弯路、少烧 token」。

---

## 1. 为什么现在这样不行

### 1.1 两次事故其实是同一个问题

**事故 A：文件落点。** 某类型条目全删进回收站后再新建，文件写进 `.ocstudio/`。助手查了三处（`library_list` / 磁盘 / `journal`），三处的答案互相矛盾，它花了 6 步才拼出真相，最后用 Python `shutil.move` 绕过。

**事故 B：层级。** 字段表里写着 `country.parentId` 与 `event.parentEventId`，助手据此建层级：

- 写 `parentId: 2` 到 frontmatter —— **键名就错了**，盘上是 `parent`（别名 `上级` / `所属`），扫描根本不认；
- 用 `library_read` 验证 —— 不显示父级；
- 用 `library_graph` 验证 —— 不遍历国家的父级；
- 用 `journal` 验证 —— `keys` 里确实有 `parent`，但那是 `undefined` 的清理被记成了「改动过」。

于是它得出「国家层级是我编的」。**这个结论也是错的**：国家层级是真的（表格页行内「新增子项」建下级国家、删除时子项提到父级、`buildCountryTree` 按 `parentId` 建树），只是**三条验证路径全是盲的**。而事件的 `parentEventId` 才是真的死列（`tree-table-rows.ts` 明写「事件没有层级」）。

结论：模型不是不知道，是**我们的工具面没给它看得见的证据**。

### 1.2 实测账单（每次 AGENT 请求的固定前缀）

| 项 | 字符 | tokens |
|---|---|---|
| 26 个工具 schema | 18,970 | **4,758** |
| 字段表 `LIBRARY_MODEL_MARKDOWN` | 3,527 | **1,188** |
| `agentInstructions`（coding agent 人格） | 1,174 | 295 |
| 环境 + 库目录 + 动作清单 | — | ~700 |
| **合计** | | **≈ 7k** |

但这 7k 不是主要开销。真正的钱花在**步数**上：一次字段猜错 = 试写 → 三种验证 → 改 → 再验证，5–8 步，每一步都要重放 7k + 历史 + 工具输出。**少 3 步比省 1k prompt 值钱得多。**

### 1.3 结论：「贵」和「蠢」是同一件事

模型花在「确认自己没做错」上的 token，比花在「做」上的多。要同时解决，得让**工具自己会说话**：读的时候告诉你可写什么，写的时候给你回执，错的时候告诉你下一步。

## 2. 六条不变式

1. **一个抽象：实体，不是文件。**
   模型能碰的只有实体与字段；`.md`、frontmatter 键名、journal 都是实现细节。凡是要求模型「知道文件长什么样」的设计，最后都会变成手写 YAML（`parentId` / `parent` 就是活例）。

2. **能力面 = 工具面。**
   字段表里出现的每一列，必须能被某个工具**读**、被某个工具**写**，或明确标注「界面维护，工具不碰」。做不到就不进表。这一条要进 CI（见 §8）。

3. **写有回执，读有脚注。**
   回执 = 落盘路径 + 实际改动的键 + 版本 hash；读脚注 = 这条现在能写哪些键、哪些键工具不写。加起来不到 80 tokens，能替掉 3–5 步自我验证。

4. **渐进披露，不预载全图。**
   上下文分三层：静态（人格 + 工具 + 能力卡片）、半静态（库目录）、动态（焦点 + 历史 + 工具结果）。某类实体的字段说明**在第一次碰到它时随工具结果返回**，而不是开局倒进系统提示。

5. **错误即下一步。**
   报错必须能直接照着做，并且区分「不存在 / 工具不写 / 需要新建」。现在那句「要新建就 `create_new: true`」是在教模型写脏字段。

6. **有尺子。**
   golden tasks + 每次请求的 token / 步数埋点。没有度量，所有优化都是玄学。

## 3. 目标架构

```
聊天 UI
  └─ 会话编排 loop ── 守卫（重复调用 / 步数 / 预算）
        ├─ 上下文装配：静态 │ 半静态 │ 动态        ← 前缀缓存友好
        ├─ 工具注册表（10–12 个动词）
        └─ 能力层（权限 · 校验 · actor）
              └─ 实体 / 落盘 / 时间线（回执来源）
```

编排与领域知识分离：**loop 只管「调工具、读回执、什么时候停」**；领域知识沉到工具描述与回执里，不进人格、不进长文档。

## 4. 工具面

### 4.1 收敛到 10–12 个动词

按「用户想干的事」切，不按「表里有什么列」切。

| 动词 | 职责 | 备注 |
|---|---|---|
| `library_search` | 标题 / 别名 / 标签 / 正文 | 结果里带「疑似重复」 |
| `library_read` | 条目 + 关系（含父级）+ **可写脚注** | 正文默认截 4k，`include_body` 才给全 |
| `library_catalog` | 模板 / 分类 / 字段组 | 按需调用，不预载 |
| `library_history` | 某条最近的改动（actor / keys / 时间） | 替代 grep `journal.jsonl` |
| `library_create` | 建条目，返回 id + 路径 + 回执 | 同名直接返回既有 id |
| `library_update` | 字段 / 标签 / 归类 / 父级 | 一个入口，内部按白名单分流 |
| `library_body` | 正文 | 长文本，单独审批与 diff |
| `library_link` | 关系边，只写发起方 | 幂等 |
| `library_media` | 图片槽位（url 下载 / 路径引用） | |
| `library_delete` | 软删除 | |

### 4.2 回执格式

```
已写入 国家/灰烬自治领.md
改动：description, header
版本：9f2c1a…（上一版 3a1d07…）
```

模型看到这三行就不需要再读一遍文件、更不需要翻 journal。

### 4.3 错误三分类

| 码 | 含义 | 回给模型的话 |
|---|---|---|
| `unknown-field` | 实体根本没有这个字段 | 列出这一类的可写字段 |
| `ui-only` | 字段存在，但工具不写（如 `parentId`） | 说明它由界面哪一处维护，工具不碰 |
| `new-field` | 自建字段不存在 | 才提示 `create_new`，并说明会写进 `custom` |
| `duplicate` | 同名条目已存在 | 返回既有 id，别新建 |
| `invalid-value` | 值本身不合法（如时间列写「霜月三日」） | 给出合法形态与替代去处 |
| `conflict` | 磁盘被外部改过 | 给「用磁盘版本 / 覆盖」两个选项 |

### 4.4 不提供的工具

- **`run_shell` 默认不下发**：它是「雷霆大思考」的主要来源（grep 源码、翻 journal、跑构建），也是安全口子。2026-11-14 已实装：默认工具面移除，真要用在「助手 › 设置 › 高级工具」里显式打开（需确认）；执行端 + Rust 各拦一次。
- **禁止直接写实体 `.md`**：`write_file` / `edit_file` 命中实体文件时拦下并提示改用 `library_*`。文件是派生结果，手改会绕过日志、索引与时间线 —— 事故 B 就是这么来的。非实体文件（附件 / 导出）在显式授权后才放行。

## 5. 上下文工程

### 5.1 三层 + 缓存

| 层 | 内容 | 变化频率 | 位置 |
|---|---|---|---|
| 静态 | 人格、工具 schema、能力卡片 | 版本级 | 最前 |
| 半静态 | 库目录（分类 / 模板 / 字段组 / 标签） | 库结构变化时 | 中间 |
| 动态 | 日期、本次焦点、会话资料、历史 | 每次 | 最后 |

顺序固定、内容字节稳定，前缀缓存才吃得满（DeepSeek / OpenAI 均按前缀命中计价）。

### 5.2 能力卡片（替代类型转储）

每类一段，约 40 tokens：

> **国家**：可写 `description / system / geography / culture`；图片 `flag`（旗帜）/ `header`（横幅）；层级 `parentId` **只能从「表格 › 新增子项」建，工具不读也不写**；标签用 `library_set_tags`。

关键是「工具不写」四个字 —— 它同时省 token 和消灭一整类错误。

### 5.3 示例

系统提示里放 2–3 段完整的正确调用序列（建条目 → 写正文 → 建关系），比把 schema 写全更能提高小模型的一次成功率。示例只写「怎么调」，不复述字段表。

### 5.4 工具结果预算

工具输出在循环里会被反复回放，这里是复利。

| 工具 | 预算 |
|---|---|
| `read_file` | 8k 字符 + `offset` 续读 |
| `run_shell` | 头 2k + 尾 2k（构建日志的结论在尾部） |
| `grep` | 30 命中 |
| `library_read` | 正文 4k，`include_body` 才给全文 |
| `library_search` | 20 条摘要 |

## 6. 循环与验证

- **回执代替自证**：写完不需要再读，回执就是读。
- **幂等与冲突**：同名创建返回既有 id；父级不合法返回候选；磁盘冲突给两个选项。
- **循环守卫**：连续 3 次只读不写 → 注入「信息够了，开始动手」；同一个失败调用重复 2 次 → 中止并汇报。
- **步数上限**：默认 12，可配；到顶先给用户看进度，而不是硬截断。
- **thinking 分档**：简单 CRUD 走 `off` / `low`，规划类任务才 `high`。这一条对「像在雷霆大思考」的观感影响最大。

## 7. 评估与观测

**golden tasks（20 条）**：建国家并挂到某联邦下、给角色加关系、改正文、换分类、重命名、删进回收站、要求一个不存在的字段（应被优雅拒绝）…

断言四件事：

1. 最终 DB 状态正确；
2. 步数不超过上限；
3. 每任务 token 不超过预算；
4. **没有脏字段**（不得写入 `parentId` 这类键）。

**埋点**：每次请求记一行 —— prompt / completion tokens、工具调用序列、步数、失败原因。先接 `stream_options.include_usage`，否则连真实开销都不知道（也顺手修好上下文百分比）。

**指标**：一次成功率、中位步数、每任务 token、脏字段数（目标恒为 0）。

## 附：这次查到的事实（避免下次再猜）

- **国家有层级**：`TreeTable.tsx` 行内「新增子项」→ `createCountry({ parentId })`；删除时子项提到父级；`buildCountryTree` 按 `parentId` 建树（悬空 / 自指 / 成环的父级当根）。编辑器里没有入口，只有表格页能建。
- **事件没有层级**：`tree-table-rows.ts` 写明「事件没有层级」；`parentEventId` 只存在于类型、序列化、扫描里，没有任何界面能建 —— **死列**。
- **TS 字段名 ≠ 盘上键名**：国家 `parentId` 落盘是 `parent`（别名 `上级` / `所属`）；`headerUrl` 落盘是 `header`；词条 `cover` 落盘是 `cover`。手写 frontmatter 必错。
- **journal 的 `keys` 有噪音**：`put()` 会把「删除该键」记成 `undefined`，而 `changedKeys` 直接 `Object.keys(updates)`，于是新建时的空 `parent` 也进了 keys。
- **journal 不存全文**：只存 `hash` / `prevHash` / `keys`，本来就是为「证明过程」而不是回滚设计的。
