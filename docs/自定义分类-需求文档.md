# 自定义集合（Collection）需求文档

> ⚠️ **已被 `docs/模板.md` 取代**（2026-10-30）。本文档第 2 节的两条原则——「字段是列不是块」「系统实体不动态化」——与组件化方向冲突，以 `docs/模板.md` 为准。
> 本文档保留作参考：集合 / 记录 / 视图 / 反链的概念定义、以及未来「通用记录模型」那部分的输入。

- 版本：v0.2
- 日期：2026-10-29
- 状态：方向已定；**本轮只更新文档，不改代码**
- 说明：文件名沿用 v0.1 的「自定义分类」。内容已从 L1「分类容器」升级为 L2「集合 = 轻量数据库」；v0.1 的「分类」是本文的一个预设。

---

## 0. 一句话

用户自建「集合」= 一张轻量数据库表；集合里每一行是「记录」（有正文的页面）；字段可自定义；关联字段可指向系统实体或其他集合的记录；人物「所属」、关系图、`@`、`[[`、vault 自动联动。

**做 L2 的完整核心，不做 L3 的完整 Notion。**

---

## 1. 从「分类」升级为「集合」

| 层级 | 是什么 | 例子 | 代价 |
|---|---|---|---|
| **L1 分类 / 容器** | 一个页面，下面挂已有实体 | 大洲页面挂国家；组织页面挂人物 | 小 |
| **L2 集合 / 数据库** | 用户自定义表：字段 + 行；每行是一条记录 | 组织集合，每条记录是一个组织，有成立时间、类型、成员关联 | 中 |
| **L3 Notion 平台** | 任意块、任意视图、公式、汇总、权限 | 完整 Notion | 很大，且会改架构 |

本文选 **L2**。

两个例子映射：

```
集合「大洲」
  字段：名称、国家（关联国家）
  记录：亚洲
    ├─ 记录：东亚（父子层级）
    │    └─ 国家：中国、日本
    └─ 国家：越南

集合「组织」
  字段：名称、类型（单选）、成立时间（日期）、成员（关联角色）、相关事件（关联事件）、纲领（关联词条）
  记录：晨曦议会
    ├─ 成员：张三、李四
    └─ 纲领：议会纲领
```

- 大洲 → 小洲 = 记录的父子层级（`parentId`），不是字段。
- 组织 → 人物 / 文本 = 记录 + 关联字段。
- 人物「所属组织」= 组织「成员」关联字段的**反向显示**，不是给角色表加一列。

## 2. 概念模型

| 概念 | 定义 | 存储 |
|---|---|---|
| **集合 Collection** | 用户自定义的一张表 + 一个页面 | `WorldEntry`（`collectionRoot` 标记）+ schema 配置 |
| **记录 Record** | 集合里的一行，也是一篇有正文的页面 | `WorldEntry`（`collection` 标记） |
| **字段 Field** | 集合的一列：名称、类型、配置 | schema 配置 |
| **关联 Relation** | 字段类型之一，指向系统实体或其他集合的记录 | 记录的 `properties[fieldKey]` |
| **反向 Backlink** | 关联字段在目标实体侧的只读/可编辑回显 | 派生查询 |
| **视图 View** | 同一批记录的不同界面：表格、树、看板、画廊、日历、时间线 | schema 配置 |
| **系统实体** | 角色 / 事件 / 国家 / 词条 | 现有四张表，不改 |

关键原则：

1. **记录是页面**：有标题、正文、标签、别名、反链，可以 `@` / `[[`。
2. **集合是页面**：有标题、说明正文、字段表、记录列表。
3. **系统实体不动态化**：角色 / 事件 / 国家仍是内置表；集合通过关联字段与它们连接。
4. **单一真源**：记录字段值只存在 `WorldEntry.properties`；人物「所属」是反查，不写镜像字段。
5. **字段是列不是块**：V1 不做「记录里再嵌任意块」；正文仍是 TipTap 富文本。

## 3. 范围

### 3.1 做（L2 完整核心）

- 集合：新建、重命名、删除、说明正文、字段表、默认视图、是否进关系图。
- 字段：7 种类型 —— 文本、数字、日期、单选、多选、勾选、关联。
- 记录：新建、编辑、删除、父子层级、标签、正文、反链。
- 列表：表格视图 + 树形视图；搜索、排序、列显示。
- 关联：指向角色 / 事件 / 国家 / 词条 / 另一个集合的记录；单选或多选；反向「所属」可编辑。
- 关系图：集合记录作为节点；关联字段作为边；父子「下级」边；按集合开关。
- `@` / `[[`：记录可被引用，类型显示集合名。
- Vault：集合 schema 写 `.ocstudio/collections.json`；记录写成笔记；字段写 frontmatter；往返不丢。
- 备份：`.ocbak` 携带集合 schema。
- 回收站、搜索、软删除、永久删除清理。
- 移动端：集合列表、表格横向滚动、记录详情、字段编辑器。
- 静态站：集合列表 + 记录详情（放到最后阶段）。

### 3.2 不做（L3，明确拒绝）

- 公式、汇总、rollup、lookup、关联聚合。
- 权限、协作、评论、版本历史（现有 journal 只做创作时间线）。
- 任意块嵌套、块级引用、块级数据库。
- 用户自定义「系统实体类型」（不能新建一张「物种」表并自己写编辑器）。
- 一个关联字段同时指向多种目标（V1 一个字段一种目标；多态关联 V2 再议）。
- 任意关系边表（关系图只画字段派生出的边，V1 不在图上新建关系）。
- 看板 / 画廊 / 日历 / 时间线（数据模型预留，P3 实现）。

### 3.3 做到什么程度（Definition of Done）

用户能完整走通这条链路，且刷新/重开/换设备（vault 文件夹）不丢：

1. 新建集合「组织」，加字段：类型（单选）、成立时间（日期）、成员（关联角色，多选，反向「所属组织」）、相关事件（关联事件）、纲领（关联词条）。
2. 新建记录「晨曦议会」，填字段、写正文、加标签。
3. 新建记录「暮光公会」，把「晨曦议会」设为「暮光公会」的上级（记录父子）。
4. 角色「张三」的「成员」里加入「晨曦议会」；张三的基本信息出现「所属组织：晨曦议会」。
5. 关系图出现「晨曦议会」「暮光公会」「张三」节点；「晨曦议会→张三」一条「成员」边；「暮光公会→晨曦议会」一条「下级」边。
6. 在张三的「所属组织」里移除晨曦议会；记录和关系图同步消失。
7. `[[晨曦]]` 能插入「晨曦议会」，点击进入记录；`@张三` 正常。
8. 关闭应用、重开，数据完整；vault 文件里能看到 `collection`、字段键、`members` 对象。
9. 未编辑的笔记字节不变；vault 验收脚本全过。
10. 移动端能完成 1–8 的核心操作。

## 4. 数据模型

### 4.1 存储选型：记录复用词条

**记录用 `WorldEntry` 承载**，不新建 `records` 表。

理由：

- 记录需要标题、正文、标签、别名、反链、`@`/`[[`、回收站、备份、vault —— 这些词条全都有。
- 新建 `records` 表要把 registry、`[[`、vault、回收站、搜索、静态站全部重接一遍，工作量更大。
- 代价是 `WorldEntry` 多两个标记字段，世界观树要把记录过滤掉。这是可控的。

不选「新建 records 表」的另一个原因：当前架构是「类型化实体 + 单一真源」，不是通用 EAV。记录复用词条，是在现有架构内加一层轻量 schema，而不是换数据层。

### 4.2 WorldEntry 扩展

```ts
// src/types/index.ts
export type MemberTargetType = 'character' | 'event' | 'country' | 'world'

export interface WorldReference {
  targetType: MemberTargetType
  targetId: number
  /** 目标是集合记录时，记录所属集合的 slug；系统实体为空 */
  collection?: string
}

export interface WorldEntry {
  // ...现有字段

  /** 集合根：该词条是一个集合的定义页，值为集合 slug */
  collectionRoot?: string

  /** 记录：该词条属于哪个集合（slug） */
  collection?: string

  /** 记录的自定义字段值，键 = 字段 key */
  properties?: Record<string, PropertyValue>

  /** 关系图坐标；记录也可拖 */
  graphPosition?: GraphPosition
}
```

注意：

- 集合根和记录**都不进世界观树**，世界观树只显示普通词条。
- 集合根不是记录，不能作为关联目标；记录可以。
- 普通词条的 `properties` 恒为空，行为不变。

### 4.3 集合 schema

存在 `.ocstudio/collections.json`（有文件夹）或 `meta.collections`（浏览器预览）。

```ts
export type CollectionFieldType =
  | 'text'
  | 'number'
  | 'date'
  | 'select'
  | 'multiSelect'
  | 'checkbox'
  | 'relation'

export type RelationTarget =
  | 'character'
  | 'event'
  | 'country'
  | 'world'
  | { collection: string } // 另一个集合的记录

export interface CollectionField {
  /** 稳定 id，f_ 前缀；不随改名变化 */
  id: string
  /** 写进 frontmatter 的键；创建时由 label 生成，之后不变 */
  key: string
  label: string
  type: CollectionFieldType
  /** select / multiSelect 的选项 */
  options?: string[]
  /** 关联字段配置 */
  relation?: {
    target: RelationTarget
    multiple: boolean
    /** 反向显示名：如「所属组织」。设置后目标实体详情会出现反向行 */
    backlinkLabel?: string
  }
  order: number
  width?: number
}

export type CollectionViewType =
  | 'table'
  | 'tree'
  | 'list'
  | 'board'
  | 'gallery'
  | 'calendar'
  | 'timeline'

export interface CollectionView {
  id: string
  name: string
  type: CollectionViewType
  /** 空数组 = 全部字段 */
  visibleFieldIds: string[]
  sort?: { fieldId: string; direction: 'asc' | 'desc' }
  /** V1 只做单条件；P3 再做多条件 */
  filter?: { fieldId: string; op: 'is' | 'contains' | 'isNotEmpty'; value: string }
  /** 看板分组字段 */
  groupBy?: string
  /** 画廊封面字段（P3） */
  coverFieldId?: string
  /** 日历 / 时间线使用的日期字段（P3） */
  dateFieldId?: string
}

export interface CollectionSchema {
  slug: string // c_xxx，稳定、不面向用户
  name: string // 显示名；与集合根标题同步
  fields: CollectionField[]
  views: CollectionView[]
  defaultViewId: string
  /** 记录是否默认进关系图；默认 true，可在集合设置里关掉 */
  showInGraph: boolean
  /** 侧边栏「更多」组内的排序（升序）；V1 = 创建顺序，P2 支持拖拽 */
  order: number
  /** 侧边栏图标（lucide 名称）；V1 统一 Boxes，P2 再开放 */
  icon?: string
  createdAt: number
  updatedAt: number
}

export interface CollectionConfig {
  version: 1
  collections: CollectionSchema[]
}
```

字段值：

```ts
export type PropertyValue =
  | string
  | number
  | boolean
  | string[]        // multiSelect
  | WorldReference[] // relation
  | null
```

- 文本：`string`
- 数字：`number`
- 日期：`YYYY-MM-DD` 字符串（与现有时间格式一致）
- 单选：`string`
- 多选：`string[]`
- 勾选：`boolean`
- 关联：`WorldReference[]`（单选也存数组，长度为 1）

### 4.4 集合配置存储

- 桌面 vault：`.ocstudio/collections.json`，与 `fields.json` 同级、同模式。
- 浏览器 Mock：`meta` 单例表的 `collections` 字段。
- 读失败回落空配置，不让界面打不开。
- 写配置：先更新内存并通知订阅者，再落盘；失败抛出给调用方提示。
- 配置里只存 schema，不存记录数据。
- `version` 从 1 开始，未来做字段迁移。

### 4.5 DB

- **不新增表**。
- `worldEntries` 增加 `collection` 索引（Dexie 字符串索引，用于按集合查记录）；DB 升 v7。
- `WorldEntry.properties` 是 JSON 对象，不加索引；按标题/字段的筛选在内存做（本地单库量级可接受）。
- `collections` 配置不进 Dexie（vault 模式）；Mock 模式进 `meta`。

### 4.6 权威与派生

**唯一权威**：记录的 `properties`。

- 关联字段的值只存在记录一侧；不在角色 / 事件 / 国家 / 词条上写镜像。
- 人物「所属组织」= 反查所有设置了 `backlinkLabel` 且 `relation.target === 'character'` 的字段，找出包含该角色的记录。
- 关系图的边 = 字段值派生。
- 记录改名不影响 id；关联存 id，安全。

反查示例：

```ts
// 伪代码
for (const schema of collections) {
  for (const field of schema.fields) {
    if (field.type !== 'relation') continue
    if (field.relation?.backlinkLabel === undefined) continue
    if (field.relation.target !== 'character') continue
    for (const record of recordsOf(schema.slug)) {
      if (record.properties?.[field.key]?.some(r => r.targetId === characterId)) {
        yield { schema, field, record }
      }
    }
  }
}
```

### 4.7 生命周期

| 场景 | 行为 |
|---|---|
| 新建集合 | 生成 slug；`order = 当前最大 + 1`；写 schema；创建集合根词条（`collectionRoot: slug`）；默认 `showInGraph: true`、一个表格视图；侧边栏「更多」出现该项 |
| 重命名集合 | 同一世界内名称唯一；更新 schema.name + 根词条标题；侧边栏项同步；记录里的父引用按 id 不受影响；vault 里根标题更新 |
| 调整集合顺序 | 更新 `CollectionSchema.order`；侧边栏按它排序（P2 支持拖拽） |
| 删除集合（软） | 根 + 全部记录软删除；schema 保留；恢复时一起回来 |
| 彻底删除集合 | 删除根、全部记录、schema；清理其他记录里指向这些记录的关联 |
| 新建记录 | `collection: slug`；`parentId` = 根或当前选中记录；标题默认「新记录」；唯一性：同一集合内标题不重复 |
| 记录改名 | 标题更新；应用内关联按 id 显示新名；vault 里引用记录的名字在下次保存时刷新（P2 可做主动同步） |
| 删除记录（软） | 记录从列表/图/反查消失；子记录的 `parentId` 悬空，按现有规则当顶层；恢复后回来 |
| 彻底删除记录 | 从其他记录的关联字段里移除该 id；不留死 chip |
| 关联循环 | 记录父子层级禁止把祖先设为后代；关联字段允许跨集合，但禁止自己指向自己；同集合的关联若形成父子重复，图上只画一条 |
| 字段删除 | schema 删字段；**笔记里的值不删**；重新加同 key 字段能读回 |
| 字段改类型 | V1 不允许；要改就删了重建（数据仍在文件里） |
| 字段改 key | V1 不允许；label 可改，key 稳定 |
| 字段改关联目标 | 允许但需二次确认；旧值可能解析不到，解析不到就丢弃显示（数据仍在文件里） |

### 4.8 Vault 格式

集合根笔记：

```yaml
---
title: 组织
collectionRoot: c_ab12cd34
tags: []
---

这个集合的说明……
```

记录笔记：

```yaml
---
title: 晨曦议会
collection: c_ab12cd34
parent: 组织
类型: 议会
成立时间: 1200-01-01
成员:
  - name: 张三
    type: character
  - name: 李四
    type: character
相关事件:
  - name: 建国
    type: event
纲领:
  - name: 议会纲领
    type: world
上级组织:
  - name: 城邦联盟
    type: world
    collection: c_ab12cd34
graph_position: { x: 120, y: 80 }
tags: [政治]
---

记录正文……
```

规则：

- `collectionRoot` / `collection` 是系统键，写回时由我们管理。
- 字段键 = schema 里的 `key`；中文键直接可读可改。
- 关联值写成 `{ name, type }`；目标是记录时多一个 `collection` slug。
- 读：
  - 有 schema 时按字段类型读；没有 schema 时记录当普通词条（不丢正文）。
  - 裸字符串关联值兼容，按 `lookupAny` 推类型。
  - 解析不到的目标跳过，并计入扫描报告。
- 写：
  - 只写 schema 里存在的字段；未知键一个字节不动。
  - 只写变化过的字段；未改动不写。
  - 保留用户已有的键名（`类型` / `成立时间`）。
  - 不整体重写。
- 记录与集合根都放在词条目录（`30.词条` 或目录关键词命中 worldEntry 的位置）；V1 不按集合分目录。V2 再考虑 `集合/组织/`。
- `collections.json` 跟文件夹走；换库各配一套。

### 4.9 备份 `.ocbak`

- `ExportPayload.data` 增加 `collections?: CollectionConfig`（可选，老备份没有）。
- 导出：`exportAllData` 读 schema store，带上配置；记录本来就在 `worldEntries` 里。
- 导入：有 `collections` 就恢复；没有就保持当前配置或空配置，不报错。
- 版本号：`version` 保持 1，新增可选字段；导入按「有则用」处理。

## 5. 页面与交互

### 5.1 导航

- **桌面侧边栏**：底部「更多」组动态列出**全部**用户自建集合（`Boxes` 图标 + 集合名），组内最后一项是「＋ 新建...」；没有集合时只显示「＋ 新建...」。不另设固定「集合」入口 —— 每个集合本身就是导航项，和截图一致。
- **选中态**：板块仍是「集合」，具体集合用 `collectionSlug` 区分；改名不影响选中，重名由 slug 兜底。`activeItem` 不再直接存集合名；侧边栏高亮比较 `collectionSlug`。
- **全部铺开、不折叠**：不设「查看更多」上限；集合多了侧边栏自身滚动（`aside` 已有 `overflow-y-auto`）。V1 不设独立集合总览页 —— 重命名/删除在集合工作区完成；P2 需要批量排序时再加「管理集合...」入口。
- **命名**：同一世界内集合名唯一；新建/重名时提示换名，避免侧边栏出现两个同名项。
- **排序**：V1 按 `CollectionSchema.order`（创建顺序）；P2 支持侧边栏拖拽排序。
- **图标**：V1 统一 `Boxes`；P2 允许每个集合选 lucide 图标。
- **新建入口**：「＋ 新建...」打开菜单，至少「新建集合」；后续可并入全局新建（角色 / 事件 / 国家 / 词条）。
- **移动端**：不加第 6 个 Tab。世界观页顶部 `词条 / 集合` 分段切换；集合列表 + 工作区复用同一套组件。
- 集合根和记录**不出现在世界观树**；世界观树只显示普通词条。
- 返回栈：记录详情 → 集合工作区 → 集合列表（移动端）；桌面端从「更多」直接切集合。

### 5.2 集合总览（P2）

V1 不设独立总览页：所有集合已在侧边栏「更多」里；新建、重命名、删除都在工作区完成。P2 集合多了，再加总览做批量排序 / 删除 / 新建。移动端的「集合列表」是选择器（V1），不是这个 P2 管理页。

- 标题：集合。
- 右上角：`＋ 新建集合`。
- 每个集合显示：名称、字段数、记录数、默认视图、是否进图。
- 点击进入工作区。
- 空态：「还没有集合，新建一个」。
- 新建弹窗：名称（必填）+ 是否进图（默认开）；创建后直接进工作区，并打开字段编辑器引导加第一个字段。

### 5.3 集合工作区

布局沿用「左列表 + 右详情」的编辑器壳：

- 页头：集合名（可双击改名）、记录数、视图切换、`字段`、`＋ 新建记录`、更多（删除集合 / 在图中显示）。
- 左侧：记录列表（表格或树），顶部搜索、排序、列显示。
- 右侧：记录详情；未选中时显示空态。
- 移动端：左列表全屏 → 点记录进详情 → 返回列表。
- 集合说明：页头旁 `说明` tab，编辑集合的正文（DocumentEditor）；不占记录列表。

表格视图：

- 列 = 标题 + 当前视图可见字段。
- 单元格按类型渲染：文本截断、数字右对齐、日期格式化、单选/多选 chip、勾选图标、关联显示名称 chip。
- 行点击选中；行尾 `⋯` 菜单（打开 / 删除）。
- 表头可排序；搜索框按标题 + 文本字段过滤。
- 空态：「还没有记录」。
- 表格横向滚动；移动端首列固定，字段列可横滑。

树形视图：

- 按 `parentId` 缩进；展开/折叠；同一层按 `order` 再按标题。
- 顶层记录的父是集合根；根不显示为行。
- 拖拽改层级放 P3；V1 通过记录详情的「上级」选择器改。

新建记录：

- 在根下创建；如果当前选中某条记录，创建为它的子记录。
- 标题默认「新记录」，选中标题可直接改名。
- 同一集合内标题唯一；重名自动加 ` 2`。

### 5.4 记录详情

- 标题：inline 输入。
- 字段区：按 schema 顺序渲染，1–2 列；类型对应控件。
  - 文本：单行输入（长文本走正文）。
  - 数字：`inputMode="decimal"` 的输入，失焦解析。
  - 日期：年 / 月 / 日三段（`DATE_INPUT`），落库 `YYYY-MM-DD`。
  - 单选：自定义菜单（portal 到 `#overlay-root`），选中 chip。
  - 多选：chip + 菜单。
  - 勾选：Checkbox。
  - 关联：chip + 「＋ 添加」；picker 按目标类型搜索。
- 正文：复用 `DocumentEditor` / `EditorCore`，不新建编辑器实例。
- 标签：复用 `TagPicker`。
- 反链：复用世界观「被引用」；正文里 `[[记录]]` / `@记录` 都能反查。
- 历史：复用 `EntityHistoryButton`。
- 保存：记录采用**自动保存**（字段失焦 / 防抖 400ms；正文沿用词条的自动保存），不设保存按钮；切换记录 / 返回前 flush。这与「记录是数据库行」的预期一致，也避免给每种字段再写一套脏状态。
  - 例外：删除是即时动作，二次确认。
  - 如果后续觉得自动保存太激进，P2 再改成显式保存。
- 删除：软删除，二次确认；子记录不级联，按悬空父级处理。

### 5.5 字段编辑器

入口：集合页头 `字段`。

- 字段列表：拖拽排序；显示 label + 类型 + key（只读小字）。
- 添加字段：label、类型、类型配置。
  - select / multiSelect：选项编辑（增删；已有值不因删选项而丢，显示原值）。
  - relation：目标（角色 / 事件 / 国家 / 词条 / 某个集合）、单选/多选、反向显示名（可选）。
- 删除字段：二次确认；提示「数据仍在笔记里，重新加同名字段可读回」。
- 改 label：允许；key 不变。
- 改类型 / key：V1 不允许（灰掉并给一句说明）。
- 改关联目标：允许但二次确认；旧值可能解析不到。
- 字段保存即时写 schema 配置；不影响记录数据。

### 5.6 关联选择器与反向「所属」

关联选择器：

- 按字段目标类型加载候选：
  - 系统实体：角色 / 事件 / 国家 / 词条。
  - 集合：该集合的记录。
- 搜索框 + 分组；已选项 chip；多选可继续加。
- 排除：自己；同集合关联时排除自己的祖先/后代（防环）。
- 目标记录显示「集合名 · 标题」。
- `filter` 字段配置在 V1 只做「目标类型」；「只显示某国角色」这类条件筛选放 P3。

反向「所属」：

- 字段设置 `backlinkLabel`（如「所属组织」）后，目标实体详情出现一行。
- V1 先接角色基本信息；国家 / 事件 P2 复用同一组件。
- 行内容：chip「集合名 · 记录名」；点击进入记录。
- 「＋ 添加」：列出所有带该反向字段的集合/字段 → 搜索记录 → 把当前角色加入该记录的关联字段。
- 移除：从该记录字段里删掉当前角色。
- 即时写入，toast 提示；不进入角色表单脏状态（关系编辑与文本字段分开）。
- 如果同一集合有多个反向字段，全部列出，用「字段名」区分。

### 5.7 集合视图（表格 / 树形 / …）

> 这是集合自身的多视图能力，和「图片导出模板」是两件事。数据模型在 V1 预留，P3 实现。

V1 实现：

- **表格**：默认；列 = 可见字段；排序；搜索。
- **树形**：按 `parentId` 缩进；适合大洲 / 分类层级。

P3 实现：

- **列表**：紧凑行，标题 + 关键字段，适合手机。
- **看板**：按单选字段分组，卡片拖动改值。
- **画廊**：卡片网格，封面字段（图片 URL / 关联实体头像）。
- **日历**：按日期字段排月历。
- **时间线**：按开始/结束日期画条（复用现有时间线的只读渲染思路）。

视图配置：

- 每个集合可以有多个视图，每个视图保存：名称、类型、可见字段、排序、单条件筛选、分组字段、封面字段、日期字段。
- 视图是 schema 的一部分，存在 `collections.json`；不改记录数据。
- V1 的表格/树形也走 `CollectionView`，避免 P3 再迁移。

### 5.8 关系图

- 只显示 `showInGraph` 为 true 的集合的记录；默认 true。
- 节点：
  - 记录节点：圆角矩形 + 标题 + 集合名；`NODE_SIZE.world` / `COLLIDE_RADIUS.world` 新增。
  - 被记录关联到的系统实体 / 普通词条：按现有节点样式出现。
- 边：
  - 关联字段：每条值一条边，标签 = 字段 label（成员 / 相关事件 / 纲领）。
  - 记录父子：`parentId` → 「下级」。
  - 同一对节点只画一条边；父子优先；不同字段重复时按字段顺序取第一条。
- 交互：
  - 类型筛选增加「记录」；可按集合再筛（P3）。
  - 点击记录节点 → 集合工作区 + 记录详情。
  - 坐标存记录的 `graphPosition`；「重新布局」包含记录。
  - V1 **不支持在图上新建关联**；关联在记录表单里编辑。P3 再考虑拖拽建边。
- 性能：记录多时图会大；用「在图中显示」按集合关掉；P3 聚类。

### 5.9 `@` / `[[` / 搜索 / 回收站

`@`：

- 记录是词条，自动出现。
- 分组仍按类型；每项右侧显示集合名（没有集合就是「词条」）。
- 修复现有 `world` 标签缺失。

`[[`：

- 记录自动出现（`WikiLinkExtension` 本来只筛词条）。
- 右侧类型显示集合名。
- 点击：记录 → 集合工作区；普通词条 → 世界观。
- 集合根不作为引用目标（V1），避免「链接到一个 schema」的歧义。

搜索：

- 记录随词条出现；结果显示集合名；P2 再拆「记录」分组。
- 集合根本身不进全局搜索（V1）；P2 可加「集合」分组。

回收站：

- 记录/集合根随词条出现；P2 按 `collection` / `collectionRoot` 显示「记录 / 集合」标签。
- 彻底删除清理关联引用。

备份：

- 见 §4.9。

### 5.10 移动端

- 入口：世界观页顶部 `词条 / 集合` 分段切换；不新增第 6 个 Tab。
- 集合列表：卡片/行；新建集合用底部弹窗或全屏页。
- 工作区：列表全屏 → 记录详情全屏 → 返回；表格横向滚动，首列固定。
- 字段编辑器：全屏页或底部抽屉；选项编辑用可滚动列表。
- 关联选择器：底部弹窗；搜索框固定；安全区域适配。
- 记录正文：复用现有移动端编辑器键盘适配；不新造编辑器。
- 所有可交互控件遵循触控反馈与安全区域约束。

### 5.11 静态展示站

放到最后阶段（P4）：

- 导航增加「集合」。
- 集合列表 → 集合页（表格）→ 记录页（字段 + 正文 + 关联链接）。
- 记录正文里的 `[[记录]]` / `@实体` 解析成站内链接。
- 样式复用 `site/styles.ts` 的令牌，不引入 Tailwind。
- 图片内联沿用现有导出管线。

## 9. 风险与边界

1. **词条表被复用**：记录/集合根与普通词条同表。必须严格过滤：世界观树、静态站词条章节、`[[` 集合根、搜索分组。漏一处就会「记录混进词条」。
2. **schema 配置与笔记分离**：`collections.json` 丢了，记录会退化成普通词条。需要恢复入口（P2：从笔记 frontmatter 推断字段）。
3. **动态字段序列化**：类型多、值形态多，`scan`/`serialize` 必须共用同一张字段定义；不能读一套写一套。
4. **关联解析**：同名实体/记录跨集合。磁盘上用 `{name, type, collection}` 消歧；解析不到要进报告，不能静默丢。
5. **反向写入**：从人物侧改关联，要写记录一侧；失败要回滚 UI 状态。用 toast + 重新拉取。
6. **图膨胀**：记录多时图会大。按集合开关 + 类型筛选；P3 聚类。
7. **自动保存**：记录自动保存，没有「未保存」提示；误删/误改只能靠回收站/历史。P2 可加撤销。
8. **视图系统**：P3 才做，但数据模型 V1 必须预留；否则 P3 要迁移。
9. **静态站**：记录正文里的关联/内链要解析，不能出死链。
10. **移动端**：表格横滑 + 字段编辑器 + picker 是三个容易溢出的地方；按现有安全区域与触控规范做。
