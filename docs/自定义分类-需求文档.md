# 自定义分类（Collection）需求文档

- 版本：v0.1（讨论稿）
- 日期：2026-10-29
- 范围：V1（可在现有架构内交付）
- 状态：已确认核心方向，待评审后进入实现

---

## 0. 一句话

把「分类」做成**词条的一种能力 + 世界观里的一个视图**：任何词条都可以设置类型、挂载异构成员；人物「所属」、关系图、`@`、`[[`、搜索、回收站、备份、vault 自动联动。

不新增 `collections` 实体表，也不做完整的 Notion 动态 schema。

---

## 1. 背景与目标

### 1.1 用户场景

**场景 A：地理分类**

```
大洲（分类）
├─ 亚洲（子分类）
│  ├─ 中国（国家，成员）
│  └─ 日本（国家，成员）
└─ 欧洲（子分类）
   └─ 法国（国家，成员）
```

**场景 B：组织分类**

```
晨曦议会（组织）
├─ 成员：张三（角色）
├─ 成员：李四（角色）
└─ 成员：议会纲领（词条 / 文本）
```

### 1.2 目标

1. 用户可以自建任意层级、任意数量的分类容器。
2. 每个容器可以打一个自由「类型」标签（大洲、组织、阵营、物种……）。
3. 容器可以放任意现有实体作为成员：角色、事件、国家、词条。
4. 人物基本信息自动出现「所属」，且可以直接增删。
5. 关系图自动出现分类节点与「下级 / 包含」边。
6. `@`、`[[`、全局搜索、回收站、`.ocbak`、vault、静态站尽量零改动继承。

### 1.3 非目标（V1 明确不做）

- 完整的用户自定义实体类型（用户新建一种「物种」表、自己定义编辑器）。
- 任意关系边表（任意两个节点连一条自定义关系）。
- 每个类型独立的字段模板（组织有「成立时间」，大洲有「面积」）。
- 成员角色、排序、主组织。
- 把分类正文里的段落当作成员（成员一律是独立实体）。

> 这些能力放到 V2 / V3，详见 §8。

## 2. 可行性依据

这不是从零造一个模块，现有架构已经有一半以上的零件：

| 需求 | 现有基础 | 结论 |
|---|---|---|
| 可嵌套容器 | `WorldEntry.parentId` + `buildEntryTree` + 世界观树拖拽 | 直接复用 |
| 异构成员 | `WorldEntry.references` 已存在；种子数据与静态站已在用 | 补编辑 UI + vault 读写 |
| 类型标签 | 无，新增 `kind` 字段 | 成本低 |
| 人物「所属」 | 可由成员关系反查 | 无需在角色表加字段 |
| `@` 引用 | `reference-registry` 已注册 `world` | 自动继承 |
| `[[` 内链 | `WikiLinkExtension` 本来就只筛词条 | 自动继承 |
| 关系图 | 唯一语义表 `relationPlan` + `buildGraphData` + 坐标持久化 | 加一种节点 |
| vault | `scan` / `serialize` 已有「名字 ↔ id」的成熟写法 | 照抄 `country.characters` |
| 搜索 / 回收站 / 备份 / 静态站 | 都已覆盖 `worldEntries` | 自动继承 |

关键判断：

- 分类不是新实体，而是「词条 + 类型标签 + 成员列表 + 图谱可见性」。
- 这与 Notion 的「page 也可以是 database」同构，而不是再发明一种实体。
- 如果新建 `collections` 表，`@` / `[[` / vault / 回收站 / 导入导出 / 静态站都要重新接一遍，且 vault 里 `组织` 目录现在映射到词条，会产生类型冲突。

## 3. 概念模型

| 概念 | 定义 | 存储 |
|---|---|---|
| 分类 | `kind` 非空的词条 | `worldEntries` 行 |
| 类型 | 用户自由填写的标签，如「大洲」「组织」 | `WorldEntry.kind` |
| 成员 | 角色 / 事件 / 国家 / 词条 | `WorldEntry.members[]` |
| 上级 | 分类树的父节点 | `WorldEntry.parentId` |
| 所属 | 人物视角的反向成员关系 | 派生查询，不落库 |
| 下级 | 父分类 → 子分类 | 由 `parentId` 派生 |
| 包含 | 分类 → 成员 | 由 `members` 派生 |

关系语义：

- **分类树**只由 `parentId` 表达，和现有词条树完全一致。
- **成员**是多对多的：一个国家可以同时属于「亚洲」和「环太平洋」两个分类。
- **国家的 `Country.parentId` 与分类成员是两套东西**：前者是国家自己的层级，后者是分类归属；V1 不自动互写。
- **分类不是标签**：标签仍是扁平、多对多、无层级的标记；分类是有层级、有成员、可进图谱的容器。

## 4. 数据模型

### 4.1 类型定义

```ts
// src/types/index.ts
export type MemberTargetType = 'character' | 'event' | 'country' | 'world'

export interface WorldReference {
  targetType: MemberTargetType
  targetId: number
  /** 预留给 V2 的成员角色（如「首领」「成员」），V1 不写入 */
  role?: string
}

export interface WorldEntry {
  // ...现有字段
  /** 分类类型；空字符串 = 普通词条，不进分类视图、不上关系图 */
  kind?: string
  /** 成员列表；分类的权威数据，不镜像到成员实体 */
  members?: WorldReference[]
  /** 关系图坐标；只有用户拖过才有 */
  graphPosition?: GraphPosition
  /** 已有：自定义字段值 */
  custom?: Record<string, string>
}
```

说明：

- `references` 更名为 `members`。`references` 只在种子数据和静态站里出现过，实际用户数据基本为空。
- `role` 只预留，V1 不提供编辑入口，也不写 vault。
- `WorldEntry.custom` 已经存在，且 `scan` / `serialize` 已经预留了 `putCustomFields(..., 'worldEntry', ...)`，只需要打开字段表开关并补表单。

### 4.2 Dexie

- **不新增表**。
- DB 升到 v7，只做一次数据迁移：
  - 对每条 `worldEntries`：若 `members` 不存在，则 `members = references ?? []`，并删除 `references`。
  - `stores` 与 v6 保持一致，不新增索引。
- 分类查询量级小（本地单库），`kind` 暂不加索引；列表页全量加载后在内存筛。

### 4.3 权威与派生

**唯一权威**：`WorldEntry.members`。

- 不在角色 / 国家 / 事件上写「所属分类」镜像字段，避免两份数据漂移。
- 人物的「所属」由反查得到：

```ts
worldEntries.filter(
  (e) => !e.deleted && e.kind?.trim() && e.members?.some(
    (m) => m.targetType === 'character' && m.targetId === characterId
  )
)
```

- 关系图的「包含」边同样从 `members` 派生。
- 成员实体改名后，`members` 里存的是 id，不会失效；vault 里的显示名在下次保存该分类时刷新（见 §4.5）。

### 4.4 删除与改名

| 场景 | 行为 |
|---|---|
| 软删除分类 | 分类从视图 / 图谱 / 人物「所属」消失；成员关系保留，恢复后回来 |
| 软删除成员 | 分类里该成员按「已删除」过滤；恢复后回来 |
| 彻底删除分类 | 删除该行；其他分类里指向它的成员引用一并清理 |
| 彻底删除成员 | 从所有分类的 `members` 中移除该 id；不留下死 chip |
| 分类改名 | 自身标题更新；正文 / `[[` / `@` 的 label 由现有引用同步逻辑处理 |
| 成员改名 | 更新所有分类 `members` 中对应 id 的显示名（落库时按 id 重新取名），并标记这些分类待落盘 |
| 父分类被删 | 子分类按现有 `buildEntryTree` 规则当根处理，不消失 |
| 循环 | 禁止把分类加入自己的祖先 / 后代；禁止自己包含自己 |

### 4.5 Vault 映射

`WORLD_KEYS` 新增：

```ts
kind: chain('kind', '类型'),
members: chain('members', '成员'),
graphPosition: chain('graph_position', 'graphPosition'),
```

文件示例：

```yaml
---
title: 晨曦议会
kind: 组织
members:
  - name: 张三
    type: character
  - name: 议会纲领
    type: world
parent: 城邦联盟
tags: [政治]
---

议会简介……
```

读写规则：

- 读：`members` 接受对象数组 `{ name, type }`；也兼容裸字符串（按 `lookupAny` 推类型）。
- 写：只写 `{ name, type }` 对象；`type` 用 `character / event / country / world`。
- 名字解析不到时跳过该成员，并计入扫描报告（与现有 `characters` / `events` 列表一致）。
- 未改动就不写；保留用户已有的键名（`成员` / `类型`）。
- 不写 `references`；如果手工文件里还有 `references`，读时作为 `members` 的回落。

### 4.6 自定义字段

- V1 打开 `FIELD_KIND_SUPPORTS_CUSTOM.worldEntry = true`。
- 字段表是**全局词条级**的：所有分类共享同一组自定义字段定义，值按条目存 `custom`。
- 分类详情增加「属性」区，渲染字段表里的自定义字段。
- 普通词条是否显示「属性」区：V1 可只在分类详情显示；V2 统一到所有词条。
- 每个类型独立字段模板（组织有「成立时间」、大洲有「面积」）放到 V2。

## 5. 页面与交互

### 5.1 入口：世界观页内的「全部 / 分类」切换

**V1 不新增侧边栏入口**，避免出现第二套编辑器、也避免移动端加第 6 个 Tab。

- 世界观页顶部（树面板上方）放一个两段切换：`全部` / `分类`。
- `全部`：现有词条树，分类条目带类型徽标。
- `分类`：只显示 `kind` 非空的词条树；新建按钮创建的是分类。
- 切换只改变树的筛选和新建行为，**详情编辑器是同一个**，数据不分叉。
- 移动端同一套切换，随页面走，不需要新导航。
- 如果后续确实需要独立侧边栏，V1.1 再加；底层数据与组件不变。

### 5.2 分类树 / 列表

- 只显示 `kind.trim() !== ''` 的词条。
- 复用 `buildEntryTree` 与现有树拖拽；分类的父子关系就是 `parentId`。
- 条目显示：标题 + 类型徽标（小号、弱色）+ 可选成员数。
- 搜索：复用世界观树的过滤（包含祖先，避免父级被筛掉）。
- 空态：「还没有分类，新建一个」。
- 新建：
  - 在「分类」视图点新建 → 创建 `title = 新分类`、`kind = 分类`、`members = []` 的词条，立即选中并进入详情。
  - 在「全部」视图点新建 → 创建普通词条（`kind` 为空），行为不变。
- 删除：沿用世界观树删除（软删除 + 回收站）。
- V1.1 可加「按类型筛选」下拉；V1 先不做，避免类型多了以后列表太长。

### 5.3 分类详情

在现有词条详情上增加三块：

1. **类型行**（标题下方）
   - 自由文本输入；有值时显示为分类，无值时是普通词条。
   - 输入框带已有类型建议（自定义浮层，不使用原生 `datalist`）。
   - 清空类型 → 该条目移出分类视图；成员保留，并提示「已转为普通词条」。
   - 类型值 trim；空字符串不落库。

2. **成员区**
   - 位置：标签行之后、正文之前。
   - 已选成员以 chip 展示，按类型分组（角色 / 国家 / 事件 / 词条），chip 前可带类型小字。
   - 「＋ 添加成员」打开搜索浮层：
     - 搜索角色 / 事件 / 国家 / 词条。
     - 按类型分组；每项显示名称 + 类型。
     - 排除自己、自己的祖先 / 后代；排除已在列表中的项。
   - 添加 / 移除**即时写入**（与世界观标签、关系图拖拽同一语义），弹出 toast；不进入正文自动保存的脏状态。
   - 成员被删除时显示为灰色「已删除」或直接过滤（V1 直接过滤，避免死链）。
   - 成员为空时显示一行弱提示：「还没有成员」。

3. **属性区**（可选，V1 末尾）
   - 渲染 `useFields('worldEntry')` 中的自定义字段。
   - 复用现有字段行样式；值存 `custom`。
   - 普通词条暂不显示，V2 再统一。

保留现有：标题、标签、被引用、正文、历史按钮。

### 5.4 人物基本信息的「所属」

- 位置：角色基本信息区末尾，固定一行，标签「所属」。
- 内容：该角色所属的分类 chip，chip 显示分类标题 + 类型小字。
- 「＋ 添加」打开分类选择器：
  - 列出所有 `kind` 非空的分类，可按类型分组 / 搜索。
  - 选中后即时把 `{ targetType: 'character', targetId }` 写入该分类的 `members`。
- chip 上的移除按钮即时从分类 `members` 删除。
- 点击 chip → 跳到世界观页的「分类」视图并选中该分类。
- 即时写入，不进入角色表单的脏状态；toast 提示「已加入 晨曦议会」/「已移出」。
  - 理由：这是跨实体的关系编辑，与关系图拖拽同类；角色表单的文本字段仍然走保存按钮。
  - 代价：改了「所属」再直接离开，关系会保留；V2 再并入统一脏状态 / 撤销。
- 新建角色尚未有 id 时，该行隐藏或禁用。
- 没有任何分类时，「＋ 添加」打开空态，引导「先去世界观 › 分类新建一个」。

> 国家 / 事件编辑器的「所属」行 V1 不做；底层服务是通用的，V2 直接复用。

### 5.5 关系图

**节点**

- 所有 `kind` 非空的词条都上图（用户已确认「全部显示」）。
- 新增 `world` 节点类型：
  - 视觉：圆角矩形 + 类型徽标 + 成员数，与角色（圆形）/ 国家（方形）/ 事件（矩形）区分。
  - `NODE_SIZE.world` 与 `COLLIDE_RADIUS.world` 新增；力导向布局自动纳入。
  - 节点 id：`world-${id}`。

**边**

- 父子：`parentId` → 「下级」。
- 成员：`members` → 「包含」。
- 同一对节点只画一条边（沿用现有无序去重）：
  - 若既是父子又是成员，保留「下级」，避免一条线两个含义。
- 分类节点之间可以有跨树成员关系；父子边和成员边都可能同时存在。

**交互**

- 类型筛选增加「分类」，默认开启；可加一个次级开关「只看有成员的分类」，默认关闭。
- 点击分类节点 → 世界观页「分类」视图 + 选中该条。
- 拖拽连线：
  - 分类 ↔ 角色 / 事件 / 国家 / 词条 → 加入成员，固定标签「包含」。
  - 分类 ↔ 分类 → 加入成员；若会形成祖先循环则拒绝。
  - 图上的连线**不修改 `parentId`**；父子层级只在树里编辑。
- 坐标：拖拽结束写回 `WorldEntry.graphPosition`；「重新布局」包含分类节点。
- 性能：分类多时图会变大；V1 先靠筛选和「只看有成员」缓解，V2 再做聚类 / 折叠。

### 5.6 `@` 与 `[[`

- `@`：`reference-registry` 已经注册 `world`，分类自动出现。
  - 修复现有小问题：`ENTITY_TYPE_LABELS` 缺少 `world`，现在会显示成 `world`；改为按 `kind` 显示「分类」或「词条」。
- `[[`：本来就只筛词条，分类自动出现；类型标签同样按 `kind` 显示。
- 点击跳转：
  - 目标 `kind` 非空 → 世界观「分类」视图 + 选中。
  - 目标 `kind` 为空 → 世界观「全部」视图 + 选中。
- 不需要新增注册类型，也不需要改 `[[` 的数据源。

### 5.7 搜索 / 回收站 / 备份 / 静态站 / 概览

| 模块 | V1 行为 | 改动 |
|---|---|---|
| 全局搜索 | 分类随词条一起出现；结果类型可显示「分类」 | 小改标签，可选 |
| 回收站 | 分类随词条一起出现 | 无 |
| `.ocbak` | `worldEntries` 自动携带新字段 | 无 |
| 静态站 | 词条详情把「引用」改为「成员」，分类带类型徽标 | 小改 |
| 概览 | 词条计数包含分类；可拆成「词条 N · 分类 M」 | V1.1 |
| 相册 | 无影响 | 无 |
| 时间线 | 无影响（分类不参与时间线） | 无 |

## 6. 联动矩阵

| 操作 | 分类视图 | 人物「所属」 | 关系图 | vault |
|---|---|---|---|---|
| 新建分类 | 出现 | — | 出现节点 | 新文件 |
| 加成员 | 成员 chip 更新 | 若成员是角色，该角色「所属」出现 | 出现「包含」边 | 分类文件写 `members` |
| 删成员 | 同上 | 同上 | 边消失 | 同上 |
| 人物「所属」加组织 | 组织成员 chip 更新 | 立即更新 | 边出现 | 组织文件写 `members` |
| 人物「所属」移出 | 同上 | 立即更新 | 边消失 | 同上 |
| 分类改名 | 树 / 图标签更新 | chip 标签更新 | 节点标签更新 | 文件标题更新 |
| 成员改名 | — | — | 节点标签更新 | 分类 `members` 的名字下次保存刷新 |
| 软删除分类 | 消失 | chip 消失 | 节点 / 边消失 | 文件移入回收站 |
| 彻底删除成员 | 成员过滤 | — | 边消失 | 清理引用 |

## 7. 分期

### V1（本文件）

- 数据：`kind`、`members`、`graphPosition`；DB v7 字段迁移。
- 世界观页「全部 / 分类」切换；分类树 / 详情；成员选择器。
- 人物「所属」行（可编辑，即时写入）。
- 关系图分类节点 / 边 / 筛选 / 坐标 / 点击 / 拖拽加成员。
- 修 `@` 的类型标签；`[[` 按 `kind` 显示。
- Vault：`kind` / `members` / `graph_position` 读写；改名同步；删除清理。
- 静态站成员区块。

### V1.1（打磨）

- 独立侧边栏「分类」（如果实际使用中需要）。
- 分类按类型筛选 / 分组。
- 概览拆分「词条 / 分类」计数。
- 搜索结果显示类型徽标。
- 移动端分类详情细节。

### V2（通用化）

- 每个类型独立的字段模板：
  - `.ocstudio/collections.json` 存 `{ kind, label, icon, color, allowedMemberTypes, fields }`。
  - 分类详情按 `kind` 渲染对应字段。
  - 仍然不新增实体表。

## 9. 风险与边界

1. **单一树**：分类和普通词条共用一个 `parentId` 树。用「全部 / 分类」视图和徽标隔离；如果实际使用中觉得乱，V1.1 可加「在世界观树隐藏分类」开关。
2. **图谱膨胀**：用户选择「全部显示」，分类多时节点会多。先用类型筛选 + 「只看有成员」缓解；V2 聚类。
3. **父子边 vs 成员边**：同一对节点只画一条，父子优先。若用户需要同时表达两种含义，V2 给边加类型。
4. **循环**：分类成员和父子关系都要阻止祖先/后代循环；写入前检查。
5. **改名同步**：成员存 id，数据层安全；vault 里的名字要等分类下次保存才刷新。可在改名时主动标记引用分类待落盘，V1 至少保证应用内显示正确。
6. **手改 vault**：成员列表由应用管理；手写但解析不到的成员会在下次保存时被丢弃。这是现有 `characters` / `events` 列表同样的边界，需要在文档/界面披露。
7. **即时写入 vs 未保存**：人物「所属」是关系编辑，即时落库，不进入角色表单脏状态。用户可能误以为「没点保存就没生效」；用 toast 和「所属」行的即时反馈降低误解。V2 再并入统一脏状态。
8. **类型拼写漂移**：「组织」和「组织 」是两个类型。V1 做 trim + 已有类型建议；V2 做类型管理。
9. **性能**：反查「所属」要扫全部词条。本地单库量级可接受；如果以后上千条，加 `memberKeys` 多值索引或缓存。
10. **不做动态 schema**：用户不能新建一种「物种」实体表；只能建分类、打类型、加成员、用全局自定义字段。这是 V1 的明确边界。
