# 时间线

> 2026-10-30 讨论定稿，**未实现**。范围只到「把已有的数据画得更好看」，不改数据模型、不改创作流程。
> 与 `docs/模板.md` 平行，互不依赖。

---

## 0. 定位：投影，不是工作台

参考对象（那套时间轴）是**工作台**：`+` 新建事件、`添加行`、在轴上定结构。我们是**投影**：轴由实体数据算出来。

一条界线，写死：

> **结构不能在轴上生长，值可以在轴上改。**

现状已经贴着这条线：

| 能在轴上做 | 不能在轴上做（也不打算做） |
|---|---|
| 拖动事件改时间（`useTimelineDrag` → `updateEventTime`） | 新建事件 |
| 拉右端改时长（写 `endTime`） | 添加行 / 定义新泳道 |
| 点开事件 → 回编辑器 | 在轴上改参与者结构 |

轴上允许改的是**已有事件的已有字段**，这是"编辑实体"，不是"在轴里造东西"。

## 3. 参与者轨道

### 3.1 形态

```
时间 ──────────────────────────────────────────────────────────▶
┌ 事件 ─────────────────────────────────────────────────────────
│      [诞生]      [初遇·并肩]        [失踪]
├ 角色 ─────────────────────────────────────────────────────────
│ 艾尔   ▬▬▬▬▬▬     ▬▬▬▬▬▬▬▬
│ 弗利欧               ▬▬▬▬▬▬▬     ▬▬▬▬▬▬
│ 星野                                     ▬▬▬▬
├ 国家 ─────────────────────────────────────────────────────────
│ 瓦兰   ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬
```

- **上：事件主轴** —— 沿用现有打包泳道，事件块保持不变
- **下：参与者轨道** —— 每个角色 / 每个国家一行；事件在那个参与者轨道上画一段**参与条**
- 两者共用同一条 x 轴，所以一眼能对上

### 3.2 关键：事件不归行

参与条的长度 = 事件跨度（`time → endTime`），瞬时事件是一个 **6px 的点**。

**不引入"主参与"字段**：事件本来就是多对多（`characters[]`、`countries[]`），任何"归一行"的方案都是在给多对多硬塞一对多，结局不是加字段就是复制块。

群像事件的读法因此变成：主轴上**一个**块 + 轨道上**七段**条 —— 正好是"这件事把谁卷进来了"。

### 3.3 兜底与折叠

| 情况 | 处理 |
|---|---|
| 事件没有任何角色 / 国家 | 单独一条 **「未归属」** 轨道兜底。**宁可丑，不能丢事件** |
| 角色多于 8 个 | 折叠成「角色（12）」一行，点开展开；配合筛选 |
| 国家 | 通常少，默认展开 |
| 轨道数据为空 | 整组不渲染，不占位 |

### 3.4 联动

- 点事件块 → 它所有的参与条高亮（不是变粗，是换 `bg-ink`）
- 点参与条 → 聚焦回事件块（滚动到可视 + 选中态）
- 悬停参与条 → 显示事件名（`text-[11px] text-ink-faint`，只在悬停出现）

## 4. 事件连线

- 来源：`events.relations`，每条 `{targetId, relation}`
- 画法：从源块右缘到目标块左缘的**正交折线**（水平 → 垂直 → 水平），拐点圆角 2px
- 颜色：`var(--oc-line-hover)`，1px；选中事件的连线换成 `var(--oc-ink)`
- 标签（关系名）：**只在悬停/选中时出现**，常显会让密集区变成蛛网
- 方向：时间先后决定左右；同一对事件只画一条（双向取时间早者为源）
- **允许交叉**：不做交叉最小化。密集到读不清时再谈分层或筛选，不在 v1 上算法

## 5. 视觉规格

### 5.1 事件块（对齐设计系统：零描边、悬停才出线）

| 状态 | 规格 |
|---|---|
| 常态 | 浅底 `bg-[var(--oc-hover)]`，**无描边** |
| 悬停 | `border-line-hover`（1px）+ 光标 |
| 选中 | `border-ink`（1px） |
| 关键节点 | 左侧 3px 见方实心点（`bg-ink`）+ 名称 `font-medium` |
| 区间事件 | 右端一个小竖线标记"到这里结束" |
| 文本 | `text-[13px] text-ink`，超出省略 |

> 现在的 `border border-line bg-paper-card` 偏重，改成"浅底 + 悬停出线"跟参考对象同一路子，也正是我们自己的令牌规则（线只用于区块之间 / 表格行 / 浮层边界）。

### 5.2 参与条

| 项 | 规格 |
|---|---|
| 高度 | 2px，圆角 `rounded-full`（圆形例外允许） |
| 颜色 | `var(--oc-line-hover)`；高亮时 `var(--oc-ink)` |
| 跨度 | 事件 `time → endTime`；瞬时事件为 6px 圆点 |
| 间距 | 同一轨道上同一天的事件不合并，靠 x 位置自然分开 |

### 5.3 其它

- 时间刻度与网格线不动
- 密度切换「简 / 详」：简 = 只有块 + 标题；详 = 块内加一行时间与参与者头像（`Avatar size="xs"`）
- 左上角工具栏保持现有 48px 页头（`TOOLBAR`），不加新按钮组

## 6. 明确不做

| 不做 | 原因 |
|---|---|
| **参与时段**（角色中途加入 / 提前退出） | 事件跨度内再裁一刀 = 每个参与者多两个输入框；收益只在「长跨度 + 多人」的少数事件，90% 的情况是给创作者加表单。**已否决（2026-10-30）** |
| 在轴上新建事件 | 工作台式的入口；新建永远在编辑器或列表页 |
| 添加行 / 自定义行 | 行由参与者数据推导，不是用户定义的结构 |
| 事件主图 | 需要新增字段，且与「封面」槽位语义冲突，另议 |
| 模糊时间（约 / 早于） | 绑在数据模型上，见组件化文档未决 E |

## 7. 实施顺序

| 步 | 内容 | 依赖 |
|---|---|---|
| 一 | 参与者轨道（含未归属兜底 + 折叠）+ 关键节点强化 + 关键节点筛选 | 无 |
| 二 | 事件连线 | 无（但建议等轨道稳定后再加，否则两层线挤在一起） |
| 三 | 密度切换 | 一、二之后 |

第一步做完，「群像读不清」的问题就解决大半；连线是锦上添花，密度切换是最后的手感调节。

## 8. 风险

1. **滚动同步**：轨道与主轴必须共用同一个滚动容器，否则横向滚动会错位。现有 `useTimelineViewport` 要改成"单容器 + 两段内容"，不能是两个各自滚动的列表。
2. **命中区冲突**：轨道层加了拖拽（参与条可点）之后，主轴事件的拖动命中区不能与之重叠；轨道与主轴之间留 8px 死区。
3. **连线交叉**：事件密集时正交折线会糊成一片。这是"允许交叉"的直接代价，先用"悬停时才显示标签 + 选中才高亮"压住。
4. **未归属轨道会漏**：如果忘了这条兜底，用户新建的事件（还没填参与者）会在时间线上凭空消失——比丑严重得多，必须有测试盯住。
5. **两层高度**：主轴 + 轨道会让可视区变矮。密度切换之外，还要允许"只显示事件"（隐藏全部轨道），给窄屏一个退路。
