# 前端审查：为什么它还像网页（2026-11-14）

审查范围：桌面端（Tauri / Windows 为主）的应用外壳、交互模型、浮层、反馈与排版。移动端（Capacitor）只在影响桌面时提到。依据是源码阅读，没有跑起来逐屏截图，所以凡是「需要实测确认」的地方都单独标了。

## 总评

设计系统本身是这个项目最强的部分：令牌唯一源（`ui-tokens.ts` + `globals.css`）、三档圆角、单一浮层阴影、`audit:design` 自动拦截，这些在个人项目里很少见，视觉上的「乱」基本已经被压住了。

问题不在视觉令牌，而在**行为层**。用户判断「这是网页还是应用」主要靠手感：窗口怎么动、点下去有什么反应、键盘能不能用、菜单怎么开关、加载时屏幕上闪了什么。这一层目前大量沿用了浏览器的默认行为或移动端的习惯，于是视觉很克制，摸起来却像一个网站。

下面按「影响有多大 × 改起来有多贵」排序。P0 是用户每天都会碰到、一眼就能感觉到的；P1 是细看会出戏的；P2 是打磨项。

| 级别 | 问题 | 主要位置 |
|---|---|---|
| P0 | 自绘标题栏不像系统窗口（按钮尺寸、图标、关闭色、Snap Layouts） | `WindowControls.tsx`、`tauri.conf.json` |
| P0 | 列表没有「选中」这一状态：单击即打开、无方向键、无 Delete 键、无右键菜单 | `CharacterListItems.tsx` 等三套 ListItems |
| P0 | 原生 `title` 提示 159 处，没有应用自己的 Tooltip | 全局 |
| P0 | 桌面端点击会缩放（`touch-feedback` 的 `scale(.96)`） | `globals.css`、`BTN_PRIMARY`、`CoverCard` |
| P0 | 浏览器快捷键没拦：F5 / Ctrl+R 刷新、Ctrl+P 打印 | 无对应代码 |
| P1 | 字体没有打包，衬线在多数 Windows 上会落到宋体 / Times | `globals.css` `--font-*` |
| P1 | 「加载中…」文字闪屏；错误态「重试」按钮实际调用的是「新建」 | 三个 List 组件 |
| P1 | 菜单系统有五六套，开关时机、键盘支持各不相同 | `components/shared/*Menu*`、`BlockTypeMenu` |
| P1 | 窗口失焦没有任何视觉变化 | 外壳 |
| P1 | 启动白闪（暗色用户）与窗口位置不记忆 | `lib.rs` setup |
| P1 | 页面切换是「网页式」的：返回按钮 + 横滑，没有前进 / 后退历史 | `SectionSwap.tsx`、`EntityEditorShell.tsx` |
| P2 | 滚动条常显、`cursor-pointer` 泛用、字号散落、对话框标题不统一等 | 见第四节 |

## 一、P0：一眼就出戏的地方

### 1.1 标题栏不像系统窗口

`tauri.conf.json` 设了 `decorations: false`，窗口按钮由 `WindowControls.tsx` 自绘。目前的实现和 Windows 11 原生标题栏差得比较多：

- **尺寸**：按钮是 `h-6 w-6`（24×24）、图标 13px，还有 `-mr-2` 往里收。原生是整条标题栏高度、约 46px 宽、贴死右上角，鼠标甩到屏幕右上角（Fitts 定律）应该能直接点到关闭。现在右上角有 4px 空隙，甩过去点不到。
- **图标**：用的是 lucide 的 `Maximize2` / `Minimize2`（两个斜向箭头），那是「全屏 / 退出全屏」的语义。Windows 的最大化是一个方框，还原是两个叠起来的方框。用户一看就知道这是网页做的。
- **关闭的悬停色**：现在是 `hover:bg-error-light hover:text-error`（淡粉底 + 红字）。系统约定是实心红底（约 `#C42B1C`）+ 白色图标。这是少数几个**应该**打破「界面无色」规则的地方，因为用户靠这块红色确认「我要关的是窗口」。
- **Snap Layouts**：自绘标题栏会丢掉 Windows 11 悬停最大化按钮时弹出的布局面板，以及 Win+Z。Tauri 本身不提供；社区插件 `tauri-plugin-decorum` 用的就是「把最大化按钮命中区报告为 `HTMAXBUTTON`」的办法。值不值得做看你的用户，但这是 Windows 用户最容易察觉的缺失。
- **透明窗口的边框和阴影**：`transparent: true` + `decorations: false` 在 Windows 上容易丢系统窗口阴影和 Win11 的圆角。**需要实测**：把窗口放在白色背景前看边缘是否有阴影、四角是否圆。

建议：按钮改成 `h-8 w-[46px]`、去掉 `-mr-2`、换成方框图标（lucide 没有现成的，自己画两个 10px 的 SVG 即可，不违反「只用 lucide」的初衷，或者在 design skill 里登记这一处例外），关闭按钮悬停用实心红 + `text-paper-fixed`。macOS 已经交给系统红绿灯，这部分只影响 Windows。

### 1.2 列表没有「选中」

这是「网页感」最大的单一来源。角色 / 事件 / 国家列表的行和卡片（`CharacterRow`、`CoverCard`）都是**单击即打开**，没有选中态。这直接导致了一串后果：

- 方向键不能在列表里移动（行有 `tabIndex={0}`，只能 Tab 一个个跳，只响应 Enter）。
- 不能按 Delete 删除、不能 F2 重命名、不能 Ctrl+A / Shift+点选多个。
- 删除只能靠悬停才出现的垃圾桶图标（`ROW_ACTIONS` 的 `opacity-0 group-hover:opacity-100`），这是典型的网页后台表格做法。
- 行和卡片**没有右键菜单**（ListItems 里没有 `onContextMenu`），而 `GlobalContextMenu` 又把系统菜单拦掉了。结果是在列表上右键「什么都不发生」。文件夹堆、侧栏分类倒是有右键菜单，所以同一屏里有的能右键、有的不能。

桌面应用的通行模型是：单击选中、双击或 Enter 打开、方向键移动、右键对选中项出菜单、Delete 删除。关系图和时间线已经是「单击选中、双击打开」（AGENTS.md 里写了时间线这么做），列表反而没有。

建议做一个共享的 `useListSelection(ids)`：管理 `selectedIds` 与锚点，处理方向键 / Home / End / Shift / Ctrl，挂在 `SortableList` 外层。行和卡片只读 `selected` 渲染一个 `bg-[var(--oc-hover)]` 加深一档的底色（选中要比悬停深，否则分不清）。右键菜单复用 `MediaContextMenu`，项目和悬停按钮一致。悬停按钮可以保留，但不应是唯一入口。

一个折中：如果你认为「单击即打开」对创作工具更顺手（Notion、Obsidian 的文件列表都是单击打开），那也可以保留单击打开，但至少要补上**方向键移动焦点 + 右键菜单 + Delete**。Obsidian 就是这么做的。

### 1.3 原生 `title` 提示

全项目有 159 处 `title="…"`，`components/ui/` 下没有 Tooltip 组件。原生提示是浏览器画的：悬停约 1 秒才出、字体和底色跟着系统走（暗色主题下也可能是一块浅色框）、不能控制位置、移动端完全不出。图标按钮全靠它说明自己是什么，所以每个图标按钮都在提醒用户「这是 WebView」。

建议：基于 Base UI 的 Tooltip 做一个 `components/ui/tooltip.tsx`，Portal 到 `#overlay-root`，皮肤用 `MENU` 那一套但更小（`text-[12px] px-2 py-1`），延迟 500ms、在同一组按钮之间移动时即时切换（Base UI 的 `Tooltip.Provider` 有 `delay` / `closeDelay`）。快捷键写进提示里（「保存 Ctrl+S」），这是桌面应用的标配。迁移可以分批：先换页头、工具栏、编辑器格式栏这些图标按钮密集的地方，`aria-label` 保留。

### 1.4 桌面端点击会缩放

`.touch-feedback:active { transform: scale(0.96) }` 是为触屏写的，但它没有限定指针类型，桌面鼠标按下也会缩。`BTN_PRIMARY`、`BTN_DANGER`、`SETTINGS_ACTION_BTN`、`FILTER_TRIGGER`、`MOBILE_FILTER_BTN` 和每张 `CoverCard` 都带着它。鼠标点按钮时整颗按钮缩一下，是移动网页的手感，原生桌面控件按下只变色。

建议一行解决：

```css
@media (hover: hover) and (pointer: fine) {
  .touch-feedback:active { transform: none; }
}
```

桌面上按下的反馈改为底色再深一档（`:active { background-color: var(--oc-line) }` 之类）。

### 1.5 浏览器快捷键没拦

WebView2 默认开启浏览器加速键。代码里没有拦截 F5、Ctrl+R、Ctrl+Shift+R、Ctrl+P 的地方（`NativeMenuBlocker` 只处理右键）。后果：

- F5 / Ctrl+R 会**整页刷新**。正文是 600ms 防抖自动保存，刷新时刚打的字可能还没落盘；即使保存了，刷新也会回到启动闸门，看起来像应用崩了重启。这是数据风险，不只是观感问题。
- Ctrl+P 会弹出 WebView 的打印预览，打印的是整个应用界面。
- `zoomHotkeysEnabled` 在 Tauri v2 默认是关的，Ctrl+滚轮缩放应该没问题，**需要实测确认**。

建议：在 Rust 侧对主窗口关掉浏览器加速键（WebView2 的 `AreBrowserAcceleratorKeysEnabled = false`，Tauri v2 可在 `with_webview` 里拿到 `ICoreWebView2Settings3` 设置），这是最干净的做法；同时在前端 keydown 里兜底 `preventDefault` 这几个组合键。关掉后 Ctrl+F 之类也会失效，你已经有自己的 `FindReplaceBar`，不受影响。

## 二、P1：细看会出戏的地方

### 2.1 字体没有打包

`--font-serif: 'Noto Serif SC', 'Times New Roman', serif`，项目里没有 `@font-face` 也没有 `next/font`。大多数 Windows 机器没装 Noto Serif SC，于是所有 `PAGE_TITLE`、`SECTION_TITLE`、封面卡标题、实体名输入会落到：拉丁字符用 Times New Roman、汉字由系统回落到宋体（SimSun）。宋体在小字号下发虚、笔画细，配 Times 是很典型的「旧网页」观感。你的设计系统很依赖衬线来拉开层级，这一条会直接把整体气质拉低。

`--font-sans` 也没写中文字体名（`Microsoft YaHei UI` / `PingFang SC`），中文会落到系统默认，通常是微软雅黑，问题不大，但应该显式写出来，否则不同机器表现不同。`--font-mono: 'Courier New'` 也偏旧，建议 `ui-monospace, 'Cascadia Mono', Consolas, monospace`。

建议：把思源宋体（Noto Serif SC）子集化后随包分发。只用于标题的话可以只打 600/700 两个字重，按常用 3500 字 + 标点子集化，woff2 体积可以压到 1–2 MB。正文衬线（小说阅读）如果要用，再单独加 400。

### 2.2 加载闪屏与一个真 bug

角色、事件、国家三张列表在 `loading` 时整块替换成居中的「加载中…」文字（`CharacterList.tsx:318`、`EventList.tsx:108`、`CountryList.tsx:103`）。数据来自本地 IndexedDB，通常几十毫秒就回来，所以用户看到的是一帧文字闪一下。应用的做法是：200ms 内什么都不显示（保留页头和空白），超过才显示骨架或文字。页头不该随加载消失。

**真 bug**：这三个文件的错误态里，「重试」按钮的 `onClick` 是 `onCreateCharacter` / `onCreateEvent` / `onCreateCountry`。也就是说，加载失败后点「重试」会**新建一个空实体**。`CategorySection` 和 `NovelTree` 是对的（调 `reload()`），可以照着改。

### 2.3 菜单系统不统一

我数到的独立实现有：Base UI 的 `DropdownMenu`（菜单栏）、`ContextMenu`（编辑器选区）、`GlobalContextMenu`（输入框）、`MediaContextMenu` / `MenuSurface`（按坐标弹出）、`FilterSelect`、`BlockTypeMenu`、`MenuBarSearch` 的面板、`mention-render.ts` 的原生 DOM 下拉。视觉已经统一到 `MENU` 令牌，但行为不一致：

- **关闭时机**：`BlockTypeMenu` 在 document 的 `click` 上关（即松开鼠标时）；原生菜单在**按下**时关。`ContextMenu` / `GlobalContextMenu` / `BlockTypeMenu` 关闭时都有 150ms 淡出，期间菜单还在屏幕上、还能被点到；Base UI 的菜单是另一套动画。
- **键盘**：`components/shared/` 里只有 `GroupModeMenu` 和 `PosterCover` 处理了 `ArrowDown`。也就是说多数自绘菜单打开后不能用方向键选、不能 Enter 确认。Base UI 那几个是可以的。
- **搜索框**：`MenuBarSearch` 用 `onBlur` + `setTimeout(150)` 关面板，这是网页上常见的 hack，点得慢一点就会点空。

建议：把「按坐标弹出的菜单」全部收到 Base UI 的 `Menu`（它支持虚拟锚点，右键菜单也能用），一套键盘导航、一套关闭规则。手写的那几份逐步删掉。关闭动画建议直接去掉或缩到 80ms 以内：系统菜单关闭是瞬时的，淡出会让人觉得慢。

### 2.4 窗口失焦没有变化

原生窗口失去焦点时，标题栏文字变灰、选中高亮变淡，用户靠这个知道「现在键盘输入去哪了」。代码里没有监听窗口焦点（没有 `onFocusChanged` / `document.hasFocus` 相关逻辑）。Mica 本身失焦会变成纯色，但界面上的文字和选中态不变。

建议：在 `AppShell` 里监听 `getCurrentWindow().onFocusChanged`（浏览器下退回 `window` 的 focus/blur），给 `<html>` 加 `data-window-inactive`，CSS 里把 `[data-menubar]`、`[data-sidebar]`、`[data-statusbar]` 的 `text-ink` 降到 `ink-muted`、侧栏选中竖线降到 `ink-faint`。改动很小，效果很「系统」。

### 2.5 启动白闪与窗口状态

- `lib.rs` 的 `setup` 无条件把窗口底色刷成亮色纸白 `Color(254, 252, 248, 255)`，窗口默认立即可见。暗色主题的用户每次启动都会先看到一块米白，等前端起来再变黑。建议窗口配置 `visible: false`，前端首帧（`THEME_BOOT_SCRIPT` 落完主题之后）调 `getCurrentWindow().show()`；底色按上次的主题偏好设置（Rust 侧读不到 localStorage 的话，前端在退出前把主题写进一个小文件或用 `tauri-plugin-store`）。
- 窗口尺寸和位置不记忆，每次都是 1200×800 居中。`tauri-plugin-window-state` 一行就能解决，包括最大化状态。
- `minWidth: 1050` 偏大，13 寸笔记本半屏分屏（约 960px）放不下。外壳已经有 `OverflowBar` 按容器宽度收工具栏，可以考虑放到 800 左右再验证一遍布局。

### 2.6 导航是网页式的

- 列表 → 编辑器之间是 `SectionSwap` 的横向滑动 + 编辑器左上的「← 返回」文字按钮。这是移动端 / 网页的「进入详情页」模型。桌面应用里，编辑器已经带了左侧列表栏（`EntityEditorShell` 的 `list`），这本身就是主从（master-detail）布局，「返回」按钮和滑动转场就显得多余：列表在左边一直可见，用户并不需要「回去」。
- 没有前进 / 后退历史：鼠标侧键（`button 3/4`）、`Alt+←/→` 都没有处理。在实体之间通过 `@` 引用和 `[[链接]]` 跳来跳去是这个应用的核心动作，跳过去以后没有办法回到上一篇，这比任何视觉问题都更影响「好不好用」。
- 侧栏切换板块是即时的，列表 ↔ 编辑器却有 150ms 滑动，两种节奏混在一起。

建议：在 `NavigationContext` 上加一个历史栈（记录 `activeItem` + 实体 id），接上侧键和 `Alt+←/→`，编辑器页头放一对 ‹ › 小箭头替换「返回」文字。桌面上把横滑改成 fast 档的淡入（或直接无动画），横滑只留给移动端。

## 三、视觉细节（P1–P2）

这些单看都不大，但累积起来就是「粗糙感」的主要来源。

- **滚动条常显**：全局 `::-webkit-scrollbar` 6px，滑块用 `line-hover` 常显。Windows 11 和 macOS 的默认行为是细条、静止时隐藏或极淡、悬停才变粗。WebView2 支持 `scrollbar-width: thin` 但不支持自动隐藏，可以用「容器 `:hover` 时才给滑块上色」近似：静止透明，悬停 `line-hover`，拖动 `ink-faint`。
- **`cursor-pointer` 泛用**：28 个文件里有。Windows 和 macOS 的原生按钮、菜单项、列表行都是箭头光标，手形只留给超链接。`dropdown-menu.tsx` 的 `ITEM` 里就写了 `cursor-pointer`，菜单项出现手形是很明显的网页信号。建议全局 `button, [role=button], [role=menuitem] { cursor: default }`，只在正文链接与 `[[链接]]` 上保留手形。
- **文字光标**：`body` 设了 `user-select: none`，这是对的。但要实测一下在不可选的标签文字上，鼠标是否仍显示 I 形光标（Chromium 在某些版本会这样），如果是，需要在 `body` 上补 `cursor: default`。
- **焦点圈**：`focus:outline-none` 出现 46 处，而统一的 `focus-visible` 样式基本没有（shadcn 留下的 `outline-ring/50` 被大量覆盖）。键盘用户 Tab 时经常不知道焦点在哪。建议全局定义一条 `:focus-visible { outline: 1.5px solid var(--oc-ink-muted); outline-offset: 1px }`，各处删掉 `focus:outline-none`，只在输入框这种「有底线表达焦点」的地方显式关掉。
- **对话框动画**：`dialog.tsx` 用 shadcn 默认的 `zoom-in-95`（从 95% 放大进场）。这是 shadcn 网页模板的标志性动效，桌面系统对话框是淡入 + 极小位移或者干脆没有。你在 `globals.css` 里已经写了更克制的 `overlay-panel-in`（6px 上移 + 淡入），建议对话框也统一用它。
- **对话框标题不统一**：design skill 规定弹窗标题用 `PAGE_TITLE`，多数调用点也传了，但 `DialogTitle` 默认样式是 `font-heading text-base font-medium`（sans 16px），`SettingsDialog.tsx:51` 就没传，于是设置弹窗的标题是另一种字。建议把 `PAGE_TITLE` 直接写进 `DialogTitle` 的默认值，调用点不用再传。
- **字号散落**：`text-[10/11/12/12.5/13/14/15px]` 这类字面量有 518 处，加上 `text-xs/sm/base` 144 处，实际在用的字号至少有八九档。设计系统管住了颜色和圆角，但没有管字号。建议在 `globals.css` 的 `@theme` 里定义 4–5 档语义字号（如 `--text-caption: 11px`、`--text-ui: 13px`、`--text-body: 15px`、`--text-title: 18px`），`audit:design` 加一条规则拦字号字面量，和圆角同样处理。
- **选区颜色**：`::selection` 写死了 `rgba(107, 102, 93, 0.25)`，没有走令牌，换主题预设时不会跟着变。建议加一个 `--oc-selection` 令牌放进主题。
- **旧内核降级写死了色值**：`[data-below-target-version] .backdrop-blur-lg` 用的是 `#FEFCF8` / `#1C1B1A`，换成其他主题预设会出现一块错色。改成 `var(--oc-paper)`。
- **代码块零圆角**：`.tiptap code` / `.tiptap pre` 是 `border-radius: 0`，而导出预览 `.oc-doc-prose pre` 是 `radius-item`。按设计系统，代码块属于「贴内容的小件」，应该是 4px。
- **Toast 文案偏长**：例如重命名文件夹后是「已重命名为「X」」加一句「N 个角色跟着走，角色本身没动」。这违反了你自己的文案节制规则（§9），而且 toast 位置在左下角，两行字会盖住侧栏底部的设置入口。建议 description 只留在有风险的操作上。
- **图片可被拖出来**：45 处 `<img>` 里只有 4 处设了 `draggable={false}`。在 WebView 里拖一张头像会出现半透明的浏览器拖拽影像，甚至能拖到桌面。建议全局 `img { -webkit-user-drag: none }`，真正需要拖的地方（相册导出？）再显式打开。
- **`DevMockBadge`** 只在浏览器 Mock 下出现，不影响桌面；但它在 `bottom-8` 和 toast 区域重叠，开发时截图会误导，可以挪到右上。

## 四、菜单栏与侧栏

- **菜单栏是四个独立的 `DropdownMenu`**，靠 document 上的 `mousemove` + 10ms 定时器实现「打开一个之后悬停切换」（`MenuBarMenus.tsx:121-151`）。能用，但原生菜单栏还有两条没有：打开后按 ← / → 在「文件 / 编辑 / 视图 / 关于」之间切换；按 Alt（或 F10）激活菜单栏、`Alt+F` 直接打开「文件」。Base UI 有 `Menubar` 组件，正是为这个场景做的，换过去可以删掉那段 mousemove 逻辑。
- **打开状态只变字色**：菜单触发器打开时是 `data-open:text-ink`，没有底色块。Windows 和 macOS 的菜单栏打开项都有一块高亮底，否则菜单浮层和触发器之间看起来没有关联。
- **「关于」作为顶级菜单**：Windows 习惯是「帮助」，里面放「关于」「检查更新」。小事，但用户找东西靠习惯。
- **编辑菜单的剪切 / 复制 / 粘贴只对编辑器生效**（`if (!activeEditor) return`）。焦点在普通输入框（搜索、字段行）时点菜单里的「复制」没有反应。可以退回 `document.execCommand` 作用于 `document.activeElement`。
- **侧栏**：板块按钮之间没有键盘导航（↑/↓）。选中态是左侧 2px 墨色竖线，这个处理很好；但悬停底色 `--oc-hover` 只有 4.5% 墨，在 Mica 透出的桌面背景上基本看不见，**需要在亮色桌面壁纸下实测**，可能要给 Mica 场景单独加深一档。

## 五、做得好的地方（别改坏）

- 令牌和审计体系：颜色、圆角、阴影、动效时长都有唯一源，并且有 `audit:design` 自动拦截。这是后面所有改动能「一处改、全局变」的基础。上面的字号、焦点圈、光标建议，都应该照这个模式收进令牌 + 审计。
- 浮层统一 Portal 到 `#overlay-root`，并且要求「打开前量好坐标」（约束 6），避免了下拉闪到左上角再归位这种很网页的问题。
- `OverflowBar` 按容器宽度收工具栏，比按窗口断点收要「应用」得多。
- 关窗协调器、保存屏障、Ctrl+S 的回执：数据安全这一层做得比很多商业应用都严谨。
- 右键菜单统一拦截、`user-select: none` 只放开编辑区，这两条已经是桌面化的正确方向。

- `design-audit` 的 `font-size-literal` 从警告改成**报错**，白名单 `FONT_SIZE_LITERAL_ALLOW` 按**值**放行并逐个写理由；
  另用探针文件确认过：加一处 `text-[11px]` 会让 `audit:design` exit 1。
- `globals.css` 的 `@theme` 注释与 design skill 的「字号五档」小节同步：五档用途、等值迁移口径、
  什么情况能写字面量、**新加一档的完整步骤**（`@theme` → `src/lib/utils.ts` 的 `extendTailwindMerge` → 白名单）。

### 5.4 「从编辑页返回列表时闪一下」的排查结论 —— 不是回退引入的，动效未改

现象：收尾后实机点进编辑器 / 返回列表，中间会白闪一下。用户怀疑是「四、回退与修正」的遗留。

**先比对了旧版代码**：把 `page.tsx` / `use-entity-workspace.ts` / `globals.css` 三处过渡逻辑与 `v0.20.5-beta`
（旧版 tag `f2f9ed7`）逐行对照 —— `data-animate` 的取值、四个 `slide-*` keyframes、`@starting-style`、
`.section-fade[data-visible="false"]` 的 `display:none` 规则**完全一致**。所以不是那次回退改坏的。

**再抓帧**（WebView2 的 `--remote-debugging-port` + `Page.startScreencast`，同一操作各抓一轮）：

| 前端 | 点击返回到列表完全显示 | 空白帧（80% 近白） |
|---|---|---|
| `next dev` | ~380ms | 102ms / 175ms（两帧，肉眼可见） |
| 生产构建 `out/` | ~308ms | 55ms / 147ms（两帧，肉眼不可见） |

`next dev` 下点击返回后主线程被占约 150ms（CPU profile 里是 React 开发模式的
`jsxDEV` / `jsxDEVImpl` / `logComponentRender` / `validatePropertiesInDevelopment` 等校验，long task 实测 106ms + 53ms），
150ms 的横滑只画出了起始帧和结束帧 —— 于是看到「空白 → 跳一下 → 内容出现」。
生产构建没有这段开销，旧版安装包也是生产包，所以「旧版没这个问题」。

**结论**：dev 专属的观感问题，代码不动。残余的 1–2 帧空白来自两件事：旧页内容先卸载（只剩纸色）、
新页从 `display:none` 恢复的那一帧还没画出来；要彻底消掉得让旧页在滑出期间不淡出、新页压在它上面淡入
（约 6 行 CSS，试过可行），按「不改动效」的决定已撤回，未提交。
