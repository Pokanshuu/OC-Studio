# 编辑器工具栏设计（Markdown 最小集）

> 版本 1.0 · 2026-10-29 · 状态：参考稿（待拍板后实施）
> 范围：只覆盖正文 Markdown 编辑命令。不含文件管理、预览/阅读、导出/分享、协同、账户、AI、主题切换、页面设置。
> 适用：OC Studio 的 TipTap 正文（`EditorCore` / `DocumentEditor`），正文最终落成 **Markdown + frontmatter**。

## 0. 先说清楚这份文档的来由

- 这是从 Simple_Office 移植编辑器能力时的**取舍依据**：借它的工具栏注册表、组级溢出、响应式策略、查找替换、链接浮层、图片处理，**不**照搬它的字体 / 颜色 / 对齐 / 页面设置 / docx / 打印。
- 原因不是「那些功能不好」，而是 OC Studio 的正文是 Markdown 真源：工具栏产出的每一笔都要能无损往返。Markdown 表达不了的格式，要么写 HTML 污染文件，要么触发 `oc-document` 兜底块。
- **保留** OC Studio 已有的、Simple_Office 没有的能力：`@` 提及、`[[` 内链、`<small>`、自定义图片块、表格/任务列表、拖拽手柄、斜杠菜单、移动端选词工具栏、Markdown 桥。
- 本文件只解决「正文工具条长什么样、放什么、怎么溢出、快捷键怎么排」；不含三栏布局本身。

## 1. 目标与「90% 覆盖」口径

### 1.1 目标

- 宽屏常驻**不超过 9 个功能组**；手机常驻**不超过 3–4 个按钮 + 溢出入口**。
- 典型 Markdown 写作任务的核心操作一键可达；常用扩展最多打开一次溢出菜单。
- 不为低频语法增加常驻宽度；长尾语法靠快捷键、手动输入或后续扩展。
- **OC Studio 只有所见即所得一种模式**（TipTap）。工具条命令直接应用样式，再由 Markdown 桥序列化；没有源码模式，也不做「插入原始 Markdown 标记」的双模式分支。

### 1.2 「90%」的验收口径

典型任务：标题、粗体、斜体、无序列表、有序列表、引用、链接、图片、行内代码、代码块、表格、分割线、任务列表、删除线。

验收标准：

- 不打开二级以上菜单可完成：粗体、斜体、标题、无序/有序列表、链接、更多入口。
- 打开一次溢出菜单可完成：引用、代码块、行内代码、图片、表格、分割线、任务列表、删除线。
- 窄屏/手机选中文本后，通过上下文气泡完成粗体、斜体、链接、行内代码。
- 不纳入脚注、数学公式、目录、定义列表、图表、HTML 嵌入、YAML front matter 等长尾。

## 2. 最小功能集与 Markdown 映射

### 2.1 核心常驻

| 功能 | Markdown 输出 | 建议快捷键 | OC Studio 现状 / 备注 |
|---|---|---|---|
| 撤销 / 重做 | 编辑器历史 | `Ctrl/Cmd+Z` / `Shift+Ctrl/Cmd+Z` | 有历史栈；桌面气泡没有撤销，移动端工具栏有 |
| 粗体 | `**文本**` | `Ctrl/Cmd+B` | 已有；气泡有，无桌面常驻栏 |
| 斜体 | `*文本*` | `Ctrl/Cmd+I` | 已有；气泡有 |
| 标题 | `#`–`####` | `Ctrl/Cmd+1/2/3` | schema 只到 H4；H5/H6 会被桥降级，**不要**放进工具条 |
| 列表 | `-` / `1.` / `- [ ]` | 无统一 | 无序/有序/任务列表都有；合并为下拉 |
| 链接 | `[文本](url)` | `Ctrl/Cmd+K` | StarterKit 已带 Link mark，**没有 UI**；Markdown 桥支持；title 不承载 |
| 图片 | `![alt](url)` | 可选 | 自定义 `imageBlock`，走图片服务/仓库；目前是点块上传，没有粘贴/拖拽 |
| 行内代码 | `` `code` `` | `Ctrl/Cmd+E` | code mark 已有；气泡没有，工具条要加 |
| 溢出菜单 | — | — | 固定；收纳其余功能 |

### 2.2 溢出菜单中的常用扩展

| 功能 | Markdown 输出 | 分组 | 备注 |
|---|---|---|---|
| 删除线 | `~~文本~~` | 文本格式 | strike 已有；气泡可补 |
| 引用 | `>` | 块格式 | 已有 |
| 代码块 | ``` 围栏 | 块格式 | 已有 |
| 表格 | GFM 表格模板 | 插入 | 已有 3×3 插入；后续加网格选择 |
| 分割线 | `---` | 插入 | 已有 |
| 任务列表 | `- [ ]` | 列表扩展 | 已有 |
| H4 | `####` | 标题扩展 | 只在溢出；H5/H6 不做 |
| 查找 / 替换 | 编辑器能力 | 编辑辅助 | 目前没有，移植 Simple_Office |
| 下划线 | `<u>…</u>` | **OC 额外** | 现有气泡能力；不是 Markdown 核心，只在气泡保留，**不进常驻栏** |

### 2.3 明确不纳入

- 字符颜色、高亮、字体、字号、对齐、行距、段前段后、缩进、上下标、大小写、符号面板。
- 这些要么不是 Markdown，要么会逼出 HTML / `oc-document` 兜底块；与「文件是真源、未编辑的笔记零改动」直接冲突。
- 页面设置、缩放、打印、导出 PDF、docx 导入导出：属于文档/办公域，不属于 OC Studio 的笔记正文；后续若做，另开入口，不进正文工具条。

## 3. 分组与响应式

### 3.1 分组

| 组 ID | 组名称 | 包含 | 默认位置 |
|---|---|---|---|
| `history` | 历史 | 撤销、重做 | 常驻；撤销固定 |
| `text` | 字符格式 | 粗体、斜体、删除线、行内代码 | 粗体/斜体常驻；其余按断点 |
| `heading` | 标题 | 正文、H1–H3；H4 溢出 | 常驻下拉 |
| `list` | 列表 | 无序、有序、任务列表 | 常驻下拉；任务列表可溢出 |
| `quote-code` | 引用与代码块 | 引用、代码块 | 溢出 |
| `insert` | 插入 | 链接、图片、表格、分割线 | 链接/图片宽屏常驻；其余溢出 |
| `more` | 溢出 | 上述未显示项 | 固定，始终可见 |
| `find` | 查找替换 | 查找、替换 | 溢出或快捷键，不常驻 |

### 3.2 响应式（以**工具栏容器宽度**为准，不以窗口宽度）

| 断点 | 容器宽度 | 布局变化 |
|---|---|---|
| 宽屏 | ≥ 960px | 上述常驻集；标题、列表为下拉；链接、图片、行内代码可见 |
| 中屏 | 640–959px | 隐藏文字标签；标题/列表仍为下拉；链接、图片、行内代码进溢出；粗体、斜体保留 |
| 窄屏 | 480–639px | 仅撤销、粗体、斜体、更多常驻；其余全部溢出；启用选区气泡 |
| 手机 | < 480px | 撤销、粗体、更多常驻；斜体可进气泡/溢出；触摸目标 ≥ 44×44 |

- 折叠顺序（数字越小越先隐藏）：分割线 → 表格 → 图片 → 任务列表 → 删除线 → 引用 → 代码块 → 行内代码 → 有序列表 → 无序列表 → 标题 → 斜体 → 粗体 → 历史。
- 固定项不参与折叠：更多按钮、窄屏撤销。
- 以**组**为单位折叠，不按单个按钮逐个消失；避免字号/标签变化导致按钮反复进出溢出。
- 不建议把横向滚动当主策略。若用，必须有边缘渐隐/滚动指示。
- 实现上优先用 `ResizeObserver` 读容器宽度 + 组级 `data-overflow` 标记；不要用 `window.innerWidth`（编辑器可能在侧栏/分栏里，宽度与窗口无关）。

### 3.3 在当前 OC Studio 里的现实

- 当前正文是单栏 `max-w-3xl`（约 768px），工具条容器落在**中屏**：常驻只能放撤销/重做、粗体、斜体、标题、列表、更多。链接/图片/行内代码进溢出。
- 三栏布局的右栏在 1500px 窗口约 940px，落宽屏；1280–1499 约 880px，落中屏。工具条必须在两种容器宽度下都不跳。
- 移动端不要新写一套：继续用 `MobileEditorToolbar` + 移动端选词工具栏；本文件的手机断点是目标，不是第一版移植范围。

## 4. 溢出菜单与选区气泡

### 4.1 溢出菜单

- 容器 `MENU`（`py-1`，左右无内边距），行 `MENU_ITEM_BASE`（`px-3`、`py-1`），组间 `MENU_GROUP_LABEL`，可加一条 `border-t border-line` 分隔。
- 按功能域分组：文本格式（删除线、行内代码若未常驻）、块格式（引用、代码块、H4）、列表扩展（任务列表）、插入（链接、图片、表格、分割线）、编辑辅助（查找、替换、重做若未常驻）。
- 行内**图标 + 文字**；窄屏也不靠纯图标辨认。
- 菜单 Portal 到 `#overlay-root`；点外/Esc 关闭；关闭后焦点回到触发按钮或编辑器。

### 4.2 选区气泡

- 文本选区：粗体、斜体、删除线、行内代码、链接；**保留** OC 的 `@` 提及、`[[` 内链。
- 块级选区（NodeSelection）：转标题、无序/有序列表、引用、代码块。
- 气泡是窄屏/手机覆盖 90% 的关键：常驻栏可以很小，选中后高频操作仍一触可达。
- 现有 `BubbleMenuButtons` 已有粗体/斜体/下划线/`@`/`[[`；补删除线、行内代码、链接；下划线保持在气泡里，不进常驻栏。
- 链接浮层：
  - 输入 URL；**不做 title 输入**（Markdown 桥明确不承载 `link:title`，写了也会丢）。
  - 只接受 `http(s)` / `mailto` / `tel`；其它协议拒绝并就地提示。
  - 空值 = 移除链接；确定后焦点回编辑器。
  - 在 Tauri 里点击链接必须走 `openExternal`（`src/lib/open-external.ts`），不能靠 `<a target="_blank">`。

### 4.3 图片与表格

- 图片：保留现有 `imageBlock`（点击上传、裁剪、宽度拖拽）。后续从 Simple_Office 移植**粘贴/拖拽插入 + 最长边压缩**；不要移植它的页面宽度/打印逻辑。
- 表格：现有 `insertTable(3×3)`；后续做 8×8 或 10×6 网格选择，定位到首个单元格。表格增删行/列、合并/拆分放右键菜单或工具条的溢出，不占常驻。
- 代码块：围栏代码块；语言标识先不做输入框，避免多一层 UI；需要时再补。

## 5. 交互与状态

- **激活态**：光标在粗体/斜体/删除线/行内代码/链接/标题/列表内时，对应按钮或下拉显示激活。标题下拉显示当前块级别；列表下拉显示当前列表类型。
- **命令行为**：
  - 有选区：包裹/应用标记。
  - 无选区：字符格式先插入标记（或进入待输入状态），块级命令作用于当前段/选中段。
  - 撤销/重做交给编辑器历史栈，不手工反转字符串；工具条命令与手动输入统一进历史。
- **链接/图片弹窗**：关闭后焦点回编辑区；Esc 关闭；点外关闭。
- **溢出菜单**关闭后焦点回触发按钮或编辑区。
- **不变式**：
  - 不写 Markdown 表达不了的格式（颜色/字体/对齐等）。
  - 不新增 HTML 标签（下划线 `<u>` 是现有例外，只保留在气泡）。
  - 粘贴 HTML 先清洗：只保留 Markdown 能表达的结构与标记；丢弃颜色/字体/样式/脚本/非法 URL。Simple_Office 的 `sanitize.ts` 可作为参考，按 OC 的 schema 收窄。

## 6. 快捷键与冲突（OC Studio 必须现在定）

| 命令 | 快捷键 | 冲突 / 处理 |
|---|---|---|
| 粗体 | `Ctrl/Cmd+B` | **与三栏布局的「折叠左栏」冲突**。编辑区聚焦时粗体优先；左栏折叠改用 `Ctrl/Cmd+Shift+B` 或 `Ctrl/Cmd+\`。todo ① 里的 `⌘/Ctrl+B` 要改。 |
| 斜体 | `Ctrl/Cmd+I` | 无 |
| 链接 | `Ctrl/Cmd+K` | **与全局命令面板冲突**。建议：编辑器聚焦 → 链接；其它位置 → 命令面板。或命令面板改 `Ctrl/Cmd+Shift+P`。待拍板。 |
| 行内代码 | `Ctrl/Cmd+E` | 无已知冲突；注意别和系统输入法快捷键撞。 |
| 标题 1/2/3 | `Ctrl/Cmd+1/2/3` | 浏览器里会切标签页；编辑器聚焦时 `preventDefault`。Tauri 无标签页。 |
| 撤销/重做 | `Ctrl/Cmd+Z` / `Shift+Ctrl/Cmd+Z` | 无 |
| 查找 | `Ctrl/Cmd+F` | 浏览器查找；编辑器聚焦时拦截。 |
| 替换 | `Ctrl/Cmd+H` | 浏览器历史；编辑器聚焦时拦截。 |
| 保存 | `Ctrl/Cmd+S` | 已有应用级保存；工具条不抢。 |
| `@` / `[[` | 直接输入 | 不是工具条按钮；保留现有补全。 |

- 所有编辑器快捷键只在**编辑区聚焦**时拦截；焦点在输入框/弹窗/其它页面时保持应用原行为。
- 快捷键表最终以「命令注册表」为唯一源，避免工具栏、气泡、菜单三处各写一套。

## 8. OC Studio 落地约定

### 8.1 组件与文件

```
src/components/editor/
  EditorToolbar.tsx        # 壳：固定撤销/重做 + 分组 + 溢出按钮
  toolbar-registry.ts      # 组/控件/优先级/断点元数据（唯一源）
  toolbar-commands.ts      # 纯命令映射（editor.chain()...），工具栏/气泡/快捷键共用
  ToolbarButton.tsx        # 通用按钮：active / disabled / tooltip / 44px 触摸
  ToolbarMenu.tsx          # 下拉与溢出菜单（MENU / MENU_ITEM / 分组）
  LinkPopover.tsx          # 链接输入（URL only）
  FindReplaceBar.tsx       # 查找替换浮条
  useEditorToolbarState.ts # useEditorState 选择器 + ResizeObserver 容器宽度
```

- 工具条挂在**正文所在的那一栏**：三栏布局的右栏顶部；当前单栏编辑器里放在 `DocumentEditor` 正文上方。不要每个实体编辑器各写一套。
- 复用 `EditorCore` 的编辑器实例；工具条只接收 `editor`，不创建新实例。
- 三栏布局里的工具条是右栏的固定行（不随正文滚动），**不要**把 padding 加在滚动容器上（AGENTS §10）。
- 菜单/浮层 Portal 到 `#overlay-root`；移动端工具条继续用 `MobileEditorToolbar`。

### 8.2 样式与设计令牌

- 按钮/菜单/输入只从 `src/lib/ui-tokens.ts` 取：`ICON_BTN` / `ICON_BTN_MD` / `MENU` / `MENU_ITEM_BASE` / `MENU_ITEM` / `BTN_QUIET` / `BTN_PRIMARY` / `INPUT_LINE` / `ROUND_*`。
- 图标只用 `lucide-react`，`strokeWidth={2}`；折叠 `ChevronLeft`，展开 `Menu`，关闭 `X`，返回 `ArrowLeft`。
- 圆角只用 4/6/8；控件零描边；浮层只用 `FLOAT_SHADOW`；不写 `shadow-*`、不写 Tailwind 原色、不写像素圆角。
- 触控：移动端按钮 ≥44×44，桌面 24/28/32 三档；有边框的控件用 `touch-feedback`，无边框的用 `hover/active:bg-[var(--oc-hover)]`。
- 工具条高度与右栏页头一致（建议 40 或 48）；与编辑器内容之间只用一条 `border-line`。

### 8.3 数据与往返

- 所有命令必须落在 `MARK_NAMES` / schema 内；新增 mark/节点前先确认 `src/lib/vault/markdown/doc.ts` 与 `to-markdown.ts` 能表达。
- **当前 Markdown 桥的白名单**（`to-markdown.ts`）：
  - mark：`bold` / `italic` / `strike` / `underline` / `small` / `link`。
  - 节点：`paragraph` / `heading`（1–4）/ `blockquote` / `bulletList` / `orderedList` / `listItem` / `taskList` / `taskItem` / `codeBlock` / `horizontalRule` / `table` 系列 / `imageBlock`。
  - 其余节点或标记落 `hasFallback`，附 ` ```oc-document ` 兜底块。这是「做错会静默污染笔记」的唯一来源；加命令前先查这张表。
- 链接：`href` 会被序列化成 `[text](href)`；`title` 不支持（桥里有 `link:title` 的 unsupported 记录），浮层不提供 title。
- 下划线：序列化为 `<u>…</u>`；与「`<small>` 是唯一行内 HTML」的现状有张力，因此只保留在气泡，不进常驻栏，也不新增其它 HTML。
- 图片：`imageBlock` 的 `width` 不写回 Markdown（`imageBlock:width` 是已知 unsupported）；工具条不要新增会丢宽度的尺寸控制。
- 每次改工具条后跑 `npx tsx scripts/vault-markdown-check.ts "<vault>"`；没有 vault 时至少跑 `scripts/vault-migrate-check.ts` 的桥接自检。
- 不碰 `src/lib/vault/` 的写入规则；正文仍由 `getJSON()` + Markdown 桥落盘。

### 8.4 Simple_Office 移植清单

**移植（有用、且不破坏 Markdown）**

- 工具栏注册表 / 组级溢出 / 固定撤销 / 响应式断点（`formatToolbar.tsx`、`toolbarRegistry.ts`、`toolbarControls.tsx`）。
- 查找替换（`lib/findReplace.ts`、`findReplaceBar.tsx`）：每次按当前文档重算匹配、单事务全部替换、替换后选中下一处。
- 链接浮层（`linkPopover.tsx`）+ URL 白名单；OC 侧改成 `openExternal`、`PANEL`/`INPUT_LINE`、不加 title。
- 图片粘贴/拖拽 + 最长边压缩（`useImageDrop.ts`、`image.ts`）：接到 OC 的 `image-service` / 仓库，不接它的页面逻辑。
- 粘贴清洗（`sanitize.ts`）：按 OC schema 收窄，只保留 Markdown 能表达的结构/标记。
- 大纲（`outlinePanel.tsx`）：后续做成正文的侧栏/浮层，点击标题滚动；先不进第一版工具条。

**不移植（办公/非 Markdown）**

- 字体族/字号/颜色/高亮/上标/下标/大小写/对齐/行距/缩进/清除格式/符号面板。
- 页面设置、纸张、缩放、打印/PDF、docx 导入导出、`.sowd` 格式、自动保存模型。
- 它的顶栏/首页/路由/Dexie 存储（OC 已有自己的壳与仓库）。

**保留（OC 自有）**

- `@` 提及、`[[` 内链、`<small>`、图片块、表格、任务列表、details、拖拽手柄、斜杠菜单、移动端键盘工具栏、移动端选词工具栏、Markdown 桥、仓库保存/脏状态。

### 8.5 四个硬坑（审计结论，动手前先看）

1. **`#overlay-root` 的 pointer-events**：OC 的 `OverlayRoot` 是 `pointerEvents:'none'`，且 `globals.css` **没有** `#overlay-root > * { pointer-events:auto }`。照搬 `linkPopover` / `findReplaceBar` / 溢出面板会得到**点不动的死浮层**。所有新浮层必须显式 `pointer-events-auto`（现有 `BlockTypeMenu`、`SlashCommandMenu` 都这么写）。
2. **`sanitizeDocJson` 不能整段搬**：它的节点白名单不含 `mention` / `wikiLink` / `imageBlock` / `small`，整段套会删掉 OC 的引用与图片节点。只借 `safeHref` / `safeImageSrc` / `safeColor` 三个纯函数；真要清洗 doc，按 OC schema 另写白名单。
3. **没有 toast 体系**：源项目的 `onWarn` / `onResult` 要改成浮条内联提示（一行、≤20 字）或 StatusBar，不要引入第二套 toast。
4. **包与 API 差异**：OC 用 TipTap 3.22，源用 3.31；`text-align` / `color` / `text-style` / `image` / `character-count` **未安装**。本最小集不需要它们（Link 已由 StarterKit 带），但做排版类扩展前要先装包并核对导出。新增组件全部 `'use client'`，编辑器实例只能走 `buildEditorConfig`，不要另起 `new Editor()`。

### 8.6 出处与许可

- 两个仓库同作者、同 MIT（Copyright (c) 2026 Pokanshu），跨项目复制无授权障碍。
- 搬运具体文件时保留文件头来源注释；若复制了成段代码，在 `src/components/settings/credits.ts` 的「编辑器与文档」组补一条。
- 不要引入 TipTap Pro（跟踪更改/批注）：源项目未用，本最小集也不需要。

### 8.7 建议施工顺序

1. **查找替换**（零风险、可独立验收）。
2. **链接浮层 + safeHref + `openExternal`**（零风险，Markdown 桥已支持 link）。
3. **工具栏骨架**（注册表原样复制，渲染层重写；先只挂 OC 已有能力：撤销/重做、段落/H1–H4、粗体/斜体/删除线/行内代码、列表/任务、引用/代码块、链接/图片/表格/分隔线、更多）。
4. **大纲 / 图片粘贴拖拽**（并行）。
5. **排版类**（对齐/行距/字体/颜色/高亮/上下标）等 Markdown 桥扩完再做；否则先不做。
