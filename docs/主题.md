# 主题

> 主题 = **界面外壳的皮肤**，不是换一套 CSS。能换的是皮，不是骨。
> **v1 已落地**：4 套官方主题（只换亮暗纸色 / 墨色 / 线色），设置 › 个性化 › 纸色。

---

## 0. 一句话

**机制上分三层（令牌 / 材质 / 结构），作用域上分两级（应用 / 页面）。**

---

## 0.1 作用域分两级（关键）

| 级别 | 换什么 | 存在哪 | 例子 |
|---|---|---|---|
| **应用级** | 外壳：菜单栏 / 侧栏 / 状态栏 / 内容面板 / 背景 | 应用设置（每台机器一份） | 暗色木桌；全屏背景图 |
| **页面级** | 实体页的背景、卡片底、强调色 | **模板挂主题 id**（随库走） | 「不同国家的角色用不同背景」 |

两级可以组合：外壳是深色木桌，页面是一张纸；或者外壳是纸，页面是一张照片。

**为什么必须分开**：外壳是你坐在哪儿写，页面是你在写什么。把两者塞进一个"主题"，就会出现"换了个国家背景，菜单栏也跟着变了"。

---

## 1. 三层

| 层 | 内容 | 开放程度 |
|---|---|---|
| **令牌** | 色值（paper / ink / line / hover / scrim / danger）、强调色 | **全开放**，但导入时校验对比度 |
| **材质** | 表面材质（纯色 / 渐变 / 模糊 / 背景图）、边线有无、密度（紧凑 / 宽松） | **开放**，但提供预设；背景图强制带遮罩 |
| **结构** | 外壳排布：侧栏位置、菜单栏形态、内容区是否卡片化 | **不开放**。只给 2–3 套内置"外壳样式"（纸 / 玻璃 / 极简） |

**结构不开放的理由**：结构一旦自由，每加一个组件就要在所有外壳形态下测一遍；而且它会让"侧栏 / 内容面板 / 浮层"的层级关系失控——现在那套"一块 `bg-paper` + 一条 `border`"的规矩正是靠结构固定才成立的。

### 1.1 官方主题 = 内置的自定义主题

**官方主题不是另一套实现，就是几份 `theme.json` 放在内置目录里。**

| | 官方主题 | 用户主题 |
|---|---|---|
| 数据结构 | `theme.json` | `theme.json`（同一份） |
| 加载路径 | 内置目录 | 导入 / 用户目录 |
| 能改的层 | 令牌 + 材质 | 令牌 + 材质 |
| 能否覆盖结构 | 不能 | 不能 |

一旦官方主题走"硬编码一套、用户主题走另一套"，两边就会开始互相追赶——所以第一天就要同构。**内置主题是你允许的最大自由度的示范**，它自己先守规矩。

### 1.2 令牌必须声明归属（这是"不打架"的制度保证）

每个令牌新增时必须在 `globals.css` 里登记它属于哪一类，否则主题系统无法安全地做作用域：

| 归属 | 令牌 | 谁能改 |
|---|---|---|
| `shell` | 外壳底色、菜单栏 / 侧栏 / 状态栏表面 | 应用级主题 |
| `page` | `--oc-paper` / `paper-alt` / `paper-card` / `ink*` / `line*` / `hover` / `scrim` | 应用级 + 页面级 |
| `both` | 危险色、强调色 | 都行，页面级覆盖应用级 |

**强调色板已落地 12 档**：`--oc-accent-1..12`（`globals.css`，亮暗各一套，每档在对应底色上 ≥ 4.5:1）。目前只给关系图连线用（关系名与线条同色），按主题规则属于 `page` 级；时间线 / 统计图要用时直接取同一份，不另建色板。取色入口是 `src/lib/relation-colors.ts`，组件不许写裸色值。

**页面级主题只能改 `page`，碰不到 `shell`。** 这就是"换了个国家的背景，菜单栏不会跟着变"的机制保证——靠的是分组，不是靠自觉。

### 1.3 放开节奏

| 阶段 | 给用户什么 | 风险 |
|---|---|---|
| **v1** | 3–5 套官方主题，只换**颜色 + 背景** | 低。机制先跑通，用户先有选择 |
| **v2** | 开放编辑：色板 / 背景图 / 边线有无 / 密度 | 中。要对比度校验与预设兜底 |
| **v3** | 主题包导入导出、社区分享 | 中高。要 scope 校验 + 版本兼容 |
| **不做** | 结构（侧栏位置、菜单栏形态、内容区卡片化） | — |

每一档都是**在上一档的同一份数据结构上放宽字段**，不是换实现。

### 1.4 v1 已落地（2026-11-05）

**颜色 + 背景图 v1 都已落地**：先把「令牌 → 数据 → 界面」这条链跑通；背景图的随库存储（`.ocstudio/backgrounds/`）与主题包留给下一档。

| 项 | 落点 |
|---|---|
| 主题数据 | `src/lib/theme/presets.ts`：`ThemePreset { id, name, scope, tokens: { light, dark }, preview }`，4 套（纸白 / 亚麻 / 松烟 / 青瓷）亮暗各一套 |
| 应用主题 | `src/lib/theme/apply.ts#applyThemePreset(id, isDark)`：往 `<html>` 写行内 `--oc-*` 变量 + `data-palette`，亮暗切换时重落一遍 |
| 首帧 | `src/lib/theme/boot.ts#THEME_BOOT_SCRIPT`：`layout.tsx` 的 `<head>` 里同步读 localStorage，先落亮暗 class 与纸色，避免首帧闪回默认纸白 |
| 设置 | `Settings.themePreset`（localStorage，非法值回落 `paper`）；设置 › 个性化 › **纸色**（`ThemePresetRadio`，一块「纸 + 两行墨」的小样） |
| 背景图 | `src/lib/theme/background.ts`：压缩（长边 ≤ 2560 WebP）→ Tauri 写 `.ocstudio/backgrounds/`（浏览器 Mock 用 data URL）→ `html.oc-background` 铺图 + 纸色 wash；外壳 35% 纸色；填充 / 平铺 / 固定；遮罩 20–80%；有图时强制关 Mica |
| 自检 | `npm run audit:palettes`：4 套 × 亮暗 × 7 项对比度 + 坏值回落，退出码非 0 即失败 |

**v1 只覆盖 `page` 令牌**（纸 / 卡片 / 线 / 墨 / 悬停），`shell` 与结构不开放；组件仍然只认令牌，所以换主题不需要改任何组件。**静态站与图片导出都已消费这套主题**：静态站传 `SiteThemeTokens`，模板海报直接读 `--oc-*`；见 §5。

`ThemePreset` 是将来 `theme.json` 的**子集**：多了 `tokens.light/dark` 与 `preview`，少了 `material` / `background` / `author` / `version`。下一档只加字段、不改 `applyThemePreset` 的调用方式；背景图暂存应用设置（data URL），还不是 `theme.json` 的一部分。

## 2. 材质层：背景图是重头

| 项 | 定法 | v1 现状 |
|---|---|---|
| 存储 | `.ocstudio/backgrounds/`（随库走，不是应用设置） | 已做：Tauri 写 `.ocstudio/backgrounds/background-<时间>.webp`，设置只存相对路径；浏览器 Mock 退化成 data URL |
| 处理 | 上屏用压缩版（长边 ≤ 2560、转 WebP），**原图不进界面** | 已做（`compressBackgroundImage`，同时返回字节给落库） |
| 遮罩 | 背景图上**强制**一层 wash，强度可调但有下限（可读性优先） | 已做：纸色 wash 20–80%，默认 35%；外壳另盖 35% 纸色 |
| 与 Mica | 设了背景图 → 窗口模糊让位（两者只能取一个） | 已做：设图即关 Mica，`BlurEffect` 初始化也跳过 |
| 定位 | 居中填充 / 平铺 / 上下固定（内容滚动时背景不动） | 已做：填充 / 平铺 / 固定 |
| 移动端 | 允许，但默认关（耗电） | 未单独验证（本轮只打磨桌面） |

**v1 的边界**：背景图只铺在 `<html>` 上，菜单栏 / 侧栏 / 状态栏透出 35% 纸色 + 图，内容区仍是 `bg-paper` 的纸；所以图主要在外壳上可见，不会穿到正文后面。`backdrop-filter` 没有加 —— 实测 WebView2 里它会把 html 背景采样成白色，图直接消失。

## 3. 组件契约（新增一条硬约束）

每个组件必须能在**任意主题 + 任意背景**下可读：

- 只用令牌，不写死色值（`npm run audit:design` 已经在管）
- **不许假设背景是纯色**：卡片 / 浮层的半透明底（`bg-paper/85` + `backdrop-blur`）在图片背景上要能读，靠 `--oc-scrim` 保底
- 固定底色上的文字继续用 `text-ink-fixed` / `text-paper-fixed`

---

## 4. 强调色是新增项

现在全站以墨色为主。`--oc-accent` 先只在**图表 / 时间线 / 关系图**里开放；界面控件不开放——否则"一屏不该出现第二块深色"和"选中 = 浅底块"两条规矩同时失效。

---

## 5. 导出与主题

**导出必须用同一套主题渲染**，否则所见非所得。

- 图片导出：用当前页面级主题
- 静态站：用应用级主题，但给一个「强制纸色」选项（更保险、更耐看）
- 打印：强制纸色

**现状（v1）**：静态站已接（`SiteExportDialog` 传 `SiteThemeTokens`，注入 `--paper` / `--ink` 等令牌；「强制纸白」就是纸白主题的亮色令牌）。模板海报导出也已接：`TemplatePoster` 是真实 DOM，直接读 `--oc-*`，截出来的图跟界面同一套纸色。角色卡 / 整图导出还没做。接的时候只传令牌值进去，别把 `presets.ts` 整份塞进导出器。

---

## 6. 主题包

```
theme.json
├─ id / name / author / version / scope: app|page
├─ tokens:   { paper, ink, line, hover, scrim, accent }
├─ material: { surface: solid|gradient|blur|image, lines: on|off, density }
├─ background: { image, mode, scrimStrength }
└─ preview.png
```

导入校验：颜色格式、**对比度阈值**、资源大小、版本、`scope` 与安装位置是否匹配（页面级主题不能装到应用级）。

---

## 7. 前置与风险

**前置**：`globals.css` 的令牌体系（已有）、`settings.tsx`（已有）。**不依赖模板**——应用级主题可以先做，页面级等模板的「挂主题 id」落地。

| 风险 | 说明 |
|---|---|
| **性能** | 背景图 + `backdrop-blur` 在 Windows WebView2 上代价很高。要么限制模糊区域，要么有背景图时关掉 blur |
| **对比度** | 社区主题最常见的翻车点，导入必须算 |
| **Mica** | 与背景图互斥，做成"二选一"，不能叠加 |
| **安全** | 禁止任意 CSS / JS，只能填值；`scope` 不许越权 |
| **导出保真** | 主题一旦参与渲染，导出的图片 / 静态站就必须用同一套，否则用户截图和导出对不上 |

---

## 8. 工程量

比"换几个色值"大得多，**跟时间线同级**：令牌 + 材质 + 背景图管线（压缩 / 缓存 / 遮罩）+ 主题包 + 对比度校验 + 导出保真。

**已完成（v1）**：令牌归属登记（`audit:theme`）+ 4 套官方主题（颜色）+ 亮暗对比度自检（`audit:palettes`）+ 静态站 / 模板海报消费主题令牌 + **背景图 v1**（压缩 / 随库 / 三种铺法 / 纸色 wash / Mica 互斥）。**未完成**：材质（边线 / 密度）、外壳样式、用户主题导入、页面级主题、角色卡 / 整图导出。

可以拆：**应用级主题（外壳 + 背景）先做，页面级（模板挂主题）跟着模板走**。
