# 组件开发指南（模板系统实现契约）

> 面向「以后还要加组件」的人。读完这一篇应该能回答三件事：
> **一个组件由哪些层组成、加一个组件要动哪些文件、哪些红线踩了会被审计拦下。**
>
> 设计取舍的历史在 [`docs/模板.md`](模板.md)（§1–§14）；这里只讲**现在的实现与扩展流程**。
> 有出入时以代码 + `npm run audit:templates` 为准，然后把两边改一致。

## 0. 一句话模型

**模板 = 有序的组件列表（id + 开关 + 参数）**；**组件 = 一个数据槽位 + 一套渲染**；
**组件库（InfoGroup / BodyGroup）= 可复用的一份字段或骨架**，模板只存「选了哪一个」。

数据始终写实体自己的列 / `custom`，模板只决定**怎么拼**。同一份数据只有一个入口。

## 1. 分层与文件地图

| 层 | 文件 | 职责 | 不做什么 |
|---|---|---|---|
| 类型 | `src/lib/templates/types.ts` | 组件 id 闭集、`TemplateDoc`、`TEMPLATE_SCHEMA_VERSION` | 不 import React |
| 登记 | `src/lib/templates/registry.ts` | 每个组件的 id / 中文名 / 级别 / 参数键 / 备注 | 不做渲染 |
| 参数契约 | `src/lib/templates/params.ts` | 每个参数的类型、默认值、可选值、**消费方白名单** | 不写界面 |
| 宿主接线 | `src/lib/templates/support.ts` | `WIRED_BY_TEMPLATE`：每个宿主能用哪些组件（也是「添加组件」菜单） | 不判断数据 |
| 笔记宿主 | `src/lib/templates/note.ts` | `NOTE_COMPONENT_IDS` / `isNoteTemplate` / 单篇模板候选 | 不碰渲染 |
| 内置默认 | `src/lib/templates/defaults.ts` | 六个内置模板的组件顺序 / 开关 / 默认参数 | 不写用户数据 |
| 读写 | `src/lib/templates/store.ts` | 盘 ⇄ 内存、`useTemplates()`、参数写回、**旧版本一次性升级** | 不写界面 |
| 序列化 | `src/lib/templates/serialize.ts` | frontmatter ⇄ `TemplateDoc`（`版本:` / `组件:` / `参数:`） | 不校验业务 |
| 字段键 | `src/lib/templates/fields.ts` | 模板 → 基本信息字段键（笔记组件） | 不画控件 |
| 渲染循环 | `src/components/shared/TemplateRenderer.tsx` | 按顺序调用宿主渲染器、分隔线、头像叠封面、悬停设置键 | 不认识实体类型 |
| 呈现块 | `src/components/shared/template-blocks/` | 无数据库依赖的区块（简介 / 画廊 / 图片 / 头像 / 动画）+ `shared/TimeTrio.tsx`（时间三段） | 不直接写库 |
| 宿主渲染器 | `characters/.../CharacterFrontmatter`、`events/.../EventFrontmatter`、`countries/.../CountryFrontmatter`、`world/components/note/NoteTemplateContent` | 组件 id → 数据映射 + 写回调 | 不重复抄呈现块 |
| 设置面 | `TemplatesPanel` / `TemplateComposer` / `TemplateParams` / `TemplateParamPanel` / `BasicInfoPanel` / `BodyPresetPanel` / `ComponentsPanel` | 编排、参数、组件库 | 不自己发明参数 |
| 审计 | `scripts/templates-check.ts` | 层与层之间的一致性 | — |

界面上的「组件块」一律经 `ComponentSection`（标题行 / 动作 / 分隔线 / 悬停 ⚙）；
**间距只由外层 `gap-8` 给，组件自己不带 margin**。

## 2. 一个组件的契约

```ts
// registry.ts —— 加组件第一步
{ id: 'example', label: '示例', level: 'block', params: ['title', 'label'], note?: string }
```

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 模板文件里存的键 | **闭集、稳定、不可改名**；改名等于删掉旧组件（旧模板会丢这一块） |
| `label` | 设置界面上的名字 | 只影响界面，不写文件 |
| `level` | `block` / `atom` | atom 只活在 group（基本信息）内；当前没有登记为 atom 的组件，字段是 info 内部的 atom，不进闭集 |
| `params` | 允许的参数键 | 必须与 `params.ts` 的 schema 一致，否则审计报 |

**参数**（`params.ts`）只有四种 `kind`：

| kind | 用途 | 界面 |
|---|---|---|
| `choice` | 分段按钮（模式 / 列数 / 显隐） | 编排行内联 |
| `text` | 文本（`label` 标题文案；正文预设） | 行内展开输入框，失焦保存 |
| `group` | 选组件库的一份（`info.group` / `body.group`） | 单选列表 + ⚙ |
| `fields` | 旧版内联字段（只读兼容） | 只在「存为组件」出现 |

每个参数必须**真有人读**：`choice` 用 `componentParam(component, '<key>', fallback)`，
`label` 用 `componentLabel(component)`。渲染器不得自己写死默认值（默认值只在 schema 里）。

## 3. 现有组件总表（11 个）

> 「数据」列是落盘列 / frontmatter 键；「渲染」列是对应的实现文件。
> 宿主缩写：C 角色 · E 事件 · N 国家 · Note 词条 / 分类条目 / 宠物 / 武器 / 自建模板。

| id | 名字 | 宿主 | 数据 | 参数 | 渲染 | 备注 |
|---|---|---|---|---|---|---|
| `cover` | 封面 | C/E/N/Note | `header`（实体）/ `cover`（笔记） | — | `ProfileBannerEditor` / `WorldCoverField` | 3:2、贴顶、后方不画线 |
| `avatar` | 头像 | C/N/Note | `avatar` / `flag`（N）/ `avatar`（Note） | — | `AvatarBlock` | 紧跟封面时叠在横幅下缘；封面不再自带头像 |
| `info` | 基本信息 | C/E/N/Note | 标题 + 各宿主字段（见 §4） | `group`（仅 Note）、`fields`（旧） | `CharacterInfoSection` / `EventInfoSection` / N 名称输入 / `WorldCustomFields` | 标题也在这一块；模板没有它时标题兜底 |
| `relations` | 关系 | C/E/N/Note | `relations`；N 是派生；Note = 命名边 + `parentId` + 引用 | `presentation`（表 / 紧凑 / 图）、`title`、`label` | `RelationsSection` | 呈现写**模板**，同类条目一起变；图只读 |
| `tags` | 标签 | 全部 | `tags`（标签 id 数组） | — | `TagsSection` / `WorldMetaFields` | 管理在 设置 › 世界 › 标签 |
| `image` | 图片 | Note | `image` | `width`（全 / 半）、`title`、`label` | `ImageBlock` | **仅笔记宿主**，单张 |
| `gallery` | 画廊 | 全部 | C `gallery` / E `images` / N `gallery` / Note `gallery` | `mode`（网格 / 滑动）、`columns`、`title`、`label` | `GalleryBlock` | 标题文案默认按宿主；图注字段预留 |
| `portrait` | 立绘 | C | `avatars[]`（9:16） | `label` | `GalleryBlock`（portrait 参数） | **角色专属**，与画廊是两个槽位 |
| `animation` | 动画 | C | `animation`（视频路径） | `label` | `AnimationBlock` | **角色专属**，移除只解除引用 |
| `summary` | 简介 | 全部 | C `bio` / E `summary` / N `description` / Note `summary` | `title`、`label` | `SummaryBlock` | 纯文本；老 HTML 展示前过 `plainTextOf` |
| `body` | 正文 | 全部 | `document`（Note 老数据兜底 `content`） | `group`（正文组件库） | `DocumentEditor` / 各宿主 body 节点 | 无标题行；骨架只铺新条目 |

**宿主可用性**（`support.ts` / `note.ts`）：C = 除 `image` 外全部；
E = 无 `avatar` / `portrait` / `animation` / `image`；N = 无 `portrait` / `animation` / `image`；
Note = 11 − `portrait` / `animation`。加组件时**先想清楚数据槽位在不在**，再改这张表。

> **时间 / 地点不在组件闭集里**（2026-11-10）：它们是基本信息里的**特殊字段行** ——
> 事件在字段表（`lib/fields` `type` 按 id 特判），词条在 `InfoGroup.types` 的
> `time` / `timeEnd` / `place` 三种特殊类型；值写 `time` / `endTime` / `location` 列。
> 别为了加「可以排序的时间块」把它们再做成组件：同一份数据两个入口，模板开关一漂就回到原来的 bug。

## 4. 基本信息（info）的特殊性

- 它是**唯一带 atom 编排的 group**，但各宿主实现不同：
  - 角色 / 事件：字段表在 `lib/fields`（全局），模板只是引用；控件由内置字段类型决定。
  - 国家：名称 + 自建字段（字段表在 `lib/fields`，值落 `Country.custom`；体制 / 地理 / 文化在正文里）。
  - 笔记：字段来自**选中的 `InfoGroup`**（`info.params.group`），值落 `WorldEntry.custom`；
    没选组件时回落到字段表里的自建字段；两者都没有就只显示标题。
    其中 `time` / `timeEnd` / `place` 三种**特殊类型**写实体列、不落 `custom`（每种最多一行）。
- `InfoGroup` 存 `.ocstudio/info-groups.json`，内置宠物 / 武器；列型宿主（角色 / 事件）的组只是字段表投影，
  **选择器只对笔记宿主开放**，实体宿主跳字段表走编辑器标题行的悬停 ⚙。
- 空组件 / 空字段表给一句提示，并保留跳组件的设置键；不要留只有标题的空壳。

## 5. 新增一个组件：清单

以「地图缩略」这类组件为例，**按顺序**做（少一步审计会报）：

1. **定槽位**：数据放哪？已有列能复用吗？要不要新列 → `src/types`、`src/lib/vault/fields.ts`（键链）、
   `scan.ts` / `serialize.ts`（读写）、`.ocbak` / agent 白名单（如果需要）。
   规则：**能算出来的不存**；同一事实不能有两处写。
2. **类型**：`types.ts` 的 `TemplateComponentId` union 加 id。
3. **登记**：`registry.ts` 加 `label` / `level` / `params`。
4. **参数**（可选）：`params.ts` 的 schema 加 def；同时登记消费方：
   `TEMPLATE_PARAM_SUPPORT`（实体宿主）或 `TEMPLATE_PARAM_ANY_NOTE`（笔记宿主）。
5. **宿主接线**：`support.ts` 的 `WIRED_BY_TEMPLATE`；笔记宿主还要看 `note.ts` 的 `NOTE_COMPONENT_IDS`。
6. **内置默认**：`defaults.ts` 里该有的内置模板补上；**加到既有模板默认值时必须升
   `TEMPLATE_SCHEMA_VERSION` 并在 `store.ts` 写一次性补齐**（未改过的换新默认、改过的只做加法）。
7. **渲染**：每个可用宿主加 `case '<id>'`：
   - 无数据库依赖的呈现 → 新 `template-blocks/` 块（props 进、回调出），再在宿主 case 里映射数据；
   - 标题走 `ComponentSection`，标题显隐读 `title`、文案读 `componentLabel`；
   - 空态只留标题行 + 一个动作，不画虚线框、不写「暂无」。
8. **设置面**：新参数如果是 `choice` 自动出现在编排行；`text` 走通用输入框；
   `group` 需要自己的选择器（参考 `InfoGroupPicker` / `BodyGroupPicker`）。
   有组件库的块再在 `edit-target.ts` 给悬停 ⚙ 的目标（只给「编辑这个组件」）。
9. **导出 / 站点**（可选但推荐）：组件有内容的话，在 `lib/export/site/build.ts` 的
   `siteTemplateView`（标题 / 显隐 / **顺序**：内容区块经 `joinByTemplateOrder` 按组件顺序排）或
   `lib/export/poster/options.ts` 的 `posterTemplateDefaults`（海报默认块与顺序）里登记映射；
   没登记 = 导出物里看不到它，这是有意的边界，不是 bug。
   审计：`npm run audit:site` / `npm run audit:export`。
10. **审计**：`npm run audit:templates` 至少会查：登记 ↔ schema 一致、每个 id 在宿主渲染器里有 `case`、
   笔记闭集、参数有消费方、模板往返、旧版本升级。其他：`audit:export` / `audit:site` / `audit:capabilities`。
11. **文档**：`docs/模板.md` 的 §4 清单 + §6 视觉规格 + 本文件 §3 总表；CHANGELOG 一条人话。
12. **验证**：`npx tsc --noEmit`、`npm run lint`（0 error）、`npm run build`、相关 audit。

**新增组件绝不能做的事**

- 不给组件加平台分支（macOS / Windows / 移动端同一套交互，hover 与长按各归各家）。
- 不在渲染器里写死标题文案（用 `label` 默认值）；不在组件里带 margin（间距归壳）。
- 不让参数「能配但没人读」；不让选择器「能选但不生效」；不造第二份真源。
- 不把组件 id 当数据键写进 frontmatter（文件里只存模板名 / 组件参数，槽位键另算）。
- 不把角色专属组件塞进笔记宿主（笔记没有对应列，渲染会静默跳过 —— 审计会拦）。

## 6. 兼容与迁移

| 场景 | 规则 |
|---|---|
| 新增组件、旧模板没有它 | **加法升级**：按 `版本:` 一次性补（`store.ts` 的 `upgradeLegacyTemplate`），补完写回新版本 |
| 用户删掉组件 | 下次保存写 `版本:`；之后不再加回来 |
| 参数改制（布尔 → 文本等） | 新键并存、旧键只读；渲染器优先新键，读侧不认识的值回落默认 |
| 退役组件 | id 从闭集移除 + 旧模板读回时跳过；**数据列保留**，不删值。序列化侧用 `LEGACY_COMPONENT_IDS` 放行旧 id，让升级逻辑能看见它们（否则解析阶段就静默丢了）。时间 / 地点 2026-11-10 就是这么退的：事件补字段表行，词条把特殊字段补进模板当时选的基本信息组件（`queueSpecialInfoFields`） |
| 字段表改版 | 字段表文件有 `version`（当前 2）：退役又收回的内置字段按版本**一次性**补回；补完写新版本，用户再删不会被加回来（`lib/fields/store.ts` 的 `upgradeFieldConfig`） |
| 笔记模板 / 分类绑定 | `isNoteTemplate` 按宿主收窄；已绑定的旧模板仍能打开，缺失块跳过 |

模板文件当前结构（`版本: 3`）：

```md
---
id: character
名称: 角色
版本: 3
组件:
  - id: cover
    开: true
  - id: avatar
    开: true
    参数:
      label: 头像
---
```

## 7. 审计把什么钉住了

`scripts/templates-check.ts`（`npm run audit:templates`）：

- 组件闭集 ↔ 参数 schema ↔ 登记表一致；内置模板有 `body`、无未知 id、可无损往返。
- **每个 id 在对应宿主渲染文件里真有 `case`**（防「开关能开、画不出来」）。
- **每个 `choice` 参数都有 `componentParam` 读取、`label` 有 `componentLabel` 读取**（防「配了没反应」）。
- 笔记组件闭集不含角色专属组件；角色模板不被当成笔记模板。
- 图片槽位 / 宿主可用性 / 单篇模板候选（`perNoteTemplates` 排除角色 / 事件 / 国家）。
- 旧版本一次性升级的行为（未动过的换默认、动过的只补、已升级的不再补）。

## 8. 还有哪些已知边界

- 静态站详情页的**内容区块**（图集 / 关系 / 正文等）按模板组件顺序排；页头、导航、路由与
  站点版式骨架仍是站点自己的（它们是另一层"版式模板"）。导出卡（海报）首次默认跟随模板，
  之后以用户保存的导出配置为准。
- 画廊图注 `caption` 是预留字段，未展示 / 未编辑。
- 关系呈现是模板级：改一篇会改所有同模板条目（文档已写明，界面只给了 tooltip）。

> 改这个系统之前先读 [`docs/模板.md`](模板.md) §1.4 / §8；加组件按本文 §5 走；
> 如果发现某一步和现实不符，**先改文档再改代码**，别让下一任维护者再猜一次。
