- [ ] **P2 清理未引用的图片**：现在**永久删除一个角色，它的头像 / 立绘 / 相册图仍然留在库里**（软删不动图是对的 —— 恢复后封面照旧；但永久删就只回收了 md 与回收站文件）。命名、位置、是否算「未引用」都还没定，见决策 1.8；倾向「不自动删，给一个可复核的清理入口（列表 + 确认 + 报告）」
- [ ] **P2 长列表虚拟滚动**：400 个角色时角色画廊首屏 **2.6s**、约 3 万 DOM 节点；搜索框已改成防抖（单键 250–1250ms → 0–1ms），但**首屏仍卡在 DOM 创建**上，加 memo 边界也不够（卡片 props 里有内联 JSX）。要真正解决得在 `CoverFlow` / 表格里做窗口化（或每屏 120 条 + 「加载更多」）。封面卡的「进视口才画」已经改成全站共用一个 IntersectionObserver（`cover/cover-visibility.ts`），那部分不再是瓶颈。关系图与时间线已经改成**第一次看到时才挂载**（`lib/use-visited-once.ts`）：开机 DOM 从 3.2 万降到 2.8 万，这两个重视图各约 3 秒的代价挪到了用户真正打开它们的时候；它们**自身**在大库下的画布开销仍未做窗口化。角色画廊与表格同样改成了首次可见才挂载（`use-visited-once.ts`，开机 DOM 2.8 万 → 1.1 千、落地 386ms）。**还没解决的是「来回切」**：已挂载的重视图会随父组件重渲染（卡片 props 里有内联 JSX，`memo` 挡不住），在角色与表格之间切一次约 1.5s。**注意：这个数字是 dev 模式量的** —— CPU profile 显示其中大头是 `jsxDEVImpl` / 属性校验（Next dev 特性），生产构建低一个量级。memo 边界已经加上（`MemoCharacterList` / `MemoTreeTable`，表格的 `onNavigate` 也提成了 `useCallback`），但**dev 里验不出收益**；以后要证明这类改动，得对着 `next build && next start` 的生产构建量，别再拿 dev 数字下结论
- [ ] **P3 开机自启动**：设置里那个开关以前是**拨了没反应**（只写 localStorage，没人调系统接口），2026-11-11 已改成灰掉的「暂未实现」。要真做：`tauri-plugin-autostart`（写 `HKCU\…\Run`）对**打包版无效** —— MSIX 里 Run 键会被虚拟化，得在清单里声明 `StartupTask`，并配套一个「在系统设置里打开」的按钮。别只装插件就当完成，那会变成「拨亮了但不自启」的第二次静默失败
- [ ] **P3 从相册拖到编辑器**：现在只能从相册「保存到…」；缺按住缩略图直接拖进正文成为图片块
- [ ] **P3 可访问性全量**：焦点环已有 `audit:design` 的 `focus-ring` 规则兜底；缺的是全站 Tab 链不断、`aria-*`、主题对比度校验
- [ ] **P3 灵感删除的可恢复性（确认窗已加）**：确认窗已于 2026-11-13 加上（`AlertDialog` + `BTN_DANGER`，文案说明「没有回收站、不可恢复」）；灵感现在仍是**永久删除**，没有撤销。要做可恢复，先定「删除后 5 秒撤销」还是「进回收站」—— 灵感不是实体，现有回收站只收实体，直接塞进去会多一套生命周期。
