# 计划：编辑体验现代化（模板 / 组件四期）

> **已归档 2026-11-10** —— 四期全部完成（W1 标题文案 / W2 立绘与动画组件化 / W3 国家字段 / W4 导出与静态站消费模板参数）。
> 现在的组件模型与参数契约见 `../模板.md`，组件闭集清单见 `../组件开发指南.md`。

> 起于 2026-11-09。目标不是再补几个开关，而是把「模板 = 组件编排」这套模型补成
> 能长期演进的一代：每个能力都有归属、都能被模板控制、导出与编辑器讲同一套话。
> 全程**零破坏**：旧库、旧模板、旧备份、Windows / 移动端行为都不能变。

## 不变量（四期都要守）

1. **数据不动**：只改「组件模型 / 渲染 / 参数」，不改已有列的含义与落盘键。新字段一律加列或复用 `custom`。
2. **旧模板能读**：参数值兼容旧形态（布尔 / 字符串 / 数字），不认识的值回落默认，不报错、不丢。
3. **归属唯一**：一份数据只有一个入口；不允许「配了不显示」「显示的不在设置里」。
4. **设计纪律**：`ui-tokens`、三档圆角、零阴影、文案节制、悬停只给「编辑这个组件」。
5. **每个能力三件套**：能配（设置面）、能生效（渲染器）、能被审计发现漂移。
6. **平台中立**：不新增平台分支；macOS / Windows / 移动端同一套交互（hover 与长按各归各家）。

## 四期

### W1 标题参数文本化（先做，收益面最大）

**问题**：`title` 现在是布尔（显示 / 隐藏），区块标题文案写死在宿主里（相册 / 图片 / 画廊 / 关系…）。
用户改不了「相册」叫「照片」、「关系」叫「人物关系」。

**做法**：

- 每个有标题行的组件加参数 `label`（`kind: 'text'`，空 = 用默认文案）；旧的 `title` 布尔继续管显隐。
- 设置面：模板行展开 → 「标题文案」输入框（失焦 / 回车保存，清空恢复默认）；编排层抽屉同一份。
- 渲染：`RelationsSection` / `GalleryBlock` / `ImageBlock` / `SummaryBlock` 接受 `title` 文本，
  宿主把 `label` 传进去；标签块不加（它固定叫标签）。
  （时间 / 地点 2026-11-10 并回基本信息后不再是组件，`label` 改由字段表的显示名承担。）
- 审计：`label` 必须真有 `componentParam(..., 'label')` 读取（沿用「参数必须有人读」的断言）。

**验收**：任一模板块改标题立即生效并落模板文件；清空恢复默认；旧模板（只有布尔）行为不变；
`audit:templates` 通过；导出/站点暂不受影响（见 W4）。

### W2 立绘 / OC 动画组件化

**问题**：立绘（`avatars[]`，9:16）和动画（`animation`，视频）硬编码在角色「基本信息」里，
不能关、不能调序，动画连组件登记都没有。

**做法**：

- 组件闭集新增 `portrait`（立绘，9:16 图集）与 `animation`（视频槽），**仅角色宿主**。
- 立绘/动画从 `CharacterInfoSection` 移出，变成 `template-blocks` 里的独立块；角色默认模板补上
  `cover, avatar, info, portrait, relations, tags, gallery, summary, animation, body` 之类顺序。
- 宿主可用性：`WIRED_BY_TEMPLATE.character` 增加两项；笔记 / 事件 / 国家不可用。
- **兼容**：没改过的旧角色模板在加载时补上这两个组件（与头像升级同一套「未改动才升级」）；
  改过的模板保持原样，立绘/动画仍在基本信息里兜底渲染一次，避免能力消失。
- 审计：新 id 必须进 registry / 有渲染分支 / 参数契约；`isNoteTemplate` 的边界写清楚。

**验收**：角色模板可关掉立绘、把动画拖到正文之后；旧角色数据（avatars / animation）原样显示；
模板文件往返不丢；分类模板不会出现这两个组件。

### W3 国家字段能力

**问题**：国家「基本信息」只有一个名称输入，模板 group/atom 模型在国家宿主上不成立。

**做法**：

- `Country` 加 `custom?: Record<string, string>`（与 `WorldEntry.custom` 同形），落盘走 frontmatter
  自建键（复用 `scan` / `serialize` 的 custom 键机制，登记进 `COUNTRY_KEYS` 的「未管理键」处理）。
- 「基本信息」组件对国家开放：字段来自 `lib/fields` 的国家字段表（先给一张空的），
  编辑面复用 `FieldKindSettings` / `BasicInfoPanel`，渲染复用 `WorldCustomFields` 的控件层。
- 国家编辑器 `info` 块 = 名称 + 字段；实体字段表在设置 › 组件 › 国家 可增删。
- 兼容：老国家没有 `custom`，空对象；导出 / 站点 / 助手读不到就是没有。

**验收**：国家能加自建字段并保存、重开还在；与角色 / 事件的字段表 UI 一致；
模板参数 `info.group` 对国家仍然不开放（字段表是全局唯一源）。

### W4 导出 / 静态站消费模板参数

**问题**：关系呈现、画廊列数、标题文案、标题显隐只作用于编辑器；导出与站点按自己的版式取数据。
用户会以为「模板 = 全局版式」。

**做法**（分两步，先小后大）：

1. **参数贯通**：导出 / 站点读取同一个模板文件，至少消费 `label` / `title`（文案与显隐）、
   `gallery.mode` / `columns`；关系呈现按 `presentation` 选择紧凑 / 表格（图仍只读）。
2. **版式贯通**：导出卡 / 站点详情页的区块顺序与开关由模板组件决定；保留一套「导出预设」覆盖项，
   但默认从模板来。

**验收**：同一篇笔记在编辑器、导出卡、站点详情页的标题文案 / 区块顺序 / 显隐一致；
旧导出预设（没读模板时）行为不变；导出审计补「模板参数被消费」断言。

## 顺序与理由

W1 → W2 → W3 → W4。理由：W1 是所有区块的共同语言，先统一；W2 把角色页收干净，
让「组件编排」在实体宿主上也成立；W3 补国家这个宿主缺口；W4 依赖前三者稳定后才动导出，
否则每改一次参数就要改一遍导出。

## 每期的完成定义（DoD）

- 代码：实现 + 类型 + 审计断言；`tsc` / `lint`（0 error）/ `npm run build` 全过。
- 文档：`docs/模板.md` 对应小节 + CHANGELOG 一条（用户能看懂的一句话）+ AGENTS 现状描述。
- 兼容：旧模板 / 旧库手测路径写进文档；迁移只对「未改动」的模板生效。
- 回滚：参数与组件都是加法，必要时删掉注册项即可退回（数据列不动）。
